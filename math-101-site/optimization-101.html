문제를 세 줄로 쓰기: 변수, 목적, 제약

쓰인 곳선형대수 101의 최소제곱포즈 그래프 SLAMRL101·모방학습의 학습PID 다음의 드론 제어(LQR, MPC)
먼저, 수식 없이

최적화는 질문 세 개로 시작합니다. 무엇을 바꿀 수 있나(변수), 무엇이 작을수록 좋은가(목적 함수), 무엇은 꼭 지켜야 하나(제약). IK라면 변수는 관절 각도, 목적은 손끝과 목표 사이의 거리, 제약은 관절 한계예요. SLAM이라면 변수는 로봇이 지나온 자세들, 목적은 측정과 어긋난 정도의 합입니다.

이렇게 적고 나면 문제가 지형으로 보입니다. 변수가 둘이면 가로·세로가 변수이고 높이가 목적 함수인 지형이에요. 답은 가장 낮은 골짜기 바닥입니다. 그릇처럼 바닥이 하나뿐인 지형(볼록)이면 어디서 출발해도 그 바닥에 닿아요. 골짜기가 여럿이면 출발점에 따라 다른 바닥에 갇힐 수 있습니다.

그래서 로봇 공학자들은 문제를 되도록 볼록하게 세우려고 애씁니다. 최소제곱, LQR, 대부분의 MPC가 볼록 문제라서 빠르고 믿을 만하게 풀려요. 신경망 학습이나 장애물 사이 경로 찾기처럼 볼록하지 않은 문제는 좋은 출발점과 여러 번의 시도가 필요합니다.

한 줄로최적화 문제는 변수, 목적 함수, 제약 세 줄로 씁니다. 바닥이 하나뿐인 볼록 문제는 어디서 출발해도 같은 답에 닿고, 아니면 출발점에 따라 답이 달라져요.

조금 더 정확하게

표준형은 minx f(x) s.t. g(x) = 0, h(x) ≤ 0입니다. 최대화는 부호를 바꿔 최소화로 쓰고, ‘이 이상’ 같은 조건도 부호를 바꿔 h ≤ 0 꼴로 맞춰요. 목적 함수를 무엇으로 정하느냐가 곧 ‘무엇을 원하나’를 정하는 일이라서, 같은 로봇이라도 목적 함수가 바뀌면 행동이 달라집니다. LQR에서 Q와 R을 바꾸자 드론의 성격이 바뀐 것처럼요.

함수가 볼록하다는 것은 그래프 위 두 점을 이은 선분이 늘 그래프보다 위(또는 위에 닿게)에 있다는 뜻입니다. 볼록 함수에서는 기울기가 0인 곳이 곧 전체에서 가장 낮은 곳이라 국소 최솟값 함정이 없어요. 2차 함수 ½xᵀPx + qᵀx는 P가 양의 정부호(선형대수 101 13단계)일 때 볼록합니다. 최소제곱의 비용도 여기에 속해요.

볼록하지 않은 문제를 다루는 현실적인 처방은 세 가지입니다. 좋은 출발점에서 시작하기(SLAM의 오도메트리 초기값), 여러 출발점에서 돌려 보고 가장 좋은 답 고르기, 문제를 볼록한 조각으로 근사해 차례로 풀기. 3단계부터 나오는 가우스-뉴턴과 LM이 마지막 방법의 대표입니다.

import numpy as np
from scipy.optimize import minimize

def f(p):                                   # 두 골짜기 지형
    x, y = p
    return 0.25 * (x**2 - 2)**2 + 0.6 * y**2 + 0.25 * x

for x0 in [[-2.0, 1.0], [2.0, 1.0]]:         # 출발점만 바꿔 본다
    res = minimize(f, x0)                   # 기본은 준뉴턴법(BFGS)
    print(x0, '->', res.x.round(3), round(res.fun, 3))
# [-2, 1] -> [-1.473, 0.0] -0.361   (더 낮은 바닥)
# [ 2, 1] -> [ 1.347, 0.0]  0.345   (국소 최솟값)

starts = np.random.uniform(-3, 3, size=(20, 2))   # 여러 번 출발하기
best = min((minimize(f, s) for s in starts), key=lambda r: r.fun)

경사 하강은 발밑의 기울기만 봅니다. 기울기가 크면 크게, 작으면 작게 걷죠. 그런데 땅이 얼마나 휘었는지까지 알면 더 똑똑하게 걸을 수 있어요. 지금 자리에서 지형을 포물선으로 맞춘 뒤(테일러 2차 근사), 그 포물선의 바닥으로 바로 점프하는 겁니다. 이것이 뉴턴법이에요. 지형이 진짜 포물선(2차 함수)이면 한 번에 바닥에 닿습니다.

경사 하강이 특히 고생하는 곳은 좁고 긴 골짜기예요. 골짜기를 가로지르는 방향은 가파르고, 골짜기를 따라 내려가는 방향은 완만하죠. 가파른 방향에 맞춰 보폭을 작게 잡으면 완만한 방향으로는 거의 안 나아가고, 보폭을 키우면 벽 사이를 지그재그로 튕깁니다. 가파름의 비율을 조건수라고 해요.

뉴턴법은 방향마다 휘는 정도로 나눠 주기 때문에 좁은 골짜기도 한 번에 펴서 갑니다. 대신 2차 미분 표(헤세 행렬)를 만들고 연립방정식을 풀어야 해서 변수가 수백만 개인 신경망에는 너무 비싸요. 그래서 신경망은 지난 걸음의 방향을 기억해 지그재그를 상쇄하는 모멘텀, 칸마다 보폭을 따로 맞추는 Adam 같은 절충안을 씁니다.

한 줄로뉴턴법은 지금 자리의 포물선 근사의 바닥으로 점프합니다. 곡률을 쓰니 좁은 골짜기에서도 빠르지만, 2차 미분을 구하고 풀어야 해서 비쌉니다.

까먹었다면미적분 101 9단계: f(x) ≈ f(a) + f′(a)(x − a) + ½f″(a)(x − a)². 이 포물선의 바닥은 x = a − f′(a)/f″(a)예요. 미분해서 0으로 두면 나옵니다.

조금 더 정확하게

1차원에서 뉴턴 걸음은 x ← x − f′(x)/f″(x)입니다. 지금 자리의 포물선 바닥이 바로 거기니까요. 경사 하강의 x ← x − ηf′(x)과 비교하면, 보폭 η를 1/f″로, 곧 ‘휜 정도의 역수’로 자동으로 고른 셈이에요. 많이 휜 곳에서는 작게, 평평한 곳에서는 크게 걷습니다. 바닥 근처에서는 맞는 자릿수가 걸음마다 두 배씩 늘어(2차 수렴) 몇 걸음이면 끝나요.

변수가 여럿이면 f″ 자리에 헤세 행렬 H가 들어가 Δ = −H⁻¹∇f가 됩니다. 계산은 역행렬 대신 HΔ = −∇f를 풀어요. 함정도 있습니다. H가 양의 정부호가 아니면(꼭대기나 안장점 근처) 포물선이 아래로 열려 있어서 뉴턴 걸음이 오히려 오르막으로 갑니다. 그래서 실제 구현은 H에 μI를 더해 그릇으로 만들거나(4단계의 LM과 같은 생각) 걸음 길이를 줄여요.

경사 하강의 보폭은 가장 가파른 방향 때문에 η < 2/λmax로 묶이고, 그 보폭으로 가장 완만한 방향을 내려가려면 걸음 수가 대략 조건수 κ = λmax/λmin에 비례합니다. 모멘텀은 v ← βv − η∇f로 지난 걸음을 β만큼 이어 가서, 골짜기를 가로지르는 성분은 서로 상쇄되고 골짜기를 따르는 성분은 쌓여요. 걸음 수가 대략 √κ에 비례하게 줄어듭니다.

뉴턴법: 포물선의 바닥으로
(2)
  1. 11차원 뉴턴 걸음. 지금 자리의 포물선 바닥으로. 보폭이 곡률의 역수로 자동으로 정해져요.
  2. 2여러 변수. 헤세 행렬 H로 방향마다 휜 정도를 나눠 줍니다. 실제로는 HΔ = −∇f를 풀어요.
좁은 골짜기와 모멘텀
(3)

  2. 2모멘텀. 지난 걸음을 β만큼 이어 가요. 지그재그는 상쇄되고 골짜기 방향은 쌓입니다.

def f(p):  x, y = p; return (1 - x)**2 + 4 * (y - x**2)**2       # 바나나 골짜기
def g(p):  x, y = p; return np.array([-2*(1-x) - 16*x*(y-x**2), 8*(y-x**2)])
def H(p):  x, y = p; return np.array([[2 - 16*(y-x**2) + 32*x**2, -16*x], [-16*x, 8.0]])

x = np.array([-1.5, 2.0])
for k in range(20):                          # 뉴턴법

    lam_min = np.linalg.eigvalsh(Hk)[0]

    x = x + np.linalg.solve(Hk, -g(x))
    if np.linalg.norm(g(x)) < 1e-9: break
print(k + 1, x)                              # 10걸음 남짓에 [1, 1]

잔차를 펴서 푼다: 최소제곱과 가우스-뉴턴

쓰인 곳포즈 그래프 SLAM 5단계선형대수 101의 최소제곱확률과 통계 101의 최대 가능도확률과 통계 101의 비콘 위치 추정
먼저, 수식 없이

로봇이 비콘 세 개까지의 거리를 쟀습니다. 위치를 어떻게 구할까요? 위치를 하나 짐작하면 각 비콘까지 ‘계산한 거리’가 나오고, 그것과 ‘잰 거리’의 차이를 잔차라고 합니다. 잔차 제곱의 합이 가장 작은 위치가 답이에요. 측정 잡음이 정규분포면 이게 가장 그럴듯한 위치이기도 합니다(확률과 통계 101 17단계).

문제는 거리가 위치에 대해 곡선이라는 점입니다. 직선(선형) 문제라면 선형대수 101의 정규방정식 한 번으로 끝났을 텐데요. 가우스-뉴턴은 지금 짐작한 자리에서 잔차를 직선으로 펴고(1차 테일러), 그 직선 문제를 정규방정식으로 풀어 한 걸음 옮기고, 새 자리에서 다시 펴기를 되풀이합니다.

SLAM의 포즈 그래프 최적화가 정확히 이것이었어요. 다른 점은 잔차가 수천 개이고 변수가 자세 수백 개라는 것뿐입니다. 뉴턴법과 달리 2차 미분이 필요 없고 잔차의 1차 미분(야코비안)만 있으면 돼서, 잔차 제곱합 꼴의 문제에서는 거의 늘 이걸 씁니다.

한 줄로잔차 제곱합을 최소로 하는 문제는 잔차를 지금 자리에서 직선으로 펴서 정규방정식을 풀고 옮기기를 되풀이합니다. 이것이 가우스-뉴턴이에요.

잔차 r
모델이 예측한 값 − 실제로 잰 값.
잔차의 야코비안 J
변수를 조금 바꿀 때 잔차들이 바뀌는 비율 표.
정규방정식
JᵀJΔ = −Jᵀr. 직선으로 편 문제의 답.

위치를 아는 기준점. 거리나 방향을 재는 상대.

까먹었다면선형대수 101 8단계: 직선 문제 Ax ≈ y의 최소제곱 답은 AᵀAx = Aᵀy를 풀면 나와요. 가우스-뉴턴에서는 A 자리에 J, y 자리에 −r이 들어갑니다.

조금 더 정확하게

목적은 F(x) = ½Σri(x)²입니다. 지금 x 근처에서 r(x + Δ) ≈ r(x) + JΔ로 펴면 ½‖r + JΔ‖²는 Δ에 대한 선형 최소제곱이 되고, 그 답이 (JᵀJ)Δ = −Jᵀr입니다. 뉴턴법과 비교하면 F의 그래디언트는 정확히 Jᵀr이고, 헤세 행렬은 JᵀJ에 ‘잔차 × 잔차의 2차 미분’ 항을 더한 것인데 가우스-뉴턴은 그 둘째 항을 버린 셈이에요. 잔차가 작거나 거의 직선이면 그 항이 작아서 뉴턴법만큼 빠릅니다.

비콘 문제에서 잔차는 ri = ‖p − bi‖ − di이고, 그 야코비안의 행은 비콘에서 로봇 쪽을 가리키는 단위 벡터입니다. ‘그 방향으로 움직이면 거리가 늘어난다’는 뜻이니 당연하죠. 비콘들이 한 줄로 늘어서 있으면 이 단위 벡터들이 거의 평행해서 JᵀJ가 납작해지고(선형대수 101의 특잇값), 줄과 수직인 방향의 위치가 불확실해집니다. GPS에서 위성 배치가 나쁘면 오차가 커지는 것(DOP)과 같은 이야기예요.

가우스-뉴턴은 출발점이 답에서 너무 멀면 직선 근사가 엉터리가 되어 비용이 오히려 커지는 걸음을 내딛을 수 있습니다. 다음 단계의 레벤버그-마콰트가 이걸 고쳐요.

import numpy as np

beacons = np.array([[0.0, 0.0], [6.0, 0.5], [2.0, 5.0]])
d = np.array([3.62, 3.37, 3.17])            # 잰 거리 (잡음 섞임)

p = np.array([5.0, 4.0])                    # 처음 짐작
for k in range(10):
    diff = p - beacons
    dist = np.linalg.norm(diff, axis=1)
    r = dist - d                            # 잔차
    J = diff / dist[:, None]                # 각 행 = 단위 벡터
    delta = np.linalg.solve(J.T @ J, -J.T @ r)   # 정규방정식
    p = p + delta
    print(k, p.round(4), 0.5 * r @ r)
    if np.linalg.norm(delta) < 1e-10: break

조심스럽게 걷기: 레벤버그-마콰트

쓰인 곳포즈 그래프 SLAM 5단계의 LM선형대수 101의 감쇠 최소제곱(DLS)모터·센서 파라미터 식별scipy의 least_squares
먼저, 수식 없이

가우스-뉴턴은 ‘지금 자리에서 편 직선 근사를 믿고 한 번에 크게’ 걷습니다. 근사가 잘 맞으면 빠르지만, 출발점이 엉뚱하면 근사가 틀려서 엉뚱한 곳으로 멀리 뛰어 버려요. 모터의 계단 응답에서 시정수를 맞추는 문제처럼, 출발점이 나쁘면 시정수가 음수로 튀어 다시는 돌아오지 못하기도 합니다.

레벤버그-마콰트(LM)는 걸음마다 ‘이 걸음으로 비용이 줄었나?’를 확인합니다. 줄었으면 받아들이고 근사를 더 믿어 다음엔 더 과감하게(λ를 줄임), 늘었으면 버리고 근사를 덜 믿어 더 조심스럽게(λ를 키움) 다시 풀어요. λ가 크면 짧고 안전한 경사 하강에 가깝고, 작으면 빠른 가우스-뉴턴이 됩니다.

SLAM 실습의 LM 버튼과 선형대수 101 IK의 감쇠 최소제곱(DLS)이 같은 생각이에요. DLS는 λ를 고정해 두고, LM은 λ를 걸음마다 스스로 고칩니다. scipy의 least_squares, Ceres 같은 라이브러리의 기본 방법이기도 해요.

한 줄로LM은 가우스-뉴턴 걸음에 감쇠 λ를 더하고, 비용이 줄면 λ를 줄이고 늘면 걸음을 버리고 λ를 키웁니다. 빠를 때는 가우스-뉴턴처럼, 위험할 때는 경사 하강처럼 걸어요.

감쇠 λ
근사를 얼마나 덜 믿을지. 크면 짧고 안전한 걸음.
신뢰 영역
근사를 믿을 수 있는 둘레. λ가 그 크기를 정해요.
받은 걸음, 버린 걸음
비용을 줄인 걸음만 반영합니다.
시정수 τ
계단 입력 뒤 최종값의 63%에 닿는 시간.

까먹었다면선형대수 101 7단계의 DLS: Δθ = Jᵀ(JJᵀ + λ²I)⁻¹e. λ가 작으면 빠르지만 특이점 근처에서 폭발하고, 크면 전치 방식처럼 느리지만 안전했어요.

조금 더 정확하게

LM 걸음은 (JᵀJ + λD)Δ = −Jᵀr입니다. D를 단위 행렬로 두면 λ가 클 때 Δ ≈ −Jᵀr/λ, 곧 보폭 1/λ의 경사 하강이 되고, D = diag(JᵀJ)로 두면(마콰트의 제안) 변수마다 단위가 달라도 감쇠가 공평하게 걸려요. 모터 문제처럼 이득 A(단위 없음)와 시정수 τ(초)를 함께 맞출 때 중요합니다.

λ를 고치는 규칙은 단순합니다. 새 비용이 줄었으면 걸음을 받고 λ ← λ/10, 아니면 걸음을 버리고 λ ← 10λ로 같은 자리에서 다시 풀어요. 버린 걸음도 계산 비용은 들지만, 발산하는 걸음을 절대 받지 않으니 비용은 걸음마다 줄기만 합니다. 이 실습의 모터 응답 맞추기에서 가우스-뉴턴이 발산하는 출발점에서도 LM은 답을 찾아요.

LM은 ‘근사를 믿을 수 있는 둘레(신뢰 영역) 안에서 가장 좋은 걸음’을 찾는 방법의 한 종류입니다. 그래도 볼록하지 않은 문제의 국소 최솟값을 피하게 해 주지는 못해요. 출발점은 여전히 중요합니다.

레벤버그-마콰트
(6)
  1. 1감쇠를 더한 정규방정식. λ = 0이면 가우스-뉴턴, λ가 크면 짧은 경사 하강. diag(JᵀJ)로 변수마다 단위를 맞춰요.
  2. 2λ 고치기. 비용이 줄면 받고 더 과감하게, 늘면 버리고 더 조심스럽게. 그래서 비용은 늘 줄기만 합니다.
파이썬
import numpy as np

t = np.arange(25) * 0.1                         # 모터 계단 응답 (25점)
y = 2.0 * (1 - np.exp(-t / 0.4)) + np.random.normal(0, 0.03, t.size)

def res(th):  A, tau = th; return A * (1 - np.exp(-t / tau)) - y
def jac(th):
    A, tau = th; e = np.exp(-t / tau)
    return np.stack([1 - e, -A * t * e / tau**2], axis=1)

th, lam = np.array([1.0, 3.0]), 1e-2            # 시정수를 너무 크게 짐작
cost = 0.5 * res(th) @ res(th)
for k in range(60):
    r, J = res(th), jac(th)
    H = J.T @ J
    step = np.linalg.solve(H + lam * np.diag(np.diag(H)), -J.T @ r)
    new_cost = 0.5 * res(th + step) @ res(th + step)
    if new_cost < cost:  th, cost, lam = th + step, new_cost, lam / 10   # 받기
    else:                lam = lam * 10                                   # 버리기
print(th)                                       # 약 [2.0, 0.4]

# 실제로는 한 줄: scipy.optimize.least_squares(res, [1, 3], jac=jac, method='lm')

  • 출발점(주황 점)을 시정수 τ가 큰 위쪽(τ = 3 근처)으로 끌어 보세요. 가우스-뉴턴(빨강)은 첫 걸음에 그래프 밖으로 튀어 τ가 음수가 되고 돌아오지 못합니다. LM(주황)은 처음 몇 걸음을 버리며(× 표시) λ를 키운 뒤 조심스럽게 내려와 답에 닿아요.
  • 출발점을 답 근처로 옮기면 두 방법이 거의 같은 길로, 같은 걸음 수에 끝납니다. 근사가 잘 맞으면 LM의 λ는 금방 작아져 가우스-뉴턴이 돼요. 오른쪽 그래프에서 λ가 줄어드는 걸 보세요.
  • 처음 λ를 1e-4에서 10까지 바꿔 보세요. 너무 크면 처음 몇 걸음이 경사 하강처럼 느리고, 너무 작으면 버리는 걸음이 늘어납니다. 그래도 끝에는 같은 답에 닿아요.

핵심

LM은 가우스-뉴턴에 감쇠 λ를 더해 비용이 줄 때만 걸음을 받고, 실패하면 λ를 키워 조심스럽게 다시 풉니다. 출발점이 나빠도 잘 버텨서 SLAM과 파라미터 식별의 기본 방법이에요.

이상치 하나에 휘둘리지 않기: 강건한 손실

쓰인 곳포즈 그래프 SLAM 7단계의 Huber·Cauchy선형대수 101의 이상치와 RANSAC확률과 통계 101의 평균과 중앙값라이다 스캔 매칭
먼저, 수식 없이

최소제곱은 잔차를 제곱합니다. 10 cm 틀린 측정은 1 cm 틀린 것보다 100배 큰 벌을 받아요. 그래서 엉뚱한 측정(이상치) 하나가 답 전체를 끌어당깁니다. SLAM에서 틀린 루프 클로저 하나가 지도 전체를 구긴 것이 이 때문이었어요.

처방은 잔차가 커지면 벌을 덜 키우는 것입니다. Huber 손실은 작은 잔차는 제곱으로, 큰 잔차는 직선으로 세요. Cauchy 손실은 잔차가 커질수록 거의 무시합니다. 확률과 통계 101에서 이상치에는 평균 대신 중앙값을 쓰라고 한 것과 같은 생각이에요.

푸는 방법도 간단합니다. 지금 답에서 잔차가 큰 측정의 무게를 깎고, 그 무게로 가중 최소제곱을 풀고, 새 답에서 다시 무게를 매기기를 되풀이해요(IRLS). 몇 번이면 이상치의 무게가 거의 0이 되어 나머지 측정에 맞는 답이 남습니다.

한 줄로제곱 대신 큰 잔차를 덜 벌하는 손실(Huber, Cauchy)을 쓰면 이상치가 답을 끌어당기지 못합니다. 무게를 다시 매기며 가중 최소제곱을 되풀이해서 풀어요.

조금 더 정확하게

강건한 손실은 Σρ(ri)를 최소로 합니다. ρ(r) = ½r²이면 보통의 최소제곱이고, Huber는 |r| ≤ k까지 ½r², 그 밖에서는 k|r| − ½k²로 직선이 돼요. 직선이니 큰 잔차가 당기는 힘(ρ′)이 k로 일정합니다. Cauchy는 ½k² ln(1 + (r/k)²)로, 당기는 힘이 잔차가 커질수록 오히려 줄어요. k는 ‘이 정도까지는 정상 잡음’이라는 경계로, 보통 잡음 표준편차의 1~3배로 잡습니다.

이 목적의 그래디언트는 Σρ′(ri)∇ri인데, wi = ρ′(ri)/ri로 두면 Σwiri∇ri, 곧 무게 wi를 단 최소제곱의 그래디언트와 같아집니다. 그래서 ‘무게를 매기고 가중 최소제곱을 풀기’를 되풀이하면 강건한 답에 닿아요. 가우스-뉴턴이나 LM의 걸음마다 무게를 다시 매기면 되고, SLAM 라이브러리가 강건 커널을 넣는 방식이 이것입니다.

Cauchy처럼 이상치를 강하게 무시하는 손실은 볼록하지 않아서, 출발점이 나쁘면 진짜 데이터를 이상치로 오해할 수 있어요. 그래서 이상치가 많으면 RANSAC으로 먼저 걸러 내거나, Huber로 시작해 답이 자리 잡은 뒤 Cauchy로 바꾸는 식으로 씁니다.

강건한 손실과 무게 다시 매기기
(7)
  1. 1제곱 대신 ρ. ρ(r) = ½r²이면 보통 최소제곱이에요.
  2. 2Huber. 경계 k 안에서는 제곱, 밖에서는 직선. 큰 잔차가 당기는 힘이 k로 묶여요.
  3. 3무게 다시 매기기. 잔차가 큰 측정의 무게를 깎고 가중 최소제곱을 풀기를 되풀이합니다(IRLS).
파이썬
import numpy as np

x = np.linspace(0, 9, 12)
y = 0.5 * x + 1 + np.random.normal(0, 0.15, x.size)
x = np.append(x, [2.0, 3.0]); y = np.append(y, [7.0, 8.0])   # 이상치 둘

def weights(r, kind, k=0.5):
    a = np.abs(r)
    if kind == 'huber':  return np.where(a <= k, 1.0, k / a)
    if kind == 'cauchy': return 1.0 / (1 + (r / k)**2)
    return np.ones_like(r)

for kind in ['l2', 'huber', 'cauchy']:
    w = np.ones_like(x)
    for it in range(30):                     # IRLS
        A = np.stack([x, np.ones_like(x)], 1)
        m, c = np.linalg.solve(A.T @ (w[:, None] * A), A.T @ (w * y))
        w = weights(y - (m * x + c), kind)
    print(kind, round(m, 3), round(c, 3))   # l2만 크게 끌려감

선 위에서만 움직일 때: 라그랑주 승수

쓰인 곳선형대수 101의 영공간여유 자유도 팔의 최소 노름 IK7, 8단계의 KKT와 QP
먼저, 수식 없이

레일 위를 달리는 카메라 카트가 피사체에 가장 가까이 가는 자리는 어디일까요? 카트는 레일을 벗어날 수 없으니, 피사체까지 거리가 0인 곳(제약 없는 답)이 아니라 레일 위에서 가장 가까운 곳이 답입니다. 그 자리에서는 레일을 따라 조금 움직여도 거리가 더 줄지 않아요. 거리가 줄어드는 방향이 레일과 정확히 직각이라는 뜻입니다.

이걸 등고선으로 보면 깔끔합니다. 답에서는 목적 함수의 등고선이 제약 곡선에 살짝 닿아요(접해요). 그래서 두 곡선의 법선, 곧 ∇f와 ∇g가 한 직선 위에 놓입니다. 둘 사이의 비율을 라그랑주 승수 λ라고 해요.

λ에는 쓸모 있는 뜻도 있습니다. 제약을 조금 풀어 주면(레일을 피사체 쪽으로 1 cm 옮기면) 최적의 비용이 얼마나 좋아지는가가 λ예요. ‘이 제약이 얼마나 비싼가’를 알려 주는 값이라 그림자 가격이라고도 부릅니다.

한 줄로등식 제약이 있으면 답에서 목적 함수의 기울기와 제약의 기울기가 평행합니다. 그 비율이 라그랑주 승수이고, 제약을 조금 풀 때 비용이 얼마나 좋아지는지를 알려 줘요.

조금 더 정확하게

min f(x) s.t. g(x) = 0의 답 x*에서는 제약 곡선을 따라 움직이는 어떤 방향으로도 f가 1차로 변하지 않아야 합니다. 곡선을 따르는 방향은 ∇g와 직각인 방향이니, ∇f도 그 방향과 직각, 곧 ∇g와 평행해야 해요. 이것을 ∇f + λ∇g = 0으로 씁니다. 식이 변수 수만큼, 제약 g = 0이 하나 더 있으니 x와 λ를 함께 풀 수 있어요.

라그랑지안 𝓛 = f + λg를 x와 λ로 각각 미분해 0으로 두면 정확히 이 조건과 g = 0이 나옵니다. 제약 있는 문제를 ‘제약 없는 문제의 기울기 0 조건’으로 바꿔 쓴 셈이에요. 제약이 여러 개면 λ도 여러 개이고, 답에서 ∇f는 ∇g들의 조합이 됩니다.

로봇 예로, 여유 자유도가 있는 팔에서 ‘손끝은 목표에 정확히 두고(등식 제약) 관절 움직임은 가장 작게(목적)’를 풀면 선형대수 101의 의사역행렬 답이 나옵니다. 영공간 방향으로는 손끝이 안 움직이니, 그 방향의 성분을 0으로 두는 것이 가장 작은 움직임이에요.

라그랑주 승수
(8)
  1. 1등식 제약 문제. 곡선 g = 0 위에서만 f를 줄입니다.
  2. 2답의 조건. 두 그래디언트가 한 직선 위에. λ는 둘의 비율이에요.
  3. 3라그랑지안. x와 λ로 미분해 0으로 두면 위 조건과 g = 0이 함께 나옵니다.
파이썬
import numpy as np
from scipy.optimize import minimize

goal = np.array([3.0, 1.0])
f  = lambda p: np.sum((p - goal)**2)          # 목표까지 거리 제곱
g  = lambda p: p[0]**2 + p[1]**2 - 1.0        # 반지름 1인 원 위에서만

res = minimize(f, x0=[0.0, 1.0], constraints=[{'type': 'eq', 'fun': g}])
p = res.x
print(p)                                      # [0.949, 0.316] = 목표 방향의 원 위 점

grad_f = 2 * (p - goal)
grad_g = 2 * p
lam = -grad_f @ grad_g / (grad_g @ grad_g)    # ∇f + λ∇g = 0
print(lam, grad_f + lam * grad_g)             # λ ≈ 2.16, 나머지 ≈ 0

해 볼 것

  • 제약 원 위의 점(주황)을 끌어 원을 따라 움직여 보세요. 빨간 화살표(−∇f, 비용이 가장 빨리 주는 방향)와 원의 접선이 직각이 되는 곳에서 비용이 가장 작아집니다. 그 자리에서 ∇f와 ∇g(파랑)가 한 직선 위에 놓여요.
  • 목표(초록 별)를 끌어 원 안으로 넣어 보세요. 원 위에 있어야 한다는 제약 때문에 답은 여전히 원 위의 가장 가까운 점이고, λ의 부호가 바뀝니다. 원이 목표 쪽으로 커지면 좋겠는지, 작아지면 좋겠는지가 바뀌었으니까요.
  • 반지름을 0.1씩 바꿔 가며 오른쪽의 ‘최적 비용’이 얼마나 바뀌는지 보세요. 그 변화를 반지름 제곱의 변화로 나눈 값이 대략 −λ입니다. 승수가 제약의 값을 알려 준다는 뜻이에요.

핵심

등식 제약이 있으면 답에서 ∇f와 ∇g가 평행하고, 그 비율이 라그랑주 승수입니다. 라그랑지안을 미분해 0으로 두면 그 조건이 나오고, λ는 제약을 조금 풀 때 비용이 얼마나 나아지는지를 알려 줘요.

넘으면 안 되는 선: 부등식 제약, 사영, 벌점

쓰인 곳PID의 출력 포화(clip)관절 한계드론의 기울기·추력 한계9, 10단계
먼저, 수식 없이

부등식 제약은 ‘이 선을 넘지 마라’입니다. 관절은 ±90°까지, 모터는 최대 추력까지. 제약 안쪽에 원래 답이 있으면 제약은 없는 것과 같고(비활성), 원래 답이 밖에 있으면 답은 경계 위로 옮겨 가요(활성). 경계에 선 답에서는 벽이 미는 힘이 내리막으로 가려는 힘과 맞섭니다.

이 조건을 적은 것이 KKT 조건이에요. 벽은 밀기만 하지 당기지는 않으니 미는 힘 μ는 0 이상이고, 벽에 닿지 않았으면 밀 이유가 없으니 μ = 0입니다. ‘닿았거나, 밀지 않거나’ 둘 중 하나예요.

푸는 쉬운 방법이 둘 있습니다. 사영은 경사 하강으로 한 걸음 간 뒤 선을 넘었으면 가장 가까운 안쪽 점으로 되돌려 놓아요. PID의 출력 clip이 바로 이것입니다. 벌점은 선을 넘은 만큼 비용을 크게 더해서 넘지 않게 유도해요. 벌점이 작으면 조금 넘고, 크면 거의 경계에 붙습니다.

한 줄로부등식 제약은 답이 안쪽이면 영향이 없고, 밖이면 답을 경계로 옮깁니다. 경계에서는 벽이 미는 힘(μ ≥ 0)이 기울기와 맞서고, 사영이나 벌점으로 풀 수 있어요.

import numpy as np

goal = np.array([2.2, 1.6])
grad = lambda p: 2 * (p - goal)               # f = |p - goal|^2
lo, hi = np.array([-1.0, -1.0]), np.array([1.0, 1.0])   # 상자 제약

p = np.array([-0.5, 0.0])
for k in range(100):                           # 사영 경사 하강
    p = np.clip(p - 0.1 * grad(p), lo, hi)
print(p)                                       # [1, 1]: 모서리에 붙음

mu = -grad(p)                                  # 벽이 미는 힘 (활성인 칸만)
print(mu)                                      # [2.4, 1.2] ≥ 0 → KKT 만족

for rho in [1, 10, 100, 1000]:                 # 벌점법
    q = np.zeros(2)
    for k in range(20000):
        over = np.maximum(0, q - hi)            # 위쪽 한계를 넘은 양
        q -= 0.2 / (1 + rho) * (grad(q) + rho * over)
    print(rho, q.round(3))                     # ρ가 클수록 [1, 1]에 다가감

목적 함수가 그릇 모양 2차 함수이고 제약이 모두 직선(평면)인 문제를 이차 계획법(QP)이라고 합니다. 모양이 단순해서 아주 빠르고 확실하게 풀리고, 답이 하나뿐(볼록)이에요. 그래서 로봇 공학자들은 어려운 문제를 매 순간 QP로 근사해서 풉니다.

실제로 QP는 어디에나 있어요. MPC는 매 제어 주기마다 ‘앞으로 N칸의 명령’을 QP로 풀고, 4족이나 휴머노이드는 ‘발마다 얼마의 힘을 낼까’를 마찰 원뿔을 직선으로 근사한 QP로 정하며, IK는 관절 한계를 지키는 걸음을 QP로 고릅니다.

QP를 푸는 가장 직관적인 방법은 ‘어느 벽에 붙을까’를 찾는 것입니다(활성 집합). 붙을 벽을 정하면 남은 문제는 등식 제약 문제라서 연립방정식 한 번으로 풀려요. 붙은 벽의 미는 힘이 모두 0 이상이고 다른 벽은 넘지 않으면 그게 답입니다.

한 줄로QP는 그릇 모양 2차 목적에 직선 제약을 단 문제입니다. 볼록해서 빠르고 확실하게 풀리고, 답은 ‘어느 제약이 활성인가’만 정하면 연립방정식으로 나와요.

QP

조금 더 정확하게

QP는 min ½xᵀPx + qᵀx s.t. Ax ≤ b입니다. P가 양의 정부호면 목적은 그릇이고, 제약 Ax ≤ b는 반공간들의 교집합이라 볼록한 다각형(다면체)이에요. 볼록 그릇을 볼록 영역에서 줄이니 국소 최솟값 함정이 없고, 답은 하나입니다.

활성 집합 S를 정하면 KKT 조건이 선형 연립방정식이 됩니다. [P ASᵀ; AS 0][x; μS] = [−q; bS]. 이 실습의 2차원 QP는 가능한 활성 집합(벽 0개, 1개, 2개)을 모두 시험해서 ‘모든 제약을 지키고 μ가 모두 0 이상’인 것을 고릅니다. 실제 풀이기는 이 탐색을 똑똑하게 줄인 활성 집합법, 내부점법, 또는 7단계의 사영을 발전시킨 ADMM(OSQP)을 써요.

MPC처럼 같은 꼴의 QP를 매 주기 푸는 경우에는 지난 주기의 답과 활성 집합에서 시작하면(웜 스타트) 몇 번의 반복만으로 끝납니다. 1 kHz 제어 루프 안에서 QP를 풀 수 있는 이유예요.

(10)
  1. 1QP의 꼴. 그릇 모양 2차 목적과 직선 제약들. P가 양의 정부호면 답이 하나예요.
  2. 2활성 집합을 정하면. 붙은 제약만 등식으로 둔 KKT 연립방정식. 풀어서 μ ≥ 0이고 나머지 제약을 지키면 답입니다.
파이썬
import numpy as np
import itertools

P = np.array([[2.0, 0.0], [0.0, 2.0]]); q = np.array([-4.0, -4.0])   # 바닥 (2, 2)
A = np.array([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]]); b = np.array([1.5, 3.0, 2.5])

best = None
for k in range(3):                            # 활성 집합 크기 0, 1, 2
    for S in itertools.combinations(range(len(b)), k):
        S = list(S); n = 2 + len(S)
        K = np.zeros((n, n)); K[:2, :2] = P
        K[:2, 2:] = A[S].T; K[2:, :2] = A[S]
        rhs = np.concatenate([-q, b[S]])
        try: z = np.linalg.solve(K, rhs)
        except np.linalg.LinAlgError: continue
        x, mu = z[:2], z[2:]
        if np.all(A @ x <= b + 1e-9) and np.all(mu >= -1e-9):
            val = 0.5 * x @ P @ x + q @ x
            if best is None or val < best[0]: best = (val, x, S, mu)
print(best)            # x = [1.25, 1.25], 활성: x + y ≤ 2.5, μ = 1.5

import numpy as np

L = np.array([1.0, 0.8, 0.6])
lim = np.array([[-1.6, 1.6], [0.0, 2.4], [-0.5, 0.5]])   # 손목은 ±0.5 rad

def fk(th):
    a = np.cumsum(th)
    return np.array([np.sum(L * np.cos(a)), np.sum(L * np.sin(a))])

def jac(th):
    a = np.cumsum(th); J = np.zeros((2, 3))
    for i in range(3):
        J[0, i] = -np.sum(L[i:] * np.sin(a[i:])); J[1, i] = np.sum(L[i:] * np.cos(a[i:]))
    return J

def ik_step_box(th, target, lam=0.1, iters=200):
    e, J = target - fk(th), jac(th)
    H = J.T @ J + lam**2 * np.eye(3); g = -J.T @ e
    lo, hi = lim[:, 0] - th, lim[:, 1] - th              # 걸음의 범위
    d, step = np.zeros(3), 1 / np.linalg.eigvalsh(H)[-1]
    for _ in range(iters):                                 # 사영 경사 하강
        d = np.clip(d - step * (H @ d + g), lo, hi)
    return th + d

앞을 내다보는 제어: QP로 푸는 MPC

쓰인 곳PID 다음의 드론 제어 4장 MPC·MPPILQRPID의 출력 포화와 와인드업3D 드론 레이싱의 MPCC

PID나 LQR은 지금 오차만 보고 명령을 정합니다. 그래서 모터 한계를 모른 채 큰 명령을 내고, 실제로는 잘린 힘만 나가면서 목표를 지나치기 쉬워요. MPC(모델 예측 제어)는 매 순간 ‘앞으로 N칸 동안 어떤 명령을 내면 가장 좋을까’를 모델로 내다보고, 한계를 지키는 명령열을 최적화로 고릅니다.

고른 명령열 중 첫 칸만 실제로 내보내고, 다음 순간 새로 잰 상태에서 다시 N칸을 계획해요(이동 지평). 바둑에서 몇 수 앞을 읽고 한 수만 두는 것과 같습니다. PID 다음의 드론 제어 실습의 MPPI는 이 계획을 무작위 표본 수백 개로 풀었고, 여기서는 같은 일을 QP로 정확히 풉니다.

선형 모델과 2차 비용, 명령 한계만 있으면 이 계획 문제는 정확히 8단계의 QP예요. 상태를 명령열의 식으로 미리 풀어 쓰면 변수는 명령 N개뿐이고 제약은 칸마다의 한계(상자)라서, 7단계의 사영 경사 하강으로 매 주기 풀 수 있습니다.

이중 적분기 p̈ = u를 Δt로 이산화하면 xk+1 = Axk + Buk(x = [p, v])입니다. 미래 상태는 모두 지금 상태 x₀와 명령열 U = [u₀, …, uN−1]의 일차식이라서, 비용 Σ(qp(pk − p*)² + qvvk²) + rΣuk²를 U에 대해 ½UᵀHU + gᵀU로 정리할 수 있어요. H는 N×N이고 늘 양의 정부호입니다. 제약 |uk| ≤ umax는 상자예요.

그래서 MPC 한 주기는 ‘상자 제약 QP 하나 풀기’입니다. 이 실습은 FISTA(가속 사영 경사 하강)로 풀고 지난 답을 한 칸 밀어 웜 스타트해요. 제약이 활성이 아니면 답은 LQR과 같은 선형 피드백이 되고, 한계가 활성이면 MPC는 ‘지금은 최대로 밀고, 미리 줄여서 지나치지 않게’라는 비선형 계획을 스스로 찾아냅니다.

지평 N이 짧으면 한계에 걸린 뒤의 일을 내다보지 못해 결국 지나치거나 출렁이고, 길면 계획은 좋아지지만 계산이 늘어요. 실제 드론과 4족 로봇은 N = 10~50칸, 주기 수십~수백 Hz로 이런 QP를 풉니다. 모델이 비선형이면 지금 궤적 근처에서 선형화한 QP를 매 주기 풀어요(순차 QP).

모델 예측 제어를 QP로
(12)
  1. 1N칸 앞까지의 비용. 목표와의 거리, 속도, 명령의 크기에 무게를 매겨 더해요. LQR과 같은 꼴입니다.
  2. 2모델과 한계. 미래 상태는 모델로 정해지고, 명령은 칸마다 한계 안이어야 해요.
  3. 3명령열에 대한 QP. 상태를 U의 식으로 풀어 쓰면 변수는 U뿐이고 제약은 상자입니다. 첫 칸 u₀만 내보내요.
파이썬
import numpy as np

dt, N, umax = 0.1, 25, 1.0
A = np.array([[1, dt], [0, 1]]); B = np.array([0.5 * dt**2, dt])
qp_, qv, r = 1.0, 0.1, 0.01

# 미래 상태 = Ap[k] @ x0 + Su @ U  (k = 1..N)
Ap = [np.linalg.matrix_power(A, k) for k in range(N + 1)]
Su = np.zeros((2 * N, N))
for k in range(1, N + 1):
    for j in range(k):
        Su[2*(k-1):2*k, j] = Ap[k-1-j] @ B
Qd = np.tile([qp_, qv], N)
H = Su.T @ (Qd[:, None] * Su) + r * np.eye(N)
step = 1 / np.linalg.eigvalsh(H)[-1]

def mpc(x0, target, U):
    free = np.concatenate([Ap[k] @ x0 - [target, 0] for k in range(1, N + 1)])
    g = Su.T @ (Qd * free)
    for _ in range(200):                     # 사영 경사 하강 (상자 QP)
        U = np.clip(U - step * (H @ U + g), -umax, umax)
    return U

x, U = np.array([0.0, 0.0]), np.zeros(N)
for t in range(80):
    U = mpc(x, 2.0, U)
    u = U[0]                                 # 첫 칸만 쓴다
    x = A @ x + B * u
    U = np.append(U[1:], U[-1])              # 웜 스타트

이럴 때 2단계까지의 방법은 곤란해집니다. 기울기를 차분으로 재면 작은 차이를 작은 h로 나누니 잡음이 크게 부풀고(미적분 101 5단계), 변수가 많으면 변수마다 두 번씩 돌려야 해요. SPSA는 모든 변수를 한꺼번에 무작위 방향으로 살짝 흔들어 두 번만 돌려 기울기를 어림합니다. 변수가 백 개여도 두 번이에요.

교차 엔트로피법(CEM)은 기울기를 아예 쓰지 않습니다. 후보를 여러 개 뽑아 돌려 보고, 좋은 몇 개의 평균과 퍼짐으로 다음 후보들을 뽑기를 되풀이해요. 드론 실습의 MPPI가 이 집안입니다. 잡음에 강하고 단순하지만 평가 횟수가 많이 들어요.

한 줄로시뮬레이터로 잰 잡음 섞인 목적 함수는 차분 기울기가 흔들립니다. SPSA는 두 번의 실행으로 모든 방향의 기울기를 어림하고, CEM은 좋은 후보들의 분포를 좇아 내려가요.

import numpy as np
rng = np.random.default_rng(0)

def cost(x, noise=0.05):                     # 시뮬레이터로 잰 비용 (잡음 섞임)
    kp, kd = x
    true = 0.5 * ((kp - 4) / 1.5)**2 + ((kd - 2.8) / 0.8)**2
    return true + noise * rng.normal()

x = np.array([1.0, 0.5])                     # SPSA
for k in range(200):                         # 평가 400번
    a, c = 0.3 / (k + 10)**0.602, 0.3 / (k + 1)**0.101
    D = rng.choice([-1.0, 1.0], size=2)
    g = (cost(x + c * D) - cost(x - c * D)) / (2 * c) * D
    x = x - a * g

mu, sd = np.array([1.0, 0.5]), np.array([1.5, 1.5])   # 교차 엔트로피법
for it in range(25):                         # 평가 25 x 16 = 400번
    cand = mu + sd * rng.normal(size=(16, 2))
    elite = cand[np.argsort([cost(c) for c in cand])[:4]]
    mu, sd = elite.mean(0), elite.std(0) + 0.02
print(x, mu)                                 # 둘 다 (4, 2.8) 근처

로켓 착지 시뮬레이터에 바람, 추력 오차, 질량 오차 세 가지 불확실한 입력이 있습니다. 한 번 돌리는 데 몇 분이 걸려서 수천 번은 못 돌려요. 어떤 입력 조합으로 돌려야 적은 횟수로 많이 배울까요? 그게 실험 계획입니다.

격자로 고르게 찍으면 변수가 늘수록 횟수가 폭발하고, 그냥 무작위로 뽑으면 운 나쁘게 한쪽이 비어요. 라틴 하이퍼큐브는 변수마다 범위를 N칸으로 나눠 칸마다 정확히 한 점씩 오게 뽑습니다. 어느 변수 하나만 봐도 범위 전체가 고르게 덮여요.

그다음 질문은 ‘어떤 입력이 결과를 가장 흔드나’(민감도)입니다. 기준점에서 하나씩 살짝 바꿔 보는 국소 민감도는 싸지만, 두 입력이 함께 작용하는 효과(바람이 셀 때만 추력 오차가 중요해지는)를 놓쳐요. 입력을 모두 무작위로 흔들어 결과의 분산을 입력별로 나누는 전역 민감도(소볼 지수)는 그 효과까지 잡습니다.

한 줄로라틴 하이퍼큐브는 적은 실행으로 입력 범위를 고르게 덮습니다. 기준점의 미분(국소 민감도)은 상호작용을 놓치니, 결과의 분산을 입력별로 나누는 전역 민감도로 무엇이 중요한지 가려요.

변수 d개를 각각 m수준으로 격자를 짜면 md번이라, 수준 5개에 변수 6개면 15625번입니다. 라틴 하이퍼큐브는 N번이면 되고, 각 변수의 1차원 투영이 N개 층에 정확히 하나씩 들어가서 같은 N의 단순 무작위 표본보다 평균 같은 양을 훨씬 안정적으로 어림해요. 실험 결과로 2차 다항식 같은 응답 표면(대리 모델)을 맞추면, 비싼 시뮬레이터 대신 그 모델로 최적화와 민감도 분석을 빠르게 할 수 있습니다.

국소 민감도는 ∂y/∂xi를 기준점에서 재고 입력의 퍼짐을 곱해 비교합니다. 실습의 모형 y = 2x₁ + 0.3x₂ + 1.8x₁x₂ + 0.5x₃²에서 기준점(0, 0, 0)의 기울기는 (2, 0.3, 0)이라 x₂는 거의 무시해도 될 것처럼 보여요. 그런데 x₁이 클 때 x₂의 효과는 1.8x₁만큼 커집니다. 이 상호작용 몫이 전체 분산의 약 21%예요.

1차 소볼 지수 Si = Var(E[Y|Xi])/Var(Y)는 ‘Xi 하나만 정확히 알면 줄어드는 분산의 비율’이고, 1 − ΣSi가 상호작용 몫입니다. 실습은 표본 2만 개를 Xi 값으로 구간을 나눠 구간 평균의 분산으로 Si를 어림해요. 실제로는 Saltelli 표본 설계와 SALib 같은 라이브러리로 전체 효과 지수까지 함께 구합니다.

실험 계획과 전역 민감도
(14)
  1. 1라틴 하이퍼큐브. 변수마다 범위를 N칸으로 나누고 칸마다 점 하나. 변수끼리의 짝은 무작위로 섞어요.
  2. 2국소 민감도. 기준점에서 한 변수만 살짝 바꾼 기울기. 싸지만 상호작용을 못 봐요.
  3. 31차 소볼 지수. 그 입력 하나로 설명되는 분산의 비율. 나머지가 상호작용 몫입니다.
파이썬
import numpy as np
rng = np.random.default_rng(0)

def lhs(n, d):                                     # 라틴 하이퍼큐브 (범위 -1~1)
    u = (np.argsort(rng.random((d, n)), axis=1).T + rng.random((n, d))) / n
    return 2 * u - 1

def sim(x):                                        # 착지 오차를 흉내 낸 모형
    x1, x2, x3 = x.T
    return 2*x1 + 0.3*x2 + 1.8*x1*x2 + 0.5*x3**2

X = lhs(20_000, 3); Y = sim(X)
S = []
for i in range(3):                                 # 1차 소볼 지수: 구간 평균의 분산
    bins = np.digitize(X[:, i], np.linspace(-1, 1, 21))
    means = np.array([Y[bins == b].mean() for b in range(1, 21)])
    S.append(means.var() / Y.var())
print(np.round(S, 3), round(1 - sum(S), 3))       # [0.76 0.02 0.01], 상호작용 0.21
print('국소 기울기 at 0:', [2.0, 0.3, 0.0])         # x2를 과소평가
