컴퓨터의 숫자

컴퓨터는 실수를 정해진 자릿수로 어림합니다. 그 어림이 언제 무해하고 언제 답을 망치는지, 그리고 같은 문제라도 계산 순서만 바꿔 오차를 줄이는 법을 봅니다.

1

자릿수가 정해진 숫자: 부동소수점

쓰인 곳미적분 101 10단계의 오도메트리미적분 101 5단계의 차분 오차GPU의 float32 계산MCU 펌웨어
먼저, 수식 없이

파이썬에서 0.1 + 0.2를 계산하면 0.30000000000000004가 나옵니다. 고장이 아니에요. 컴퓨터는 수를 2진법으로, 그것도 정해진 자릿수(float64는 유효숫자 약 16자리)로만 적습니다. 0.1은 2진법으로 끝없이 이어지는 수라서 끝을 잘라 어림한 값이 저장돼요.

이 어림은 상대적입니다. 1 근처에서는 아주 촘촘하게, 100만 근처에서는 그보다 100만 배 성기게 수가 놓여 있어요. 자 눈금이 수가 커질수록 넓어지는 셈입니다. 그래서 아주 큰 수에 아주 작은 수를 더하면 작은 수가 사라져요. float32(유효숫자 약 7자리)에서 10,000,000 + 0.1은 그냥 10,000,000입니다.

로봇에서는 이게 실제로 문제가 됩니다. GPU와 마이크로컨트롤러는 float32를 자주 쓰는데, 지도의 원점에서 멀리 떨어진 곳(위도·경도를 미터로 바꾼 큰 좌표)에서 1 mm 움직임을 더하면 사라지거나 계단처럼 움직여요. 작은 걸음을 오래 더하는 오도메트리는 반올림 오차가 쌓여 수 %씩 틀어지기도 하고요. 지도 좌표를 로봇 근처 원점으로 옮기거나, 합을 보정하며 더하는 방법(카한 합)으로 막습니다.

한 줄로컴퓨터의 수는 유효숫자가 정해진 2진 부동소수점이라, 상대 오차 ε/2 이하로 어림됩니다. 큰 수에 작은 수를 더하면 작은 쪽이 사라지고, 작은 오차도 수백만 번 쌓이면 커져요.

조금 더 정확하게

float64는 부호 1비트, 지수 11비트, 가수 52비트로 x = ±(1.b₁b₂…b₅₂)₂ × 2ᵉ를 적습니다. 지수가 같은 구간(예: 1~2, 2~4) 안에서는 수가 고르게 2⁵²개씩 놓이고, 구간이 2배씩 커질 때마다 간격도 2배가 돼요. 1 다음 수와 1의 차이가 기계 엡실론 ε = 2⁻⁵² ≈ 2.2 × 10⁻¹⁶이고, 어떤 수든 가장 가까운 표현 가능한 수로 어림하면 상대 오차가 ε/2를 넘지 않습니다.

사칙연산도 정확한 결과를 다시 어림하므로 fl(a ∘ b) = (a ∘ b)(1 + δ), |δ| ≤ ε/2입니다. 한 번은 아주 작은 오차지만, 덧셈은 결합 법칙이 깨져서((a + b) + c ≠ a + (b + c)) 더하는 순서가 결과를 바꿉니다. n개를 차례로 더하면 최악의 오차는 대략 nε배까지 자라요. 카한 합은 매번 잃어버린 아랫자리를 따로 모아 다음 덧셈에 보태서, 오차를 n과 거의 무관하게 만듭니다.

float32는 ε = 2⁻²³ ≈ 1.2 × 10⁻⁷이라 1000만에서 간격이 1입니다. GPU 물리 시뮬레이터, 신경망, 마이크로컨트롤러가 메모리와 속도 때문에 float32(심지어 16비트)를 쓰니, 큰 좌표는 지역 원점 기준으로 옮기고, 오래 쌓는 합은 float64로 하거나 카한 합으로 보정하는 습관이 필요합니다.

import numpy as np

print(0.1 + 0.2)                        # 0.30000000000000004
print(np.finfo(np.float64).eps)         # 2.220446049250313e-16
print(np.finfo(np.float32).eps)         # 1.1920929e-07

x = np.float32(1e7)
print(x + np.float32(0.1))              # 10000000.0  ← 0.1이 사라짐
print(np.spacing(np.float32(1e7)))      # 1.0: 1000만 근처 눈금 간격

def kahan_sum(xs):                      # 잃어버린 조각을 들고 다니는 합
    s, c = np.float32(0), np.float32(0)
    for x in xs:
        y = x - c
        t = s + y
        c = (t - s) - y                 # 이번에 잃은 아랫자리
        s = t
    return s

steps = np.full(1_000_000, 0.01, dtype=np.float32)   # 1 cm씩 백만 번
print(np.cumsum(steps)[-1], kahan_sum(steps))         # 약 9865 vs 10000

핵심

컴퓨터의 수는 유효숫자가 정해진 부동소수점이라 상대 오차 ε/2 안에서 어림됩니다. 큰 수에 작은 수를 더하면 작은 쪽이 사라지고, 오래 쌓는 합은 오차도 쌓여요. 지역 원점, float64, 카한 합으로 막습니다.

빼기가 위험할 때: 상쇄와 다시 쓰기

쓰인 곳미적분 101 9단계의 작은 각 1 − cos θ확률과 통계 101의 소프트맥스미적분 101 2단계의 로그 가중치atan2와 hypot
먼저, 수식 없이

거의 같은 두 수를 빼면 앞자리가 모두 지워지고, 원래 맨 끝에 있던 어림 오차만 남습니다. 1.0000123과 1.0000000을 뺀 0.0000123은 맞는 자리가 셋뿐이에요. 이것을 상쇄라고 합니다. 오차가 새로 생긴 게 아니라, 원래 작던 오차가 결과에 비해 갑자기 커 보이는 거예요.

처방은 대부분 ‘식을 다시 쓰기’입니다. 작은 각에서 1 − cos θ는 거의 같은 두 수의 빼기라 float32에서 θ = 0.0001이면 0이 나와요. 같은 값을 2sin²(θ/2)로 쓰면 빼기가 없어서 정확합니다. 근의 공식, 거리 계산 √(x² + y²)(hypot), 각도(atan2)도 같은 이유로 안전한 형태가 따로 있어요.

반대 방향의 위험도 있습니다. 확률을 다룰 때 e1000은 컴퓨터가 표현할 수 없는 큰 수라서 무한대가 돼요. 소프트맥스나 로그 가능도 합을 계산할 때 가장 큰 값을 먼저 빼고 지수를 씌우는(log-sum-exp) 것도 식을 다시 써서 위험한 연산을 피하는 같은 꾀입니다.

한 줄로거의 같은 두 수를 빼면 유효숫자가 사라집니다(상쇄). 빼기가 없는 같은 값의 다른 식으로 다시 쓰고, 큰 지수는 최댓값을 먼저 빼서 계산해요.

조금 더 정확하게

a와 b에 각각 상대 오차 ε 정도가 있으면 a − b의 절대 오차는 그대로 ε|a| 정도인데, 결과 |a − b|가 아주 작으면 상대 오차는 ε|a|/|a − b|로 커집니다. 잃는 유효숫자는 대략 log₁₀(|a|/|a − b|)자리예요. 그래서 빼기 자체보다 ‘빼기 직전 값들이 이미 어림된 값인가’가 문제입니다. 1 − cos θ에서 cos θ가 이미 1에 아주 가깝게 어림되었기 때문에 망가져요.

근의 공식 x = (−b ± √(b² − 4c))/2에서 b²이 4c보다 훨씬 크면 √ 값이 |b|와 거의 같아져서, 부호가 반대인 쪽 근에서 상쇄가 일어납니다. 그래서 상쇄가 없는 쪽 근 x₁을 먼저 구하고 다른 근은 x₂ = c/x₁(두 근의 곱)로 구해요. 같은 식, 다른 계산 순서입니다.

log Σezi은 m = max zi를 빼면 m + log Σezi−m이 되고, 지수 안이 모두 0 이하라 넘치지 않으며 가장 큰 항이 정확히 1이라 밑넘침으로 0이 되지도 않아요. np.hypot(x, y)는 x² 단계에서 넘치지 않게 크기를 맞춰 계산하고, atan2(y, x)는 y/x를 나누지 않아 x가 0이어도 안전합니다.

문제가 예민한가, 방법이 불안한가: 조건수

쓰인 곳선형대수 101 12단계의 조건수선형대수 101 8단계의 최소제곱최적화 101 3단계의 정규방정식IK의 특이점
먼저, 수식 없이

오차가 커지는 데는 두 가지 이유가 있습니다. 하나는 문제 자체가 예민한 경우예요. 비콘 세 개가 거의 한 줄에 있으면, 측정이 1 mm만 달라도 계산한 위치가 수십 cm 움직입니다. 어떤 방법으로 풀어도 마찬가지예요. 이 예민함의 배율이 조건수입니다.

다른 하나는 방법이 불안한 경우입니다. 문제는 멀쩡한데, 계산 순서가 중간에 오차를 키우는 거예요. 2단계의 상쇄가 그 예였고, 최소제곱을 정규방정식 AᵀAx = Aᵀy로 푸는 것도 그렇습니다. AᵀA를 만드는 순간 조건수가 제곱이 되어서, 원래 문제보다 두 배 많은 자릿수를 잃어요.

좋은 방법(안정한 알고리즘)은 문제의 조건수만큼만 오차를 키웁니다. 그래서 수치 라이브러리는 최소제곱을 QR 분해나 SVD로 풀어요. np.linalg.lstsq가 그렇게 하고, SLAM처럼 행렬이 아주 크고 성길 때만 속도 때문에 정규방정식(촐레스키)을 쓰되 조건을 미리 다듬습니다.

한 줄로조건수는 문제가 입력 오차를 몇 배로 키우는지이고, 대략 log₁₀κ자리를 잃습니다. 안정한 방법은 그 이상 키우지 않고, 정규방정식은 조건수를 제곱해서 두 배를 잃어요.

조건수 κ
입력의 상대 오차가 출력에서 몇 배가 되나.
안정한 알고리즘
문제의 조건수만큼만 오차를 키우는 계산 방법.
정규방정식
AᵀAx = Aᵀy. 빠르지만 κ가 제곱이 됨.

까먹었다면선형대수 101 12단계: 조건수는 가장 큰 특잇값 ÷ 가장 작은 특잇값. 1이면 모든 방향을 고르게 늘이고, 클수록 한쪽으로 납작해서 풀기 까다로워요.

조금 더 정확하게

함수 y = f(x)라면 x의 상대 오차가 y에서 κf = |xf′(x)/f(x)|배가 됩니다. 행렬 문제 Ax = b라면 κ(A) = σmax/σmin이 그 배율이에요. 입력이 기계 엡실론만큼만 틀려도 답은 κε만큼 틀릴 수 있으니, float64(약 16자리)로 κ = 10⁸인 문제를 풀면 믿을 만한 자릿수는 약 8자리입니다. 이건 방법이 좋든 나쁘든 어쩔 수 없는 한계예요.

방법의 안정성은 ‘구한 답이 조금 다른 입력에 대한 정확한 답인가’로 봅니다(후방 안정성). 그렇다면 오차는 κε 정도로 묶이고, QR 분해와 피벗을 쓴 LU(5단계)가 이런 방법이에요. 정규방정식은 AᵀA의 조건수 κ²으로 풀게 되어 κε 대신 κ²ε까지 틀릴 수 있습니다. κ = 10⁸이면 κ² = 10¹⁶이라 float64로는 답이 전혀 남지 않아요.

조건수가 큰 문제는 문제를 바꾸는 게 답일 때가 많습니다. 다항식을 1, x, x², …로 맞추는 대신 직교 다항식(체비쇼프 등)을 쓰고, 변수의 단위를 맞추고(최적화 101 4단계의 diag(JᵀJ)), 비콘을 넓게 배치하고, 특이점 근처에서는 감쇠를 넣는(선형대수 101 7단계의 DLS) 식이에요.

조건수: 문제가 오차를 몇 배로 키우나
(3)
  1. 1조건수의 뜻. 입력이 1% 틀리면 출력은 κ% 틀린다. 함수라면 |xf′/f|로 계산해요.
  2. 2잃는 자릿수. κ = 10⁸이면 float64의 16자리 중 약 8자리를 잃습니다. 방법과 상관없는 문제의 성질이에요.
  3. 3정규방정식의 대가. AᵀA를 만드는 순간 조건수가 제곱. 같은 문제인데 두 배의 자릿수를 잃어요.
파이썬
import numpy as np

x = np.linspace(0, 1, 40)
for deg in [3, 6, 9, 12]:
    A = np.vander(x, deg + 1, increasing=True)      # 1, x, x^2, ... 열
    c_true = 1.0 / np.arange(1, deg + 2)
    y = A @ c_true                                   # 잡음 없는 데이터
    c_ne = np.linalg.solve(A.T @ A, A.T @ y)         # 정규방정식
    Q, R = np.linalg.qr(A)
    c_qr = np.linalg.solve(R, Q.T @ y)               # QR
    print(deg, f'{np.linalg.cond(A):.1e}',
          f'{np.abs(c_ne - c_true).max():.1e}',
          f'{np.abs(c_qr - c_true).max():.1e}')
# 12차: cond 4.4e+08, 정규방정식 오차 ~1e+00, QR 오차 ~1e-08

해 볼 것

  • 차수를 3에서 12까지 올려 보세요. 조건수(회색)가 자라는 만큼 QR의 오차(주황)가 커지고, 정규방정식의 오차(빨강)는 그 제곱만큼 커집니다. 12차에서 정규방정식은 계수가 완전히 틀리고 QR은 8자리 정도 맞아요.
  • 위 그래프의 두 곡선은 데이터 점을 거의 똑같이 지나갑니다. 맞춘 곡선은 멀쩡해 보여도 계수는 엉터리일 수 있어요. 조건수가 크다는 건 서로 아주 다른 계수들이 거의 같은 곡선을 만든다는 뜻이기도 합니다.
  • [체비쇼프 기저]를 켜면 같은 차수, 같은 데이터인데 조건수가 수십 이하로 떨어지고 두 방법 모두 정확해집니다. 문제를 다시 세우는 것이 가장 좋은 처방이에요.

핵심

조건수는 문제가 오차를 키우는 배율이고, 어떤 방법도 log₁₀κ자리 손실은 피할 수 없습니다. 안정한 방법(QR, 피벗 LU)은 그 이상 잃지 않고, 정규방정식은 κ²으로 두 배를 잃어요. 조건수가 크면 문제를 다시 세우세요.

g(x) = 0 찾기: 이분법, 뉴턴, 할선

쓰인 곳카메라 렌즈 왜곡 되돌리기최적화 101 2단계의 뉴턴법10단계의 접촉 순간 찾기역기구학의 1차원 문제
먼저, 수식 없이

카메라 렌즈는 사진 가장자리를 둥글게 휩니다. 왜곡 모델은 ‘원래 반지름 r을 넣으면 찍힌 반지름 rd가 나오는’ 식 rd = r(1 + k₁r² + k₂r⁴)라서, 찍힌 점에서 원래 점을 구하려면 이 식을 거꾸로 풀어야 해요. 식으로 바로 풀 수 없으니, g(r) = r(1 + k₁r² + k₂r⁴) − rd = 0인 r을 찾아 다가갑니다. 이게 근 찾기예요.

가장 믿음직한 방법은 이분법입니다. 부호가 다른 두 점 사이에 답이 있으니 가운데를 재서 반을 버리기를 되풀이해요. 매번 구간이 절반이 되니 열 번에 약 3자리씩 정확해집니다. 느리지만 절대 놓치지 않아요.

뉴턴법은 지금 자리의 접선이 0이 되는 곳으로 점프합니다. 답 근처에서는 맞는 자릿수가 걸음마다 두 배가 되어 대여섯 번이면 끝나지만, 기울기가 0에 가까운 곳에서 출발하면 엉뚱한 곳으로 튀어요. 할선법은 미분 대신 최근 두 점을 잇는 직선을 써서, 미분식이 없어도 뉴턴에 가깝게 빠릅니다. 실제 라이브러리(scipy.optimize.brentq)는 이분법의 안전함과 할선법의 빠르기를 섞어요.

한 줄로근 찾기는 g(x) = 0에 되풀이해서 다가가는 일입니다. 이분법은 느리지만 확실하고, 뉴턴은 빠르지만 출발점에 민감하며, 할선법은 미분 없이 뉴턴에 가까워요.

까먹었다면최적화 101 2단계의 뉴턴법은 f′(x) = 0을 찾으려고 x − f′/f″로 걸었어요. 근 찾기의 뉴턴법은 g(x) = 0을 찾으려고 x − g/g′로 걷습니다. 같은 생각이에요.

조금 더 정확하게

이분법은 구간 [a, b]의 양 끝에서 g의 부호가 다르면(중간값 정리) 가운데 m을 재서 부호가 다른 쪽 반을 남깁니다. k번 뒤 오차는 (b − a)/2k 이하라서 정확도를 미리 알 수 있고, 함수가 연속이기만 하면 반드시 근에 닿아요. 대신 걸음마다 1비트(약 0.3자리)씩만 얻습니다.

뉴턴법은 xk+1 = xk − g(xk)/g′(xk)입니다. 오차가 ek라면 다음 오차는 대략 (g″/2g′)ek²이라서, 근 근처에서는 맞는 자릿수가 두 배씩 늘어요(2차 수렴). 할선법은 g′ 자리에 (g(xk) − g(xk−1))/(xk − xk−1)을 써서 미분식이 필요 없고, 수렴 차수는 황금비 1.618입니다. 함수 계산 한 번에 한 걸음이라 실제 시간으로는 뉴턴보다 빠른 경우가 많아요.

실용적으로는 ‘구간을 가둬 둔 채로 빠른 걸음을 시도하고, 그 걸음이 구간을 벗어나면 이분법 걸음으로 대신하기’가 표준입니다(브렌트 방법). 멈추는 조건도 중요해요. |g(x)|가 작아졌는지와 걸음 |xk+1 − xk|가 작아졌는지를 함께 보고, 최대 반복 횟수를 꼭 둡니다.

근 찾기 세 가지
(4)
  1. 1이분법의 오차. 걸음마다 절반. 30번이면 처음 구간의 10억분의 1이에요.
  2. 2뉴턴 걸음. 접선이 0이 되는 곳으로. 근 근처에서는 자릿수가 두 배씩 늘어요.
  3. 3할선 걸음. 접선 대신 최근 두 점을 잇는 직선. 미분식이 필요 없습니다.
파이썬
import numpy as np
from scipy.optimize import brentq

k1, k2, rd = -0.3, 0.1, 0.8                  # 렌즈 왜곡 계수, 찍힌 반지름
g  = lambda r: r * (1 + k1*r**2 + k2*r**4) - rd
dg = lambda r: 1 + 3*k1*r**2 + 5*k2*r**4

a, b = 0.0, 1.5                              # 이분법
for k in range(30):
    m = (a + b) / 2
    if g(a) * g(m) <= 0: b = m
    else: a = m

r = rd                                       # 뉴턴 (찍힌 반지름에서 출발)
for k in range(6):
    r = r - g(r) / dg(r)                     # 0.992 → 1.0000091 → 1.0

print((a + b) / 2, r, brentq(g, 0, 1.5))     # 모두 1.0

해 볼 것

  • [한 걸음]을 눌러 세 방법을 나란히 진행해 보세요. 아래 그래프(오차, 로그 눈금)에서 이분법(파랑)은 곧은 직선으로, 할선(초록)은 점점 가파르게, 뉴턴(주황)은 거의 절벽처럼 떨어집니다. 직선의 기울기가 수렴 차수예요.
  • 뉴턴의 출발점(주황 점)을 g의 기울기가 0에 가까운 곳(곡선이 평평한 언덕)으로 끌어 보세요. 첫 걸음이 그래프 밖으로 멀리 튀거나 다른 근으로 가 버립니다. 이분법은 구간만 바르게 잡으면 그런 일이 없어요.
  • k₁을 −0.6까지 내리면 g가 0 근처에서 거의 평평해지면서 뉴턴의 첫 몇 걸음이 느려지거나 엇나갑니다. 강한 광각 렌즈일수록 왜곡 되돌리기에 좋은 출발점이 필요한 이유예요.

핵심

근 찾기는 g(x) = 0에 되풀이해서 다가갑니다. 이분법은 확실하지만 느리고, 뉴턴은 2차 수렴이지만 출발점에 민감하며, 할선은 미분 없이 빠릅니다. 실제로는 구간을 가둔 채 빠른 걸음을 섞어요.

연립방정식을 안전하게: LU 분해와 피벗

쓰인 곳선형대수 101 8단계의 정규방정식최적화 101의 JᵀJΔ = −Jᵀr칼만 필터의 이득 계산np.linalg.solve
먼저, 수식 없이

중학교에서 배운 연립방정식 소거법을 기억하나요? 첫 식의 몇 배를 둘째 식에서 빼서 x를 지우고, 남은 식에서 y를 구하고 거꾸로 대입하는 것. 컴퓨터도 정확히 이렇게 풉니다(가우스 소거). 이 과정을 행렬로 적으면 A = LU, 곧 아래 삼각 행렬과 위 삼각 행렬의 곱이에요.

함정이 하나 있습니다. 첫 식의 x 계수가 0.000000000001처럼 아주 작으면 ‘몇 배’가 10¹²이 되고, 그 큰 배수를 곱해 빼는 동안 다른 식의 정보가 반올림으로 지워져요. 해법은 단순합니다. 지울 열에서 절댓값이 가장 큰 식을 맨 위로 올리고(피벗) 시작하는 것. 행 순서만 바꿨을 뿐인데 답이 살아납니다.

그리고 하나 더. 역행렬 A⁻¹을 구해서 곱하지 마세요. 더 느리고 덜 정확합니다. np.linalg.solve(A, b)가 내부에서 피벗 LU를 써요. 같은 A로 여러 b를 풀 때는 LU 분해를 한 번만 하고 삼각 행렬 풀기만 되풀이하면 됩니다.

한 줄로연립방정식은 가우스 소거(LU 분해)로 풉니다. 아주 작은 수로 나누면 답이 망가지니 매번 가장 큰 수를 피벗으로 고르고, 역행렬 대신 solve를 쓰세요.

가우스 소거는 열마다 피벗 아래 칸을 0으로 만듭니다. r행에서 c행의 ℓrc = arc/acc배를 빼는 식이에요. 이 배수들을 모은 것이 L, 남은 위 삼각 행렬이 U라서 A = LU이고, Ax = b는 Ly = b(전진 대입)와 Ux = y(후진 대입) 두 번의 쉬운 풀이가 됩니다. 분해는 n³/3번, 대입은 n²번이라, 같은 A로 b를 여러 번 바꿔 풀 때 분해를 다시 하지 않는 게 큰 이득이에요.

[[ε, 1], [1, 1]]을 피벗 없이 소거하면 ℓ₂₁ = 1/ε, u₂₂ = 1 − 1/ε입니다. ε가 아주 작으면 1 − 1/ε은 −1/ε로 어림되어 ‘1’이라는 정보가 사라져요. 결과는 x₁이 완전히 틀린 답입니다. 이 행렬의 조건수는 약 2.6으로 아주 착한 문제인데도요. 3단계의 말로 하면 ‘문제는 멀쩡한데 방법이 불안한’ 경우예요. 행을 바꿔 1을 피벗으로 쓰면(부분 피벗) 배수가 1 이하로 묶여서 오차가 커지지 않습니다. 기록은 PA = LU로 남겨요.

대칭 양의 정부호 행렬(최소제곱의 JᵀJ, 칼만 필터의 공분산)이라면 피벗 없이도 안정한 촐레스키 분해 A = LLᵀ를 쓸 수 있고 LU보다 두 배 빠릅니다(선형대수 101 14단계). 역행렬은 n³번 더 들고 오차도 커서, 식에 A⁻¹이 보이더라도 코드에서는 solve로 바꾸는 것이 원칙이에요.

LU 분해와 피벗
(5)
  1. 1피벗 LU 분해. 행 순서를 바꾸는 P를 기록해 두고 A를 아래·위 삼각 행렬로 나눠요.
  2. 2두 번의 쉬운 풀이. 위에서부터 y, 아래에서부터 x. 같은 A면 분해는 한 번만.
  3. 3작은 피벗의 위험. 배수가 1/ε로 커져서, 1 − 1/ε에서 ‘1’이 반올림으로 사라집니다.
파이썬
import numpy as np
from scipy.linalg import lu_factor, lu_solve

def solve_no_pivot(A, b):                    # 교과서 그대로, 피벗 없음
    A, b = A.astype(float).copy(), b.astype(float).copy()
    n = len(b)
    for c in range(n):
        for r in range(c + 1, n):
            l = A[r, c] / A[c, c]            # ε가 작으면 l이 거대해짐
            A[r, c:] -= l * A[c, c:]; b[r] -= l * b[c]
    x = np.zeros(n)
    for r in reversed(range(n)):
        x[r] = (b[r] - A[r, r+1:] @ x[r+1:]) / A[r, r]
    return x

eps = 1e-17
A = np.array([[eps, 1, 1], [1, 1, 0], [0, 1, 2]]); b = A @ np.ones(3)
print(solve_no_pivot(A, b))                  # [0, 1, 1]  ← x1이 틀림
print(np.linalg.solve(A, b))                 # [1, 1, 1]  (피벗 LU)

lu, piv = lu_factor(A)                       # 분해 한 번
for k in range(3):                           # b만 바꿔 여러 번
    x = lu_solve((lu, piv), b * (k + 1))

  • ε를 10⁻³에서 10⁻¹⁷까지 줄여 보세요. 피벗 없는 풀이(빨강)의 x₁이 10⁻¹²쯤부터 틀리기 시작해 10⁻¹⁷에서는 0이 됩니다. 피벗 풀이(주황)는 끝까지 1이에요. 행렬의 조건수(오른쪽)는 내내 작습니다.
  • [다음 단계]로 소거를 한 칸씩 진행해 보세요. 피벗이 없으면 배수 ℓ이 10¹⁷ 같은 값이 되고, 둘째 행의 숫자들이 거대한 값으로 덮이는 게 보입니다. 피벗을 켜면 첫 단계에서 두 행이 바뀌고 배수가 모두 1 이하로 남아요.
  • ‘조건수가 작은데도 틀린다’는 게 핵심입니다. 이 실패는 문제가 아니라 방법 탓이에요. 3단계의 정규방정식과 같은 종류의 실패입니다.

핵심

연립방정식은 LU 분해로 풀고, 매 열에서 가장 큰 수를 피벗으로 골라 배수가 커지지 않게 합니다. 역행렬 대신 solve를 쓰고, 같은 행렬로 여러 번 풀면 분해를 재사용하세요.

크고 성긴 격자는 되풀이해서: 반복법

쓰인 곳미적분 101 8단계의 퍼텐셜 필드선형대수 101 14단계의 희소 행렬MuJoCo의 접촉 풀이기(PGS, CG, Newton)점유 격자 위 경로 계획
먼저, 수식 없이

미적분 101의 퍼텐셜 필드는 U자 장애물에서 갇혔습니다. 국소 최솟값이 없는 퍼텐셜을 만드는 방법이 있어요. 지도의 칸마다 ‘값 = 네 이웃의 평균’이라는 규칙을 두고, 목표 칸은 0, 벽과 장애물은 1로 고정하는 겁니다. 이 규칙을 만족하는 값(조화 함수)에는 벽이 아닌 곳에 웅덩이가 생길 수 없어서, 어디서든 내리막만 따라가면 목표에 닿아요.

그런데 칸이 수천 개면 연립방정식도 수천 개입니다. 5단계의 LU로 풀 수도 있지만, 각 식에는 이웃 넷만 등장해서 행렬이 거의 비어(성겨) 있어요. 이럴 때는 ‘모든 칸을 이웃의 평균으로 바꾸기’를 되풀이하는 반복법이 단순하고 메모리도 적게 듭니다. 야코비 방법은 지난 판의 값으로, 가우스-자이델은 방금 바꾼 값을 바로 써서 두 배쯤 빨라요.

그래도 칸이 많으면 정보가 한 칸씩만 퍼져서 수천 번이 걸립니다. 조금 더 밀어 주는 SOR, 그리고 방향을 똑똑하게 골라 √κ에 비례하는 걸음으로 끝내는 켤레 기울기법(CG)이 표준 가속 방법이에요. MuJoCo의 접촉 풀이기도 PGS(가우스-자이델 계열), CG, 뉴턴 중에서 고릅니다.

한 줄로큰 성긴 연립방정식은 ‘이웃으로 값을 고치기’를 되풀이해서 풉니다. 가우스-자이델은 야코비의 두 배, SOR과 켤레 기울기법은 그보다 훨씬 빠르게 수렴해요.

조금 더 정확하게

격자의 각 자유 칸에 대해 ui,j = ¼(이웃 넷의 합)을 쓰면 라플라스 방정식의 이산판입니다. 칸 N개면 N개의 식이지만 식마다 다섯 칸만 등장해서, 행렬 칸 N²개 중 5N개만 0이 아니에요. 최대 원리 덕분에 해는 경계값(0과 1) 사이에 있고 내부에 극값이 없습니다. 그래서 이 u를 퍼텐셜로 쓰면 국소 최솟값 없는 경로 계획이 돼요.

야코비는 모든 칸을 지난 판 값의 평균으로 동시에 바꾸고, 가우스-자이델은 차례로 돌며 방금 바꾼 이웃 값을 바로 씁니다. 둘 다 오차가 걸음마다 일정 비율로 줄지만, 그 비율이 격자 크기의 제곱에 가깝게 1에 다가가서 큰 격자에서는 수천 번이 걸려요. SOR은 u ← u + ω(ū − u)로 1 < ω < 2만큼 더 밀어 걸음 수를 격자 크기에 비례하게 줄입니다.

켤레 기울기법은 대칭 양의 정부호 행렬에서 ‘앞서 간 방향과 서로 간섭하지 않는(켤레) 방향’으로만 걸어서, 오차가 대략 ((√κ − 1)/(√κ + 1))k로 줄어요. 최적화 101 2단계의 모멘텀과 같은 √κ의 이득입니다. 큰 SLAM 문제는 촐레스키 같은 직접법(선형대수 101 14단계)과 이런 반복법 중 크기와 구조에 맞춰 고릅니다.

되풀이해서 푸는 연립방정식
(6)
  1. 1이웃 평균. 격자 칸마다의 식. 목표와 벽은 값을 고정해요.
  2. 2고치기 한 걸음. ū는 이웃 평균. ω = 1이면 가우스-자이델, 1~2면 더 밀어 주는 SOR.
  3. 3켤레 기울기의 속도. 오차가 걸음마다 (√κ − 1)/(√κ + 1)배. 야코비·가우스-자이델은 √ 없이 κ에 묶여요.
파이썬
import numpy as np

H, W = 26, 40
fixed = np.zeros((H, W), bool); val = np.ones((H, W))
fixed[0, :] = fixed[-1, :] = fixed[:, 0] = fixed[:, -1] = True   # 벽 = 1
fixed[8:18, 18] = True                                          # 장애물 = 1
fixed[13, 33] = True; val[13, 33] = 0.0                         # 목표 = 0
u = np.where(fixed, val, 0.5)

omega = 1.85
for it in range(5000):                       # SOR (omega = 1이면 가우스-자이델)
    change = 0.0
    for i in range(1, H - 1):
        for j in range(1, W - 1):
            if fixed[i, j]: continue
            avg = 0.25 * (u[i-1, j] + u[i+1, j] + u[i, j-1] + u[i, j+1])
            d = omega * (avg - u[i, j]); u[i, j] += d
            change = max(change, abs(d))
    if change < 1e-8: break
print(it)                                    # 백 번 남짓 (가우스-자이델은 그 열 배쯤)

gy, gx = np.gradient(u)                      # 로봇은 -∇u를 따라가면 된다

해 볼 것

  • 방법을 [야코비], [가우스-자이델], [SOR], [CG]로 바꿔 [재생]해 보세요. 왼쪽 지도의 색이 목표에서부터 퍼져 나가는 빠르기와, 오른쪽 아래 잔차 그래프의 기울기를 비교하세요. 같은 정확도까지 야코비는 천 번 넘게, CG와 SOR은 백 번 남짓이면 됩니다.
  • 다 수렴한 뒤 지도 아무 곳이나 눌러 로봇을 놓으면 −∇u를 따라가는 경로(주황)가 그려져요. 장애물을 끌어 U자처럼 막아도 미적분 101의 퍼텐셜 필드와 달리 갇히지 않습니다.
  • 덜 수렴한 상태(예: 야코비 50번)에서 로봇을 놓아 보세요. 목표의 영향이 아직 퍼지지 않은 곳에서는 기울기가 거의 0이라 로봇이 멈춥니다. 반복법은 ‘다 풀린 다음’에 써야 해요.

핵심

큰 성긴 연립방정식은 이웃으로 값을 고치기를 되풀이해서 풉니다. 가우스-자이델, SOR, 켤레 기울기 순으로 빨라지고, 격자에서 라플라스 방정식을 풀면 국소 최솟값 없는 경로 계획 퍼텐셜이 나와요.

로봇팔이 경유점 다섯 개를 지나가게 하려면 점 사이의 궤적을 메워야 합니다. 가장 단순한 건 직선으로 잇는 것인데, 꺾이는 점에서 속도가 순간 바뀌어서 모터가 덜컹거려요. 그럼 모든 점을 지나는 매끄러운 곡선 하나(다항식)로 이으면 될까요?

점이 적을 때는 괜찮지만, 고르게 놓인 점이 많아지면 다항식은 양 끝에서 크게 출렁입니다(룽게 현상). 점을 늘릴수록 오히려 더 틀려요. 두 가지 처방이 있습니다. 점을 양 끝에 촘촘하게 놓거나(체비쇼프 점), 아니면 곡선 하나 대신 구간마다 짧은 3차 곡선을 이어 붙이는 스플라인을 쓰는 것이에요.

스플라인은 이음매에서 위치, 기울기(속도), 휘는 정도(가속도)까지 맞춰 이어 붙여서 매끄럽고, 점 하나를 옮겨도 그 근처만 바뀝니다. 로봇 궤적, 센서 보정표, 애니메이션 곡선이 대부분 스플라인이에요. 드론 실습의 최소 스냅 궤적은 같은 생각을 7차 다항식 조각과 스냅 최소화로 넓힌 것입니다.

한 줄로점이 많을 때 다항식 하나로 이으면 양 끝이 출렁입니다(룽게). 구간마다 3차 곡선을 매끄럽게 이어 붙인 스플라인이 궤적과 보정표의 표준이에요.

3차 스플라인
구간마다 3차식, 이음매에서 값·기울기·휨이 연속.

까먹었다면점 두 개를 지나는 직선은 하나, 세 개를 지나는 2차식(포물선)은 하나예요. 점 n + 1개를 지나는 n차 다항식은 하나뿐입니다.

조금 더 정확하게

점 n + 1개를 지나는 n차 다항식 pn의 오차는 f(n+1)(ξ)/(n + 1)! × Π(x − xi)입니다. 뒤의 곱 Π(x − xi)는 점들이 고르면 양 끝 근처에서 아주 커져서, 미분이 빨리 커지는 함수(1/(1 + 25x²) 같은)에서는 차수를 올릴수록 끝이 출렁여요. 점을 cos((2i + 1)π/(2n + 2))처럼 양 끝에 몰면 이 곱이 고르게 작아져 오차가 차수와 함께 줄어듭니다.

3차 스플라인 s(x)는 구간마다 3차식이고, 이음매에서 s, s′, s″이 연속이 되도록 계수를 정합니다. 양 끝 조건(예: s″ = 0, 자연 스플라인)을 더하면 미지수가 정확히 맞아서, 삼중 대각 연립방정식 하나로 풀려요. 5단계의 LU가 이 모양에서는 n번 연산으로 끝납니다(토마스 알고리즘). 점 하나를 옮기면 영향이 이웃 구간으로 빠르게 줄어드는 것도 장점이에요.

로봇 궤적에서는 위치뿐 아니라 속도와 가속도의 연속이 중요합니다. 3차 스플라인은 가속도까지 연속이고, 저크까지 연속이 필요하면 5차, 드론처럼 스냅까지 연속이 필요하면 7차 조각을 써요. 시간에 대한 보간이니, 경유점 사이 시간을 어떻게 나누느냐도 궤적 모양을 크게 바꿉니다.

보간의 오차와 스플라인

  2. 2체비쇼프 점. 원 위에 고르게 놓은 점을 바닥에 내린 것. 양 끝이 촘촘합니다.

f = lambda x: 1 / (1 + 25 * x**2)           # 룽게 함수

for n in [5, 10, 15]:

             np.abs(sp(xx) - f(xx)).max())  # 0.42, 0.022, 0.031

미분을 정확히: 자동 미분

쓰인 곳미적분 101 5단계의 차분 오차미적분 101 6단계의 역전파최적화 101의 야코비안JAX·PyTorch·Ceres
먼저, 수식 없이

미적분 101에서 차분으로 미분을 어림하면 h를 크게 잡으면 근사 오차가, 작게 잡으면 반올림 오차가 커져서 기껏해야 8자리 정도만 맞았습니다. 미분식을 손으로 유도하면 정확하지만, 로봇 모델처럼 식이 길면 틀리기 쉽고 고칠 때마다 다시 유도해야 해요.

자동 미분은 세 번째 길입니다. 프로그램은 결국 더하기, 곱하기, sin, exp 같은 작은 연산의 사슬이고, 각 연산의 미분 규칙은 알고 있어요. 그래서 값을 계산하면서 ‘기울기’도 함께 들고 다니며 규칙대로 갱신하면, 근사 없이 기계 정밀도까지 정확한 미분이 나옵니다. 연쇄 법칙을 컴퓨터가 대신 적용하는 거예요.

기울기를 들고 다니는 쉬운 방법이 이중수입니다. 모든 수를 (값, 기울기) 짝으로 바꾸고 연산마다 짝을 함께 계산하면 앞방향 자동 미분이 돼요. 출력이 하나이고 입력이 많은 신경망 학습에서는 거꾸로 훑는 뒷방향(역전파)이 훨씬 싸고, 입력이 적은 로봇 야코비안에는 앞방향이 잘 맞습니다.

한 줄로자동 미분은 연산마다 미분 규칙을 적용해 값과 기울기를 함께 계산합니다. 근사가 없어서 기계 정밀도까지 정확하고, 앞방향(이중수)과 뒷방향(역전파)이 있어요.

자동 미분
프로그램의 연산마다 연쇄 법칙을 적용해 정확한 미분을 계산.
이중수
a + bε, ε² = 0. b가 기울기를 들고 다님.
앞방향
입력 하나에 대한 미분을 출력 쪽으로 밀고 감.
뒷방향
출력 하나에 대한 미분을 입력 쪽으로 거꾸로 모음.

까먹었다면미적분 101 6단계: (fg)′ = f′g + fg′, (sin u)′ = cos u · u′(연쇄 법칙). 이중수의 곱셈 규칙이 바로 곱의 미분 규칙입니다.

조금 더 정확하게

이중수 a + bε는 ε² = 0인 가상의 수 ε를 쓴 수예요. 함수에 x + ε를 넣으면 테일러 전개에서 ε²부터가 모두 사라져 f(x + ε) = f(x) + f′(x)ε가 됩니다. 곱하면 (a + bε)(c + dε) = ac + (ad + bc)ε로, ε 칸이 정확히 곱의 미분 규칙을 따라요. sin, exp 같은 함수도 sin(a + bε) = sin a + b cos a ε처럼 규칙 하나씩만 정의하면 됩니다.

앞방향 모드는 입력 하나에 ε를 붙여 한 번 계산하면 모든 출력의 그 입력에 대한 미분이 나옵니다. 야코비안의 열 하나예요. 관절 셋인 팔의 손끝 야코비안은 세 번 계산하면 끝납니다. 뒷방향 모드는 계산을 한 번 기록한 뒤 출력에서부터 거꾸로 훑어 출력 하나의 모든 입력에 대한 미분, 곧 그래디언트를 한 번에 얻어요. 가중치 백만 개짜리 손실의 그래디언트가 계산 몇 번 값인 이유입니다.

자동 미분이 만능은 아닙니다. if 문으로 갈라지는 곳, 절댓값이나 clip의 꺾이는 점에서는 한쪽 미분만 나오고, 반복법(6단계)을 그대로 미분하면 반복 과정 전체를 미분하느라 비쌉니다. 그래도 SLAM 라이브러리(Ceres, GTSAM)와 학습 프레임워크(JAX, PyTorch)가 모두 이걸 쓰는 이유는, 미분식을 틀릴 일이 없기 때문이에요.

이중수로 하는 자동 미분
(8)
  1. 1이중수. 값 a와 기울기 b를 함께 들고 다니는 수. ε² = 0이 핵심이에요.
  2. 2넣으면 미분이 나온다. 테일러 전개의 1차 항만 남아서 ε 칸이 정확히 f′(x)입니다.
  3. 3연산 규칙. 곱은 곱의 미분 규칙, sin은 연쇄 법칙 그대로. 연산마다 규칙 하나씩이면 돼요.
파이썬
import math

class Dual:                                   # 앞방향 자동 미분
    def __init__(s, v, d=0.0): s.v, s.d = v, d
    def __add__(s, o): o = o if isinstance(o, Dual) else Dual(o); return Dual(s.v + o.v, s.d + o.d)
    def __mul__(s, o): o = o if isinstance(o, Dual) else Dual(o); return Dual(s.v * o.v, s.d * o.v + s.v * o.d)
    __radd__, __rmul__ = __add__, __mul__
def sin(x): return Dual(math.sin(x.v), math.cos(x.v) * x.d)
def exp(x): return Dual(math.exp(x.v), math.exp(x.v) * x.d)

f = lambda x: sin(x * x) * exp(x)
y = f(Dual(0.7, 1.0))                          # 입력에 ε를 붙여 한 번 계산
print(y.v, y.d)                                # 값과 정확한 미분 3.4352444125931836

h = 1e-5                                       # 비교: 중심 차분
g = lambda x: math.sin(x*x) * math.exp(x)
print((g(0.7 + h) - g(0.7 - h)) / (2*h))       # 3.43524441... (10자리 남짓)

# 실제로는: jax.jacfwd(f), torch.autograd.functional.jacobian(f, x)

  • 그래프에서 차분의 간격 h를 바꿔 보세요. 앞쪽 차분(빨강)과 중심 차분(파랑)은 가장 좋은 h에서도 8~11자리에 머물지만, 자동 미분(주황 선)은 h와 상관없이 16자리 가까이 맞습니다.

핵심

딱딱한 것이 터질 때: 경직 방정식과 암시적 방법

쓰인 곳미적분 101 12단계의 오일러와 RK4미적분 101 13단계의 복소수MuJoCo의 시간 간격과 접촉로봇 발의 착지
먼저, 수식 없이

로봇 발이 딱딱한 바닥에 닿는 순간을 시뮬레이션한다고 해 봅시다. 바닥을 아주 단단한 용수철로 모델링하면 발은 1초에 수백 번 떨 만큼 빨리 반응하는데, 우리가 보고 싶은 로봇의 걸음은 1초에 한두 번이에요. 빠른 것과 느린 것이 섞인 이런 시스템을 경직(stiff)하다고 합니다.

오일러 같은 명시적 방법은 가장 빠른 떨림에 맞춰 Δt를 아주 작게 잡지 않으면 터집니다(미적분 101 12단계의 kΔt > 2). 떨림이 금방 사라져서 보이지도 않는데, 그 떨림 때문에 걸음 하나를 계산하는 데 수만 칸이 필요해져요.

암시적 방법은 ‘다음 칸의 상태로 계산한 변화율’을 씁니다. 다음 상태를 모르니 작은 연립방정식을 매 칸 풀어야 하지만, 대신 Δt를 아무리 크게 잡아도 터지지 않아요. 빠른 떨림은 정확히 따라가지 못하고 뭉개지지만, 어차피 보고 싶지 않았던 거라 괜찮습니다. MuJoCo가 접촉과 감쇠를 암시적으로 처리하는 것도 이 때문이에요.

한 줄로빠른 것과 느린 것이 섞인 경직 시스템에서 명시적 방법은 가장 빠른 떨림 때문에 아주 작은 Δt가 필요합니다. 암시적 방법은 매 칸 연립방정식을 풀지만 큰 Δt에서도 안정해요.

경직(stiff)
아주 빠른 성분과 느린 성분이 함께 있는 시스템.
명시적 방법
지금 상태의 변화율로 다음 상태를 바로 계산.
암시적 방법
다음 상태의 변화율을 써서, 다음 상태를 방정식으로 풀기.
안정 영역
그 방법이 터지지 않는 λΔt의 복소평면 영역.

까먹었다면미적분 101 12단계: ẋ = −kx를 오일러로 풀면 매 칸 (1 − kΔt)배. kΔt > 2면 발산했어요. 13단계: 복소수 z를 곱하면 길이 |z|배가 됩니다.

조금 더 정확하게

경직성은 시험 방정식 ẋ = λx로 봅니다(λ는 복소수일 수 있어요. 떨림은 허수부, 감쇠는 음의 실수부). 어떤 방법이든 한 칸에 x를 R(z)배 하고(z = λΔt), |R(z)| ≤ 1이어야 터지지 않습니다. 명시적 오일러는 R = 1 + z라 안정 영역이 −1을 중심으로 한 반지름 1인 원이고, RK4도 그보다 조금 클 뿐 유한해요. 그래서 |λ|가 크면 Δt를 |λ|에 반비례하게 줄여야 합니다.

암시적 오일러는 xk+1 = xk + Δt·λxk+1이라 R = 1/(1 − z)이고, 왼쪽 반평면 전체(감쇠하는 모든 시스템)에서 |R| < 1입니다(A-안정). 대가는 두 가지예요. 매 칸 (I − ΔtA)sk+1 = sk를 풀어야 하고(비선형이면 4단계의 뉴턴법으로), 빠른 떨림을 실제보다 세게 감쇠시켜 에너지를 잃습니다. 2차 정확도가 필요하면 사다리꼴(크랭크-니콜슨)이나 BDF 방법을 써요.

로봇 시뮬레이터는 이 균형 위에서 설계됩니다. MuJoCo는 기본적으로 Δt = 2 ms에 반암시적 오일러를 쓰되 접촉을 ‘부드러운 제약’으로 풀고, 감쇠가 큰 관절은 암시적 적분기 옵션으로 안정시켜요. 접촉 강성을 무작정 키우거나 Δt를 키우면 터지는 이유, 그리고 시뮬레이션이 ‘물렁한 바닥’처럼 보이는 이유가 모두 여기 있습니다.

안정 영역과 암시적 오일러
(9)
  1. 1시험 방정식. 한 칸마다 R(z)배. z = λΔt가 어디 있느냐가 전부예요.
  2. 2명시적 오일러. |1 + z| ≤ 1인 작은 원 안에서만 안정. 빠른 λ면 Δt가 아주 작아야 해요.
  3. 3암시적 오일러. 감쇠하는 모든 z에서 안정. Δt를 키워도 터지지 않아요.
  4. 4암시적 한 칸. 다음 상태를 연립방정식으로 풉니다. 선형이면 5단계의 solve 한 번.
파이썬
import numpy as np

k, c, dt = 1e4, 20.0, 0.005               # 딱딱한 접촉 용수철, 감쇠, 5 ms
A = np.array([[0, 1], [-k, -c]])          # s = [x, v],  ds/dt = A s
s_exp = s_imp = np.array([0.0, -1.0])     # 발이 1 m/s로 바닥에 닿음

M = np.eye(2) - dt * A                    # 암시적 오일러의 행렬 (한 번만)
for n in range(1000):                     # 5초
    s_exp = s_exp + dt * (A @ s_exp)      # 명시적: 터진다
    s_imp = np.linalg.solve(M, s_imp)     # 암시적: (I - dt A) s1 = s0
print(s_exp, s_imp)                       # [2e+28 ...]  vs  [~0, ~0]

lam = np.linalg.eigvals(A)                # 빠른 떨림: |λ| = 100
print(np.abs(1 + lam * dt))               # > 1 → 명시적 오일러는 발산
print(np.abs(1 / (1 - lam * dt)))         # < 1 → 암시적은 안정

길게 늘어진 타원 궤도를 도는 위성은 행성 근처를 지날 때 아주 빠르고, 멀리 있을 때는 아주 느립니다. 고정된 Δt로 시뮬레이션하면 빠른 곳에 맞춰 작게 잡아야 하는데, 그러면 느린 곳에서 계산을 낭비해요. 반대로 크게 잡으면 빠른 곳에서 궤도가 틀어집니다.

적응 시간 간격은 매 칸 ‘이번 칸의 오차가 얼마쯤일까’를 어림해서 간격을 고칩니다. 같은 칸을 정확도가 다른 두 공식으로 계산해 차이를 보면 오차를 거의 공짜로 잴 수 있어요. 오차가 허용치보다 크면 그 칸을 버리고 줄여서 다시, 작으면 받고 다음 칸은 늘립니다. 최적화 101의 LM이 걸음을 받고 버리던 것과 같은 생각이에요.

시뮬레이션에는 ‘정확히 그 순간’이 중요한 사건도 있습니다. 공이 바닥에 닿는 순간, 로봇 발이 착지하는 순간이요. 고정 간격으로는 이미 바닥을 뚫고 들어간 칸에서야 알아차리니, 칸 안에서 g(t) = 높이 = 0인 시각을 4단계의 근 찾기로 찾아 그 순간에 맞춰 멈추고 튕깁니다(사건 찾기).

한 줄로적응 간격은 두 공식의 차이로 오차를 재며 간격을 늘리고 줄입니다. 접촉 같은 사건은 칸 안에서 근 찾기로 정확한 순간을 찾아요.

사건 함수 g(t, y)는 보통 높이나 두 물체 사이 거리처럼 부호가 바뀌는 값입니다. 칸의 시작과 끝에서 부호가 다르면 그 사이에 사건이 있으니, 칸 안을 보간(7단계)한 값에 4단계의 근 찾기를 써서 사건 시각 t*를 찾고, 거기까지만 적분한 뒤 상태를 바꿔(속도를 뒤집고 반발 계수를 곱해) 다시 시작해요. 고정 간격으로 ‘뚫고 들어간 뒤 밀어내기’를 하면 튀는 높이가 칸 크기에 따라 들쑥날쑥해집니다.

  2. 2간격 고치기. 3차 방법이라 오차 ∝ h³. 허용치에 맞는 h를 거꾸로 계산하고 0.9배로 아껴요.

import numpy as np
from scipy.integrate import solve_ivp

def kepler(t, s):                              # 행성 둘레의 위성
    x, y, vx, vy = s
    r3 = (x*x + y*y) ** 1.5
    return [vx, vy, -x / r3, -y / r3]

e = 0.8                                        # 이심률 0.8의 길쭉한 궤도
s0 = [1 - e, 0, 0, np.sqrt((1 + e) / (1 - e))]
sol = solve_ivp(kepler, [0, 2*np.pi], s0, method='RK45', rtol=1e-6, atol=1e-9)
dt = np.diff(sol.t)
print(len(sol.t), dt.min(), dt.max())          # 근지점에서 작게, 원지점에서 크게

def fall(t, s): return [s[1], -9.81]           # 튀는 공
def hit_ground(t, s): return s[0]              # 높이 = 0 이 사건
hit_ground.terminal, hit_ground.direction = True, -1
t, s, bounces = 0.0, [1.0, 0.0], []
for k in range(5):
    r = solve_ivp(fall, [t, t + 5], s, events=hit_ground, max_step=0.1)
    t = r.t_events[0][0]; v = r.y_events[0][0][1]
    s = [0.0, -0.8 * v]; bounces.append(t)     # 정확한 순간에 튕김
print(np.round(bounces, 4))                    # 0.4515, 1.174, 1.7519, ...

오래 돌려도 궤도가 무너지지 않게: 심플렉틱 적분

쓰인 곳미적분 101 12단계의 반암시적 오일러10단계의 궤도궤도 위성 군집의 장기 전파MuJoCo·분자 동역학의 기본 적분기
먼저, 수식 없이

위성 궤도를 몇 년치 시뮬레이션한다고 해 봅시다. RK4는 한 바퀴만 보면 아주 정확하지만, 한 바퀴마다 아주 조금씩 에너지를 잃어요. 그 작은 손실이 천 바퀴 쌓이면 궤도가 안쪽으로 감겨 위성이 행성에 떨어집니다. 실제로는 일어나지 않는 일이죠.

심플렉틱 적분은 다른 약속을 합니다. 한 걸음의 정확도는 RK4보다 낮지만, 에너지 오차가 쌓이지 않고 일정한 폭 안에서 오르내려요. 궤도는 조금 돌아가며 흔들리지만(세차) 무너지지 않습니다. 오래 돌릴수록 이 차이가 결정적이에요.

가장 많이 쓰는 것이 속도 베를레입니다. 속도를 반 칸 고치고, 위치를 한 칸 옮기고, 새 위치의 힘으로 속도를 나머지 반 칸 고쳐요. 미적분 101의 반암시적 오일러를 대칭으로 다듬은 것이고, 물리 엔진과 분자 동역학 시뮬레이터의 기본값입니다.

한 줄로RK4는 짧게는 정확하지만 에너지 오차가 한쪽으로 쌓입니다. 속도 베를레 같은 심플렉틱 적분은 오차가 쌓이지 않고 묶여 있어서 오래 돌리는 시뮬레이션에 맞아요.

조금 더 정확하게

보존계(마찰 없는 궤도, 진자)의 시간 흐름은 위치-속도 공간의 넓이를 보존하는 특별한 변환입니다. 심플렉틱 적분기는 한 걸음 한 걸음이 이 성질을 정확히 지켜서, 수치해가 ‘조금 다른 에너지를 정확히 보존하는’ 근처 시스템의 정확한 해가 돼요. 그래서 에너지 오차가 Δt²에 비례하는 폭 안에서 오르내릴 뿐 쌓이지 않습니다.

RK4는 4차라서 한 바퀴의 오차는 아주 작지만 심플렉틱이 아니라서, 오차의 방향이 매 바퀴 같은 쪽입니다. 오차가 바퀴 수에 비례해 자라므로 충분히 오래 돌리면 베를레를 역전당해요. 실습에서 한 바퀴 60칸, 1000바퀴면 RK4는 에너지의 절반 가까이를 잃고 베를레는 몇 % 안에 머뭅니다. 계산량도 RK4가 칸마다 힘을 네 번, 베를레는 한 번 계산해요.

대신 심플렉틱 적분기는 고정 간격일 때만 이 성질을 가집니다. 10단계의 적응 간격과 섞으면 보존 성질이 깨져서, 긴 궤도 전파는 보통 고정 간격의 심플렉틱 방법이나 아주 작은 허용 오차의 고차 방법 중에서 목적에 맞게 고릅니다.

속도 베를레
(11)
  1. 1속도 반 칸. 지금 위치의 가속도로 속도를 Δt/2만큼 고쳐요.
  2. 2위치 한 칸, 속도 반 칸. 반 칸 속도로 위치를 옮기고, 새 위치의 가속도로 속도를 마저 고칩니다. 힘 계산은 칸마다 한 번이에요.
파이썬
import numpy as np

def acc(p):  r = np.linalg.norm(p); return -p / r**3        # 행성 둘레의 중력

def energy(p, v):  return 0.5 * v @ v - 1 / np.linalg.norm(p)

e = 0.5
p, v = np.array([1 - e, 0.0]), np.array([0.0, np.sqrt((1 + e) / (1 - e))])
h, E0 = 2 * np.pi / 60, energy(p, v)                       # 한 바퀴 60칸
for k in range(60 * 1000):                                 # 1000바퀴
    v = v + h / 2 * acc(p)                                 # 속도 반 칸
    p = p + h * v                                          # 위치 한 칸
    v = v + h / 2 * acc(p)                                 # 속도 반 칸
print((energy(p, v) - E0) / abs(E0))                       # 몇 % 안에서 오르내림
# 같은 조건의 RK4는 에너지를 약 46% 잃고 궤도가 안쪽으로 감긴다

무작위가 섞인 미분방정식: 오일러-마루야마

쓰인 곳확률과 통계 101 25단계의 OU 과정드론·로켓 시뮬레이션의 돌풍칼만 필터의 공정 잡음시뮬레이션 101 1단계의 확률적 모형
먼저, 수식 없이

돌풍 속 드론의 속도는 ‘공기 저항으로 줄어드는 규칙’과 ‘매 순간 무작위로 밀리는 힘’이 함께 정합니다. 이렇게 미분방정식에 무작위가 섞인 것을 확률 미분방정식이라고 해요. 확률과 통계 101의 OU 과정이 그 예입니다.

푸는 법은 오일러 방법에 잡음 한 줄을 더한 오일러-마루야마예요. 단 하나 꼭 지켜야 할 것이 있습니다. 잡음 항에는 Δt가 아니라 √Δt를 곱해야 해요. 짧은 시간 Δt 동안 무작위로 밀린 양의 퍼짐은 Δt가 아니라 √Δt에 비례하기 때문입니다(무작위 걸음은 √로 퍼져요).

√Δt 대신 Δt를 곱하면 코드는 멀쩡히 돌지만, Δt를 줄일수록 잡음이 사라져 결과가 시간 간격에 따라 달라집니다. 시뮬레이션의 결과가 Δt를 바꿨더니 달라진다면 가장 먼저 의심할 버그예요.

한 줄로확률 미분방정식은 오일러-마루야마로 풉니다. 잡음 항에는 반드시 √Δt를 곱해야 결과가 시간 간격과 무관해져요.

확률 미분방정식
변화율에 무작위 항 b·dW가 섞인 식.
위너 과정 W
퍼짐이 √t로 자라는 연속 무작위 걸음.
오일러-마루야마
오일러 걸음 + b·√Δt·ξ.
강한·약한 수렴
경로 하나가 맞는가, 분포(평균·분산)가 맞는가.

까먹었다면확률과 통계 101 25단계: OU 과정 x ← x − (x/τ)Δt + σ√Δt·ξ. 정상 상태의 표준편차는 σ√(τ/2)였어요.

조금 더 정확하게

dX = a(X)dt + b(X)dW에서 dW는 평균 0, 분산 dt인 무작위 증분입니다. 그래서 한 칸의 증분은 √Δt·ξ(ξ는 표준정규)로 만들어요. 오일러-마루야마 Xk+1 = Xk + aΔt + b√Δt·ξk는 경로가 Δt1/2의 차수로(강한 수렴), 평균과 분산 같은 통계가 Δt의 차수로(약한 수렴) 맞아 들어갑니다. 시뮬레이션의 목적이 보통 통계라서 약한 수렴이 중요해요.

선형인 OU 과정은 정확한 한 칸 공식도 있습니다. Xk+1 = e−Δt/τXk + σ√(τ(1 − e−2Δt/τ)/2)·ξ. 이걸 쓰면 Δt가 커도 통계가 정확해서, 바람 같은 색잡음 입력을 만들 때 자주 씁니다. 오일러-마루야마는 Δt가 τ에 비해 작아야 정확해요.

잡음이 상태에 따라 세기가 달라지는 경우(b가 X의 함수)에는 해석 방식(이토, 스트라토노비치)에 따라 같은 식이 다른 뜻이 되는 미묘함이 있습니다. 로봇 시뮬레이션의 잡음 입력은 대부분 b가 상수인 덧셈 잡음이라 이 문제를 피할 수 있어요.

오일러-마루야마
(12)
  1. 1확률 미분방정식. 끌림 a와 잡음 세기 b. dW는 분산이 dt인 무작위 증분이에요.
  2. 2오일러-마루야마. 오일러 걸음에 b·√Δt·ξ를 더해요. √Δt가 핵심입니다.
파이썬
import numpy as np
rng = np.random.default_rng(0)

tau, sigma, T = 5.0, 0.5, 50.0                 # 돌풍 속 속도: dv = -(v/tau) dt + sigma dW
def final_var(dt, bug=False, n_paths=2000):
    v = np.zeros(n_paths)
    for _ in range(int(T / dt)):
        step = dt if bug else np.sqrt(dt)       # 버그: sqrt를 빠뜨림
        v = v - v / tau * dt + sigma * step * rng.normal(size=n_paths)
    return v.var()

print(sigma**2 * tau / 2)                       # 이론 정상 분산 0.625
for dt in [0.5, 0.1, 0.01]:
    print(dt, final_var(dt), final_var(dt, bug=True))
# 올바른 식: dt와 거의 무관하게 0.6 근처
# 버그:      dt를 줄일수록 분산이 0으로 사라짐

  • [√Δt를 빠뜨리면]에서 같은 Δt 조절을 해 보세요. Δt를 줄일수록 경로가 평평해지고 분산이 0으로 줄어듭니다. 같은 모형인데 시간 간격이 결과를 바꿔요. 가장 흔한 확률 시뮬레이션 버그입니다.

핵심

무작위가 섞인 미분방정식은 오일러-마루야마로 풀고, 잡음 항에 반드시 √Δt를 곱합니다. 결과가 Δt에 따라 달라지면 이 버그부터 의심하고, 선형 잡음은 정확한 한 칸 공식을 쓰세요.

막대 길이가 늘어나는 진자: 구속과 드리프트 보정

쓰인 곳선형대수 101의 로봇팔 관절MuJoCo의 구속 풀이다물체·폐루프 기구양팔 로봇이 함께 드는 물체
먼저, 수식 없이

진자를 각도 하나로 쓰면 막대 길이는 저절로 지켜집니다. 그런데 로봇팔 두 개가 상자 하나를 함께 들거나 바퀴가 바닥에서 떨어지지 않아야 하는 경우처럼, 좌표 여러 개에 ‘이 관계를 지켜라’는 구속을 거는 일이 시뮬레이터에서는 흔합니다. 진자라면 끝점 (x, y)를 따로 적분하면서 x² + y² = L²을 지키게 하는 거예요.

구속을 지키는 힘(막대의 장력)을 계산해 넣으면 이론상으로는 길이가 유지됩니다. 그런데 수치 적분의 작은 오차 때문에 길이가 조금씩 늘어나요(드리프트). 오래 돌리면 진자의 막대가 고무줄처럼 늘어난 시뮬레이션이 됩니다.

처방은 둘입니다. 매 칸 끝점을 원 위로 다시 끌어다 놓는 사영(9단계의 clip과 같은 생각), 그리고 길이 오차가 생기면 스프링과 댐퍼처럼 되돌리는 힘을 더하는 바움가르테 안정화예요. MuJoCo가 구속을 ‘부드러운 구속’으로 푸는 것도 후자와 닮은 생각입니다.

한 줄로좌표를 따로 적분하며 구속을 걸면 수치 오차로 구속이 조금씩 깨집니다(드리프트). 매 칸 되돌려 놓는 사영이나, 오차를 되돌리는 힘을 더하는 바움가르테 안정화로 막아요.

구속
좌표들이 지켜야 하는 관계. c(x) = 0.
라그랑주 승수 λ
구속을 지키는 힘의 크기(최적화 101 6단계와 같은 λ).
드리프트
적분 오차로 구속이 점점 깨지는 것.
바움가르테 안정화
c̈ + 2αċ + β²c = 0이 되게 힘을 고쳐 오차를 되돌림.

까먹었다면최적화 101 6단계: 구속 g(x) = 0 위에서는 구속의 그래디언트 방향으로 힘(λ∇g)이 작용해요. 진자에서 그 힘이 막대의 장력입니다.

조금 더 정확하게

구속 c = x² + y² − L² = 0을 두 번 미분해 c̈ = 0이 되도록 장력 λ를 고르면 λ = (‖v‖² − gy)/(x² + y²)입니다. 이 식은 ‘가속도 수준’에서만 구속을 지켜서, 위치와 속도 수준의 작은 오차는 되돌릴 힘이 없어요. 적분 오차가 c와 ċ에 쌓이면 c가 시간에 따라 자랍니다. 이런 미분대수방정식(DAE)의 전형적인 문제예요.

사영은 매 칸 위치를 원 위로, 속도를 원의 접선 방향으로 되돌립니다. 간단하고 정확하지만 구속이 많고 얽혀 있으면 되돌리는 것 자체가 연립방정식이 돼요. 바움가르테 안정화는 c̈ = 0 대신 c̈ + 2αċ + β²c = 0을 쓰도록 λ를 고쳐, 구속 오차가 감쇠 진동처럼 0으로 돌아가게 합니다. α, β가 너무 크면 이 ‘되돌리는 용수철’이 9단계의 경직성을 만들어 Δt를 줄여야 해요.

좌표를 처음부터 구속을 저절로 지키는 것(진자의 각도, 로봇팔의 관절 각)으로 고르면 이 문제가 아예 없습니다. 그래서 로봇팔은 관절 좌표로 시뮬레이션하고, 닫힌 고리(두 팔이 함께 잡은 물체, 바퀴와 지면)에만 구속을 겁니다.

구속이 있는 운동과 바움가르테 안정화
(13)
  1. 1구속. 끝점이 반지름 L인 원 위에 있어야 해요.
  2. 2장력. 구속의 두 번째 미분이 0이 되게 고른 λ. 위치·속도 오차는 되돌리지 못해요.
  3. 3바움가르테. 오차 c와 그 변화율 ċ를 감쇠 진동처럼 0으로 되돌리도록 λ를 고칩니다.
파이썬
import numpy as np

L, g, dt = 1.0, 9.81, 0.002
def step(x, y, vx, vy, mode, a=5.0, b=5.0):
    r2, v2 = x*x + y*y, vx*vx + vy*vy
    c, cd = r2 - L*L, 2 * (x*vx + y*vy)
    lam = (v2 - g*y) / r2                                   # c'' = 0이 되는 장력
    if mode == 'baumgarte':
        lam = (2*v2 - 2*g*y + 2*a*cd + b*b*c) / (2*r2)      # c'' + 2a c' + b^2 c = 0
    vx += dt * (-lam * x); vy += dt * (-lam * y - g)
    x += dt * vx;          y += dt * vy
    if mode == 'project':                                   # 원 위로 되돌리기
        r = np.hypot(x, y); x, y = x * L / r, y * L / r
        rad = (x*vx + y*vy) / (L*L); vx, vy = vx - rad*x, vy - rad*y
    return x, y, vx, vy

for mode in ['naive', 'project', 'baumgarte']:
    s = (L*np.sin(1.0), -L*np.cos(1.0), 0.0, 0.0)
    for _ in range(10_000): s = step(*s, mode)              # 20초
    print(mode, np.hypot(s[0], s[1]) - L)                   # 길이 오차: 0.08 / 0 / -0.002

  • Δt를 줄이면 그냥 적분의 드리프트도 줄지만 사라지지는 않습니다. 오래 돌릴수록 결국 쌓여요. 구속은 줄이는 것이 아니라 되돌려야 합니다.

좌표를 따로 적분하며 구속을 걸면 적분 오차로 구속이 점점 깨집니다. 매 칸 되돌리는 사영이나 오차를 감쇠시키는 바움가르테 안정화로 막고, 가능하면 구속을 저절로 지키는 좌표를 고르세요.

열이 퍼지는 속도와 시간 칸: 열 방정식과 CFL 조건

쓰인 곳위성·데이터센터의 열 관리6단계의 이웃 평균(라플라스)9단계의 경직성점유 격자의 확산
먼저, 수식 없이

위성 패널의 한쪽은 햇빛을 받고 다른 쪽은 방열판으로 열을 버립니다. 패널 안의 온도가 시간에 따라 어떻게 바뀌는지는 열 방정식이 정해요. ‘이웃보다 차가운 곳은 데워지고 더운 곳은 식는다’는 규칙입니다. 6단계에서 이웃의 평균을 맞추던 라플라스 방정식이 바로 이 열 방정식의 ‘다 퍼진 뒤’ 모습이에요.

패널을 칸으로 나누고 시간을 Δt씩 넘기면, 칸마다 ‘이웃과의 온도 차 × 비율’만큼 바꾸면 됩니다. 그런데 Δt를 욕심내 크게 잡으면 한 칸이 이웃보다 더 크게 바뀌어 넘쳐 버리고, 온도가 칸마다 들쭉날쭉 터집니다.

그 한계가 CFL 조건이에요. 열 방정식이라면 r = αΔt/Δx²가 1/2을 넘으면 안 됩니다. 칸을 반으로 잘게 나누면 Δt는 4분의 1로 줄여야 하죠. 공간을 촘촘히 할수록 시간 칸이 훨씬 빨리 작아지는, 9단계의 경직성과 같은 현상입니다. 암시적 방법은 이 한계가 없어요.

한 줄로열 방정식을 칸으로 나눠 명시적으로 풀면 r = αΔt/Δx² ≤ 1/2이어야 안정합니다(CFL 조건). 격자를 촘촘히 하면 Δt가 제곱으로 줄고, 암시적 방법은 이 한계가 없어요.

열 방정식
온도 변화율 = α × 온도 곡률. 열이 퍼지는 규칙.
열 확산율 α
재료가 열을 얼마나 빨리 퍼뜨리나.
CFL 조건
시간 칸이 공간 칸에 비해 너무 크면 안 된다는 안정 조건.
FTCS, BTCS
명시적(앞으로) 방법과 암시적(뒤로) 방법.

까먹었다면6단계: 칸의 값 = 이웃 넷의 평균(라플라스). 9단계: 빠른 성분이 있으면 명시적 방법은 Δt가 그 빠르기에 묶였어요.

조금 더 정확하게

∂T/∂t = α∂²T/∂x²에서 공간 2차 미분을 (Ti−1 − 2Ti + Ti+1)/Δx²로 바꾸면 칸마다 상미분방정식이 하나씩 생기고, 이를 오일러로 넘기면 Ti ← Ti + r(Ti−1 − 2Ti + Ti+1)입니다(FTCS). r ≤ 1/2이면 새 값이 이웃들의 가중 평균이라 넘칠 수 없고, 1/2을 넘으면 가장 들쭉날쭉한 패턴(칸마다 부호가 바뀌는)이 매 칸 커져서 터져요.

이 조건은 공간 격자 위 상미분방정식계의 가장 빠른 고유값이 −4α/Δx²이기 때문에 나옵니다. 9단계의 안정 영역 그대로예요. 그래서 칸을 반으로 줄이면 Δt를 4분의 1로 줄여야 하고, 2차원·3차원으로 가면 계산이 폭발합니다. 암시적 방법(BTCS)은 매 칸 삼중 대각 연립방정식(5단계의 LU가 n번으로 끝나는 모양)을 풀지만 어떤 Δt에서도 안정해요.

같은 이름의 조건이 다른 방정식에도 있습니다. 파동이나 흐름을 실어 나르는 방정식에서는 ‘한 시간 칸에 정보가 한 공간 칸보다 멀리 가면 안 된다’(cΔt/Δx ≤ 1)가 CFL 조건이에요. 격자 위의 확산·흐름 시뮬레이션에서 Δt를 고를 때 늘 먼저 확인하는 수입니다.

열 방정식과 CFL 조건
(14)
  1. 1열 방정식. 온도가 위로 볼록한 곳(이웃보다 더운 곳)은 식고, 아래로 볼록한 곳은 데워져요.
  2. 2명시적 한 칸과 CFL 조건. r이 1/2을 넘으면 새 값이 이웃 범위를 넘어 터집니다.
파이썬
import numpy as np

N, alpha, L = 40, 1e-4, 0.4                 # 칸 40개, 확산율 (m^2/s), 패널 길이 (m)
dx = L / N
for r in [0.4, 0.5, 0.55]:
    dt = r * dx**2 / alpha                  # r = alpha dt / dx^2
    T = np.zeros(N + 1); T[0] = 1.0         # 왼쪽 끝은 햇빛(1), 오른쪽 끝은 방열판(0)
    for _ in range(400):
        T[1:-1] = T[1:-1] + r * (T[:-2] - 2*T[1:-1] + T[2:])
    print(r, dt, np.abs(T).max())           # 0.55에서 1e+28로 터짐

# 암시적 방법: (I - r A) T_new = T_old  (삼중 대각, 어떤 r에서도 안정)
from scipy.linalg import solve_banded
r = 3.0
ab = np.zeros((3, N + 1)); ab[0, 2:] = -r; ab[1, :] = 1 + 2*r; ab[2, :-2] = -r
ab[1, 0] = ab[1, -1] = 1; ab[0, 1] = ab[2, -2] = 0
T = np.zeros(N + 1); T[0] = 1.0
for _ in range(50):
    rhs = T.copy(); rhs[0], rhs[-1] = 1.0, 0.0
    T = solve_banded((1, 1), ab, rhs)

  • r을 0.52로 올리는 순간 온도가 칸마다 위아래로 번갈아 튀다가 터집니다. 가장 들쭉날쭉한 패턴이 매 칸 커지는 거예요. [암시적]으로 바꾸면 r = 3에서도 멀쩡합니다.

맞게 풀었는지 확인하기: 수렴 차수와 제조된 해

쓰인 곳시뮬레이션 101 9단계의 검증미적분 101 12단계의 RK4모든 적분기 코드의 테스트물리 엔진 개발
먼저, 수식 없이

적분기 코드를 짰는데 결과가 그럴듯합니다. 정말 맞을까요? 시뮬레이션 101의 ‘검증’을 수치해석 쪽에서 하는 강력한 방법이 있어요. 시간 칸 Δt를 반으로 줄일 때마다 오차가 얼마나 줄어드는지 보는 것입니다.

오일러는 오차가 Δt에 비례해서 반으로 줄이면 오차도 반, RK4는 Δt⁴에 비례해서 16분의 1이 되어야 해요. 로그-로그 그래프에서 오차가 기울기 1, 4인 직선이 됩니다. 이 기울기를 수렴 차수라고 하고, RK4라고 짰는데 기울기가 2로 나오면 어딘가에 계수가 틀린 버그가 있다는 뜻이에요.

오차를 재려면 정확한 답이 필요한데, 진짜 문제에는 보통 정확한 답이 없습니다. 그래서 거꾸로 답을 먼저 정합니다. ‘답이 sin 2t + t²/2이 되게 하려면 식에 무엇을 더해야 하나’를 계산해 넣은 문제를 만드는 거예요. 이것이 제조된 해(MMS)입니다.

한 줄로Δt를 반씩 줄이며 오차가 줄어드는 기울기(수렴 차수)가 이론과 맞는지 보면 적분기 버그를 잡을 수 있습니다. 정확한 답은 제조된 해로 만들어요.

수렴 차수 p
Δt를 반으로 줄이면 오차가 2p분의 1.
로그-로그 기울기
두 축을 로그로 그렸을 때 직선의 기울기 = p.
제조된 해(MMS)
답을 먼저 정하고 그 답이 나오도록 식에 원천 항을 더한 문제.
원천 항
식에 더해 넣는 시간의 함수.

까먹었다면미적분 101 12단계: RK4는 Δt를 절반으로 하면 오차가 16분의 1이었어요. 5단계: 중심 차분의 오차는 h², 앞쪽 차분은 h에 비례했습니다.

조금 더 정확하게

차수 p인 방법의 전체 오차는 e(Δt) ≈ CΔtp이므로, Δt와 Δt/2의 오차 비율의 log₂가 p입니다. Δt를 네다섯 번 반씩 줄여 기울기를 확인하는 것을 수렴 차수 시험이라고 해요. 너무 큰 Δt에서는 아직 점근 영역이 아니라 기울기가 덜 맞고, 너무 작은 Δt에서는 1단계의 반올림 오차가 바닥을 만들어요. 가운데 구간의 기울기를 봅니다.

제조된 해는 원하는 답 y*(t)를 먼저 정하고, 원래 식 ẏ = g(t, y)에 원천 항 s(t) = ẏ*(t) − g(t, y*(t))를 더해 ẏ = g + s를 만드는 기법입니다. 그러면 y*가 정확한 답이 되고, 같은 코드로 오차를 정확히 잴 수 있어요. 편미분방정식 시뮬레이터, 물리 엔진의 검증에서 표준적으로 씁니다.

이 실습의 ‘버그 있는 RK4’는 기울기 하나의 무게를 2 대신 3으로 잘못 적고 전체를 맞춰 나눈 코드예요. 결과는 그럴듯하고 오차도 작아 보이지만, 차수가 4가 아니라 2로 나옵니다. 차수 시험이 아니면 찾기 어려운 버그예요.

수렴 차수와 제조된 해
(15)
  1. 1관측 차수. 간격을 반으로 줄일 때의 오차 비율. 오일러 1, 호인 2, RK4 4가 나와야 해요.
  2. 2제조된 해. 원하는 답 y*가 정확한 답이 되도록 원천 항을 더합니다.
파이썬
import numpy as np

ystar  = lambda t: np.sin(2*t) + 0.5*t**2          # 답을 먼저 정한다
dystar = lambda t: 2*np.cos(2*t) + t
f = lambda t, y: -2*y + (dystar(t) + 2*ystar(t))  # g = -2y 에 원천 항을 더함

def rk4(h, T=2.0, bug=False):
    t, y = 0.0, ystar(0.0)
    for _ in range(int(round(T / h))):
        k1 = f(t, y); k2 = f(t + h/2, y + h/2*k1); k3 = f(t + h/2, y + h/2*k2); k4 = f(t + h, y + h*k3)
        y += h/6 * (k1 + 2*k2 + (3 if bug else 2)*k3 + k4) * (6/7 if bug else 1)
        t += h
    return abs(y - ystar(T))

hs = [0.1, 0.05, 0.025, 0.0125]
for bug in [False, True]:
    e = [rk4(h, bug=bug) for h in hs]
    print(np.log2(np.array(e[:-1]) / np.array(e[1:])))   # [4, 4, 4] / [2, 2, 2]
