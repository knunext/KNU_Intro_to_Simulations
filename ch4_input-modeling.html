모델링과 시뮬레이션 목차

모델링과 시뮬레이션, 4편

4입력 모델링

시뮬레이션의 결과는 입력만큼만 믿을 수 있습니다. 실제로 잰 데이터를 보고 시뮬레이션에 넣을 분포를 고르고, 모수를 정하고, 잘 맞는지 확인하는 방법을 배웁니다. 마지막에는 여러분이 직접 잰 데이터를 넣어 분석해 봅니다.

이 편을 마치면

  • 데이터의 모양과 요약통계를 보고 후보 분포를 고를 수 있습니다.
  • 적률법과 최대우도법으로 분포의 모수를 추정할 수 있습니다.
  • Q-Q 그림, K-S 검정, 카이제곱 검정으로 적합도를 판단할 수 있습니다.
  • 데이터가 없을 때와 도착률이 시간에 따라 변할 때의 대처법을 압니다.

1왜 입력인가

모델 구조가 완벽해도 입력 분포가 틀리면 결과는 틀립니다. 그런데 입력의 틀림은 결과만 봐서는 잘 드러나지 않습니다.

1.1같은 평균, 다른 결과

0편 2.4절에서 바리스타의 평균 제조 시간이 똑같이 3분이어도, 시간이 들쭉날쭉하면 손님의 평균 대기가 두 배가 되는 것을 보았습니다. 이 현상을 한 줄로 정리한 공식이 있습니다. 손님이 무작위로 오고 직원이 한 명인 대기열(M/G/1)의 평균 대기시간입니다.

평균(E[S])과 이용률(ρ)은 같아도 C를 0.5로 잡느냐 1.5로 잡느냐에 따라 예측 대기시간이 두 배 이상 달라집니다. “제조 시간 평균은 3분”이라는 정보만으로는 시뮬레이션을 돌릴 수 없는 이유입니다. 분포의 모양, 특히 퍼짐과 꼬리를 데이터에서 알아내야 합니다.

앞에서1편의 M/M/1은 이 공식에서 C = 1인 경우이고, 2편 커피점의 1단계 검증에 쓴 것도 이 공식입니다.

1.2흔한 실수 네 가지

평균만 넣기

“처리 시간 3분”을 상수로 넣으면 변동성이 0이 되어 대기를 크게 과소평가합니다. 위 공식에서 C = 0으로 둔 셈입니다.

무조건 정규분포

시간 데이터는 대부분 오른쪽 꼬리가 긴데, 정규분포는 대칭이고 음수도 냅니다. 평균 2분, 표준편차 1분인 정규분포는 약 2.3%의 확률로 음수 시간을 만듭니다.

섞인 데이터를 하나로

아메리카노와 라떼의 제조 시간을 한꺼번에 맞추면 어느 쪽도 아닌 분포가 나옵니다. 원인이 다른 데이터는 나눠서 모델링합니다.

시간에 따른 변화 무시

하루 평균 도착률을 상수로 쓰면 점심 피크의 혼잡을 놓칩니다. 같은 하루 평균이라도 몰리는 시간이 있으면 대기는 훨씬 깁니다.

2이론

데이터에서 분포까지 가는 길을 네 단계로 나누어 살펴봅니다.

2.1입력 모델링의 네 단계

  1. 데이터 모으기무엇을, 언제, 몇 개나 잴지 정합니다. 섞이면 안 되는 것(메뉴, 시간대)은 처음부터 따로 기록합니다.
  2. 데이터 살펴보기히스토그램과 요약통계로 모양을 봅니다. 값들이 서로 독립인지, 시간에 따라 변하지 않는지도 확인합니다.
  3. 분포 고르고 모수 추정하기모양에 맞는 후보 분포 가족을 고르고, 데이터에 맞게 모수(평균, 모양 등)를 정합니다.
  4. 적합도 확인하기고른 분포가 데이터와 잘 맞는지 그림과 검정으로 확인합니다. 맞지 않으면 3단계로 돌아갑니다.

2.2데이터 살펴보기

첫 도구는 히스토그램입니다. 하지만 칸(bin)을 몇 개로 나누느냐에 따라 같은 데이터가 전혀 다르게 보입니다. 아래는 커피점 제조 시간 120건입니다. 칸 수를 바꿔 보세요.

히스토그램 칸 수의 함정

칸이 너무 적으면 봉우리가 둘인 것이 가려지고, 너무 많으면 우연한 들쭉날쭉이 모양처럼 보입니다.

칸 수의 출발점으로는 스터지스 규칙 1 + log2n이나 √n을 씁니다. n = 120이면 각각 약 8과 11입니다. 규칙은 출발점일 뿐이니 몇 가지를 바꿔 보며 모양이 안정적인지 확인하세요. 이 데이터에서 봉우리가 둘로 보인다면 서로 다른 두 집단이 섞여 있다는 신호입니다. 3.2절에서 이 데이터를 다시 다룹니다.

요약통계도 분포 가족을 고르는 힌트가 됩니다.

보이는 특징의미떠올릴 후보
변동계수 C ≈ 1, 0 근처가 가장 많음무작위 사건 사이의 간격지수분포
C < 1, 봉우리가 0에서 떨어져 있음여러 단계를 거치는 작업 시간감마, 로그정규, 와이블
C > 1, 아주 큰 값이 가끔대부분 빠르지만 가끔 크게 지연로그정규, 두 지수분포의 혼합
평균 ≈ 중앙값, 좌우 대칭, 0에서 멀리많은 작은 요인의 합정규분포 (음수 확인 필수)
평균 > 중앙값오른쪽 꼬리가 김감마, 로그정규

독립성과 정상성도 확인하세요. 대부분의 분포 적합은 값들이 서로 독립이고 같은 분포에서 나왔다고 가정합니다. 연속된 두 값 (xi, xi+1)을 산점도로 찍어 패턴이 보이면 독립이 아닙니다. 예를 들어 줄이 길 때 바리스타가 서두른다면 제조 시간이 대기 길이에 따라 달라집니다. 값을 기록 순서대로 그려서 시간에 따라 평균이 움직이면 정상(stationary)이 아니므로, 2.7절처럼 시간대별로 나눠야 합니다.

2.3후보 분포 가족

0편의 다섯 분포에 시간 데이터에서 자주 쓰는 셋을 더합니다.

지수

모수 1개(평균). C = 1. 도착 간격, 고장 간격. 무기억성.

감마

모수 2개(모양 k, 척도 θ). C = 1/√k. k = 1이면 지수, k가 크면 종 모양. 지수 단계 k개를 연달아 거치는 시간.

로그정규

로그를 취하면 정규. 오른쪽 꼬리가 길고, 여러 요인이 곱해져 생기는 값(수리 시간, 파일 크기).

와이블

모양과 척도 2개. 수명과 고장 시간에 표준처럼 쓰임. 모양 < 1이면 초기 고장, > 1이면 노화 고장.

삼각, PERT

최솟값, 최빈값, 최댓값만으로 정함. 데이터가 없을 때 전문가 의견으로 (2.6절).

경험분포

모수 없이 데이터 자체에서 다시 뽑음. 모양 가정이 필요 없지만, 본 적 없는 값은 절대 만들지 못함.

2.4모수 추정

적률법: 평균과 퍼짐을 맞춘다

가장 직관적인 방법은 데이터의 평균과 표준편차가 분포의 평균과 표준편차와 같아지도록 모수를 정하는 것입니다. 이를 적률법(method of moments)이라고 합니다. 감마분포의 평균은 kθ, 분산은 kθ²이므로, 이 두 식을 데이터의 x̄, s²와 같다고 놓고 풀면 다음과 같습니다.

최대우도법: 이 데이터가 나올 가능성이 가장 큰 모수

더 널리 쓰이는 방법은 최대우도법(maximum likelihood, MLE)입니다. 생각은 이렇습니다. 모수를 하나 정하면 각 데이터 값이 나올 “그럴듯함”(확률밀도의 높이)이 정해집니다. 모든 데이터의 그럴듯함을 곱한 것을 우도라고 하고, 우도를 가장 크게 만드는 모수를 고릅니다. 아래에서 지수분포의 도착률 λ를 움직여 보세요. 막대 높이는 각 데이터 점에서의 밀도입니다.

λ를 바꾸면 우도가 어떻게 변할까

위: 데이터 12개(점)와 지수분포 밀도 곡선. 아래: λ에 따른 로그우도. 세로 점선이 데이터로 계산한 최적값입니다.

λ가 크면 0 근처의 밀도는 높지만 먼 데이터의 밀도가 아주 작아지고, λ가 작으면 곡선이 낮고 넓게 퍼져 모든 점의 밀도가 낮아집니다. 그 사이 어딘가에 균형점이 있습니다. 곱셈은 다루기 불편하므로 로그를 취해 덧셈으로 바꾼 로그우도를 최대화합니다.

어떤 방법을 쓸까? 지수분포와 정규분포에서는 두 방법의 답이 같습니다. 감마나 와이블에서는 다를 수 있고, 일반적으로 최대우도 쪽이 더 정확합니다. 다만 감마와 와이블의 최대우도 추정은 반복 계산이 필요해서, 보통 scipy.stats 같은 라이브러리에 맡깁니다. 이 페이지의 적합 도구는 계산을 단순하게 하려고 감마에는 적률법, 나머지에는 최대우도를 씁니다.

2.5적합도 확인

모수를 정했으면 그 분포가 데이터와 정말 맞는지 확인합니다. 세 가지 도구를 함께 씁니다. 아래 도구에서 후보 분포를 바꿔 가며 세 화면을 비교해 보세요. 데이터는 바리스타 한 명의 제조 시간 80건입니다.

적합 도구

후보 분포를 고르면 데이터에 맞춰 모수를 추정하고 세 가지 방법으로 비교합니다.

히스토그램 + 밀도
전체 모양을 한눈에 봅니다. 하지만 칸 수에 따라 인상이 바뀌고, 꼬리 부분의 차이는 잘 안 보입니다.
Q-Q 그림
데이터를 작은 순서로 늘어놓은 값(가로)과, 같은 순위에서 분포가 예상하는 값(세로)을 점으로 찍습니다. 잘 맞으면 점들이 대각선 위에 놓입니다. 꼬리에서 대각선을 벗어나는지 보기 좋아서 실무에서 가장 많이 씁니다.
누적분포 비교
데이터의 계단 모양 누적분포와 분포의 누적분포를 겹쳐 그리고, 둘의 가장 큰 세로 차이를 봅니다. 이것이 K-S 검정 통계량입니다.

검정 결과를 맹신하지 마세요. 데이터가 아주 많으면 실용적으로 무시해도 될 작은 차이에도 “맞지 않는다”가 나오고, 데이터가 적으면 엉뚱한 분포도 통과합니다. 실제로 판단할 때는 Q-Q 그림을 먼저 보고, 검정은 보조로 씁니다. 특히 시뮬레이션에서는 꼬리가 잘 맞는지가 중요합니다. 1.1절 공식에서 보듯 대기시간은 가끔 나오는 아주 긴 처리 시간에 민감하기 때문입니다.

2.6데이터가 없을 때

새로 열 매장이나 아직 없는 시스템은 잴 데이터가 없습니다. 이럴 때는 경험 있는 사람에게 “가장 빠르면, 보통은, 가장 늦으면 몇 분인가요?”를 묻고 세 숫자로 분포를 만듭니다. 사람은 평균이나 표준편차보다 이 세 숫자를 훨씬 잘 대답합니다.

삼각분포

최솟값 a, 최빈값 m, 최댓값 b를 꼭짓점으로 하는 삼각형. 평균은 (a + m + b) / 3. 단순하지만 꼬리가 뚝 끊깁니다.

PERT (베타) 분포

같은 세 숫자로 만든 부드러운 종 모양. 평균은 (a + 4m + b) / 6로 최빈값에 더 무게를 둡니다. 프로젝트 일정 추정에서 유래했습니다.

이렇게 정한 입력은 불확실성이 크다는 것을 기억해야 합니다. 8편의 민감도 분석으로 “이 입력이 조금 틀리면 결론이 바뀌는가”를 꼭 확인합니다.

2.7시간에 따라 변하는 도착

커피점 손님은 오전 수업 전과 점심에 몰리고 오후 늦게는 한산합니다. 도착률이 시간의 함수 λ(t)인 이런 과정을 비정상 포아송 과정(NHPP)이라고 합니다. 2편 7단계의 “하루 일정”이 이 모델입니다. 시뮬레이션에서는 솎아내기(thinning)라는 간단한 방법으로 만듭니다.

  1. 가장 바쁠 때의 도착률 λmax로 후보를 만든다λ(t)가 하루 중 가장 큰 값으로 일정하게 손님이 온다고 보고 후보 도착 시각을 뽑습니다.
  2. 후보마다 확률적으로 남길지 정한다시각 t의 후보는 λ(t)/λmax의 확률로 남기고, 나머지는 버립니다. 한가한 시간대의 후보일수록 많이 버려집니다.

하루치 도착 만들기

위: 도착률 λ(t)와 후보들(흐린 점: 버림, 진한 점: 남김). 아래: 남은 손님을 시간대별로 센 막대와 기대값.

import random

def rate(t):
    """시각 t(시, 8~18)의 도착률(명/시간). 오전과 점심에 봉우리가 있는 예시."""
    if 8.5 <= t < 9.5:
        return 60
    if 11.5 <= t < 13.0:
        return 90
    return 30

def nhpp_arrivals(start=8.0, end=18.0, lam_max=90):
    t, out = start, []
    while True:
        t += random.expovariate(lam_max)          # 1단계: 가장 바쁜 비율로 후보 생성
        if t >= end:
            return out
        if random.random() < rate(t) / lam_max:   # 2단계: λ(t)/λmax 확률로 남김
            out.append(t)

arrivals = nhpp_arrivals()
print(len(arrivals), "명")                          # 기대값: 30×10 + 30×1 + 60×1.5 = 420명 안팎

도착률 함수 rate만 바꾸면 어떤 하루 일정도 만들 수 있습니다. 위 위젯의 계산도 이와 같습니다.

3예제와 사례 연구

쉬운 예제에서 시작해, 마지막에는 여러분이 직접 잰 데이터로 끝납니다. 세 사례 모두 아래 적합 도구 하나로 진행합니다.

적합 도구 (사례 연구용)

데이터를 고르고, 후보 분포와 화면을 바꿔 가며 비교하세요. 표의 굵은 줄이 K-S 통계량이 가장 작은 분포입니다.

3.1도착 간격쉬움

오전 10시부터 약 5시간 동안 커피점에 손님이 도착한 시각을 기록해 120개의 간격을 얻었다고 합시다(가상 데이터). 위 도구에서 “3.1 도착 간격”을 고르고 다음을 확인해 보세요.

  1. 요약통계를 본다표의 평균과 표준편차가 비슷한가요? 변동계수가 1에 가까우면 지수분포를 먼저 떠올립니다.
  2. 지수분포의 Q-Q 그림을 본다점들이 대각선을 따라가나요? 오른쪽 끝(가장 긴 간격들)에서 크게 벗어나지 않는지 봅니다.
  3. 다른 후보와 비교한다정규분포로 바꿔 보면 Q-Q 그림이 휘고, 히스토그램 왼쪽에서 음수 쪽으로 넘어간 밀도가 보입니다.

이 데이터에서는 감마분포도 잘 맞는데, 추정한 모양 k̂가 1에 가깝다면 사실상 지수분포입니다. 모수가 적은 쪽을 고르는 것이 원칙입니다(오컴의 면도날). 손님 도착이 서로 독립이고 일정한 비율로 일어난다는 이론적 근거도 지수분포를 뒷받침합니다.

3.2메뉴가 섞인 제조 시간중간

2.2절의 그 데이터입니다. “메뉴 혼합”을 고르고 네 후보를 모두 대 보세요. 어느 것도 Q-Q 그림에서 깔끔한 직선이 나오지 않습니다. 가운데 부분이 S자로 휘는 것은 봉우리가 둘이라는 신호입니다.

기록지에 메뉴를 함께 적어 두었다면 “아메리카노만”과 “라떼만”으로 나눠서 다시 맞춰 보세요. 각각은 감마분포나 로그정규분포에 잘 맞습니다. 시뮬레이션에서는 0편 2.5절처럼 먼저 메뉴를 고르고, 그 메뉴의 분포에서 제조 시간을 뽑으면 됩니다. 2편 커피점 모델이 메뉴별 시간을 따로 가진 이유가 이것입니다.

나눌 정보가 없다면? 두 분포의 혼합(mixture)으로 모델링할 수 있습니다. “확률 p로 분포 A, 1 − p로 분포 B”라는 모델이며, 모수는 EM 알고리즘 같은 방법으로 추정합니다. 하지만 원인을 알고 나누는 편이 훨씬 해석하기 좋고, 메뉴 비율이 바뀌는 시나리오도 실험할 수 있습니다.

3.3직접 잰 데이터실전

이제 시뮬레이션을 현실로 가져갈 차례입니다. 교내 커피점, 학생식당, 엘리베이터, 프린터 앞 어디든 좋습니다. 30분에서 1시간 정도 관찰하며 도착 시각을 기록해 보세요. 기록한 시각을 위 도구의 “내 데이터”에 붙여 넣고 “시각 기록을 간격으로 바꾸기”를 켜면 바로 분석됩니다.

현장 기록 요령

  1. 무엇을 잴지 정의한다“도착”은 줄 끝에 선 순간인가, 매장 문을 연 순간인가? “제조 시간”은 주문을 받은 순간부터인가, 머신에 컵을 올린 순간부터인가? 정의를 정하고 끝까지 지킵니다.
  2. 스톱워치 앱의 랩 기능을 쓴다사건마다 랩 버튼을 누르면 시각이 기록됩니다. 초 단위로 충분합니다. 동시에 메뉴나 일행 수 같은 특성을 짧게 메모해 두면 3.2절처럼 나눠서 분석할 수 있습니다.
  3. 충분히 모은다평균을 보려면 30개, 분포의 모양을 보려면 최소 50~100개가 필요합니다. 꼬리를 보려면 더 많아야 합니다. 필요한 개수는 9편에서 공식으로 다시 계산합니다.
  4. 시간대를 기록한다관찰 도중 도착이 눈에 띄게 몰리거나 줄었다면 시각을 적어 두고, 그 전후를 나눠 분석합니다(2.7절).

현실 데이터의 함정. 관찰자가 보이면 사람들이 평소와 다르게 행동할 수 있습니다(관찰자 효과). 버튼을 늦게 누르는 반응 지연은 짧은 간격을 왜곡합니다. 관찰을 마칠 때 아직 진행 중이던 작업은 끝을 모르므로 그냥 버리면 긴 시간이 과소 대표됩니다(중도 절단). 또 개인이 아닌 일행(2~3명)이 함께 오면 간격 0이 여러 번 생기는데, 이때는 “일행의 도착”과 “일행의 크기”를 따로 모델링하는 편이 낫습니다.

Python에서는 scipy.stats로 같은 분석을 할 수 있습니다. 분포를 정한 뒤에는 2편의 SimPy 코드에서 도착 간격을 만드는 한 줄만 바꾸면 여러분이 관찰한 현실이 시뮬레이션에 들어갑니다.

import numpy as np
from scipy import stats

gaps = np.loadtxt("my_gaps.txt")              # 직접 잰 도착 간격 (초 또는 분)

candidates = {
    "지수": stats.expon,
    "감마": stats.gamma,
    "로그정규": stats.lognorm,
    "와이블": stats.weibull_min,
}
for name, dist in candidates.items():
    params = dist.fit(gaps, floc=0)           # 위치 모수는 0으로 고정하고 최대우도 추정
    d, p = stats.kstest(gaps, dist.name, args=params)
    print(f"{name:5s} 모수={np.round(params, 3)}  K-S D={d:.3f}  p={p:.3f}")

# Q-Q 그림: 점들이 대각선 위에 있는지 눈으로 확인
import matplotlib.pyplot as plt
stats.probplot(gaps, dist=stats.expon, plot=plt)
plt.show()

4연결과 정리

4.1앞뒤 편과의 연결

0편에서분포의 개념, 평균과 표준편차, 역변환법을 썼습니다. 이 편에서 고른 분포는 결국 역변환법(또는 라이브러리 함수)으로 난수를 만들어 시뮬레이션에 들어갑니다.

2편과 3편에서커피점의 메뉴별 제조 시간과 시간대별 도착률, 생태계 개체들의 속도와 번식 간격 분포가 모두 입력 모델입니다. ABM에서는 개체의 특성(속도, 인내심, 성향)이 분포로 주어진다는 점만 다를 뿐, 방법은 같습니다.

5편으로입력이 정해지면 시뮬레이션을 돌려 나온 출력을 분석합니다. 입력 분포 자체가 유한한 데이터에서 추정한 것이라 불확실하다는 점도 출력의 불확실성에 더해집니다.

8편과 9편으로입력이 맞아도 모델 구조가 틀릴 수 있으므로 8편에서 모델 전체를 현실과 비교합니다. 9편 프로젝트의 데이터 수집 계획은 3.3절의 기록 요령에서 출발합니다.

4.2요약

왜
대기시간은 처리 시간의 평균뿐 아니라 변동계수 C에 비례해 커진다. 입력의 모양이 결과를 바꾼다.
살펴보기
히스토그램(칸 수를 바꿔 보며), 요약통계(C, 평균 대 중앙값), 독립성, 정상성.
추정
적률법은 평균과 분산을 맞춘다. 최대우도법은 데이터가 나올 가능성을 최대로 한다. 지수분포에서는 둘 다 λ̂ = 1/x̄.
확인
Q-Q 그림을 먼저, K-S와 χ² 검정은 보조로. 꼬리를 특히 본다.
특수 상황
데이터가 없으면 삼각·PERT 분포와 민감도 분석. 섞인 데이터는 원인별로 나눈다. 시간에 따라 변하면 NHPP와 솎아내기.

4.3연습 문제

1. 서버 응답 시간 데이터의 평균이 0.8초, 표준편차가 2.4초입니다. 어떤 분포를 먼저 떠올려야 할까요?

C = 2.4/0.8 = 3으로 1보다 훨씬 큽니다. 대부분은 빠르지만 가끔 아주 느린 응답이 있다는 뜻입니다. 지수분포(C = 1)나 감마분포(k = 1/9 정도)보다는 로그정규분포나 “빠른 응답 + 느린 응답”의 혼합을 먼저 검토합니다. 느린 응답의 원인(캐시 미스, 디스크 접근 등)을 알 수 있다면 나눠서 모델링하는 것이 가장 좋습니다.

2. 도착 간격 50개의 합이 125분이었습니다. 지수분포의 최대우도 추정값과, 1시간 동안의 평균 도착 수는?

λ̂ = n/Σx = 50/125 = 0.4명/분입니다. 1시간 동안의 평균 도착 수는 0.4 × 60 = 24명이고, 도착 수는 평균 24인 포아송분포를 따른다고 봅니다(0편 2.3절 참고).

3. 데이터 1만 개로 K-S 검정을 했더니 “맞지 않는다”가 나왔지만, Q-Q 그림은 거의 직선입니다. 어떻게 판단할까요?

데이터가 아주 많으면 검정은 실용적으로 무의미한 작은 차이까지 잡아냅니다. Q-Q 그림이 특히 꼬리까지 직선이라면 그 분포를 써도 됩니다. 최종 판단은 “이 차이가 시뮬레이션의 결론을 바꾸는가”로 합니다. 의심되면 경험분포로도 돌려 보고 결과가 같은지 비교합니다.

4. 전문가가 수리 시간을 “최소 10분, 보통 20분, 최대 60분”이라고 했습니다. 삼각분포와 PERT의 평균은?

삼각: (10 + 20 + 60)/3 = 30분. PERT: (10 + 4×20 + 60)/6 = 25분. 오른쪽 꼬리가 긴 상황에서 삼각분포는 최댓값의 영향을 더 많이 받습니다. 어느 쪽이든 8편의 민감도 분석으로 이 입력이 결론에 얼마나 영향을 주는지 확인해야 합니다.

5. 손님 도착을 하루 평균 도착률로 평평하게 모델링하면 대기시간을 어느 방향으로 틀리게 예측할까요? 그 이유는?

대부분 과소평가합니다. 1.1절 공식에서 대기는 ρ/(1 − ρ)로 늘어나는데, 이 함수는 볼록해서 바쁜 시간의 증가분이 한가한 시간의 감소분보다 훨씬 큽니다. 평균 이용률이 0.7이어도 점심에 0.95가 되면 그 시간의 대기가 전체 평균을 끌어올립니다. 2.7절 위젯에서 “평평하게”를 골라 시간대별 도착 수를 비교해 보세요.
