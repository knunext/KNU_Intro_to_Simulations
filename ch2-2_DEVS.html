모델링과 시뮬레이션 목차

모델링과 시뮬레이션, 2-2편 (2편 심화)

DEVS: 모델을 부품처럼 조립하기M = ⟨X, Y, S, δext, δint, λ, ta⟩

2편에서는 프롬프트 커피점을 사건 목록 하나로 돌렸습니다. 이번에는 같은 카페를 상자 네 개로 쪼갭니다. 상자마다 자기 상태만 알고, 다른 상자와는 정해진 포트로만 메시지를 주고받습니다. 이산사건 모델을 이렇게 적는 규칙이 DEVS(Discrete Event System Specification)입니다.

이 편을 마치면

  • 원자 모델의 일곱 원소로 부품 하나를 적고, 입력과 상태와 출력의 시간 궤적을 읽을 수 있습니다.
  • EIC, EOC, IC로 부품을 이어 결합 모델을 만들고, 결합에 대해 닫혀 있다는 성질을 설명할 수 있습니다.
  • 추상 시뮬레이터의 다섯 가지 메시지로 모델이 실행되는 순서를 따라갈 수 있습니다.
  • 동시 사건을 Select와 병렬 DEVS가 어떻게 다루는지, 사건 스케줄링과 무엇이 근본적으로 다른지 설명할 수 있습니다.

선 위를 지나는 점이 메시지입니다. 파란 점은 결합 모델이 부품에게 내려 주는 입력, 초록 점은 결합 모델 밖으로 나가는 출력입니다. 굵게 테두리가 켜지는 상자가 방금 상태를 바꾼 부품입니다. 손님 간격과 제조 시간은 지수분포라서 1편의 M/M/1과 같은 시스템이고, 통계 T가 잰 평균 체류시간을 공식과 비교할 수 있습니다.

1왜 다시 카페인가

2편의 코드를 떠올려 봅시다. 도착 사건 루틴은 바리스타가 비었는지 직접 들여다보고, 제조 완료 루틴은 대기열에서 다음 손님을 직접 꺼냅니다. 미래 사건 목록 하나가 카페의 모든 미래를 쥐고 있습니다. 카페가 작을 때는 이 방식이 가장 빠르고 단순합니다.

그런데 에스프레소 머신을 두 대로 늘리고, 키오스크를 붙이고, 옆 매장과 재료를 나눠 쓰기 시작하면 사정이 달라집니다. 루틴 하나를 고치면 같은 상태 변수를 건드리던 다른 루틴들을 모두 다시 확인해야 합니다. 바리스타 부분만 떼어 다른 매장 모델에 다시 쓰기도 어렵습니다.

DEVS는 Bernard Zeigler가 1976년에 제안한 이산사건 모델의 형식 명세입니다. 지키는 약속은 세 가지입니다.

자기 상태만 안다. 부품은 자기 상태 변수만 바꿀 수 있습니다. 위 그림의 바리스타 B는 줄이 몇 명인지 모릅니다.
포트로만 말한다. 바깥과 주고받는 것은 입력 포트와 출력 포트를 오가는 메시지가 전부입니다.
조립한 것도 모델이다. 부품을 이어 붙인 결합 모델도 바깥에서 보면 포트를 가진 상자 하나입니다. 그래서 계층으로 쌓을 수 있습니다.

그리고 모델과 그 모델을 돌리는 시뮬레이터가 분리됩니다. 모델은 "무슨 일이 일어나는가"만 적고, 시뮬레이터는 "언제, 누구 차례인가"만 맡습니다. 위 데모의 카페도 4절에서 볼 범용 엔진이 돌리고 있습니다. 엔진은 카페에 대해 아무것도 모릅니다.

2원자 모델: 일곱 개짜리 묶음

더 쪼개지 않는 부품을 원자 모델이라 부릅니다. 원자 모델은 일곱 가지로 정의됩니다. 예로 대기열을 품은 바리스타 P 하나를 적어 보겠습니다. 주문을 받으면 만들고, 만드는 중에 온 주문은 쌓아 두며, 한 잔에 정확히 d분이 걸립니다.

X입력 사건의 집합.
X = {주문}
Y출력 사건의 집합.
Y = {음료}
S상태의 집합. 여기서는 단계, 쌓인 주문 수 q, 남은 시간 σ의 묶음입니다.
S = {쉼, 제조} × ℕ × [0, ∞]
δext외부 전이. 입력이 들어오면 지금 상태와 마지막 전이 뒤 흐른 시간 e를 보고 새 상태를 정합니다.
δext((쉼, 0, ∞), e, 주문) = (제조, 0, d)
δext((제조, q, σ), e, 주문) = (제조, q+1, σ − e)
δint내부 전이. 입력 없이 ta(s)만큼 시간이 흐르면 일어납니다.
δint((제조, q, σ)) = (제조, q−1, d)  (q > 0일 때),  (쉼, 0, ∞)  (q = 0일 때)
λ출력 함수. 내부 전이 바로 직전의 상태를 보고 무엇을 내보낼지 정합니다.
λ((제조, q, σ)) = 음료
ta시간 전진 함수. 입력이 없다면 이 상태에 얼마나 머무는지.
ta((단계, q, σ)) = σ

이 정의가 시간 위에서 어떻게 움직이는지 봅시다. 아래 그림의 다섯 줄은 입력, 상태, 남은 시간 σ, 경과 시간 e, 출력의 시간 궤적입니다.

4분
시각 t0.0분
상태 s(쉼, 0, ∞)
경과 시간 e0.0분
남은 시간 ta(s) − e∞
아직 아무 전이도 없었습니다.

맨 위 입력 줄을 누르면 그 시각에 주문이 하나 들어가고, 이미 있는 주문을 누르면 지워집니다. 그림 위를 끌면 세로 시각 선이 움직이고, 오른쪽 상자와 위의 정의 표가 그 시각에 맞춰 바뀝니다.

총 상태 (s, e). 경과 시간 e는 언제나 0 ≤ e ≤ ta(s)입니다. e가 ta(s)에 닿는 순간 내부 전이가 일어나기 때문입니다. 그래서 어느 순간의 모델을 완전히 알려면 s와 e를 함께 알아야 하고, 이 쌍을 총 상태라고 부릅니다. 궤적 그림에서 남은 시간과 e를 더하면 각 구간마다 ta(s)로 일정한 것을 확인해 보세요.
출력은 내부 전이에서만 나옵니다. λ는 δint 직전에만 불립니다. 입력을 받자마자 대답해야 한다면 ta = 0인 상태에 잠깐 들렀다가 나갑니다. 3절의 대기열 Q가 바로 이렇게 손님을 바리스타에게 넘깁니다. 반대로 ta = ∞인 상태는 수동 상태라고 합니다. 바리스타의 '쉼'처럼 입력이 오기 전에는 영원히 그대로입니다.

이 데모는 주문 도착과 제조 완료가 같은 시각이면 완료를 먼저 처리합니다. 이 선택이 왜 문제가 되는지는 5절에서 다룹니다.

3결합 모델: 상자를 선으로 잇기

바리스타 P 하나로도 카페를 돌릴 수는 있습니다. 하지만 줄 서는 규칙만 바꾸거나 바리스타만 늘리고 싶어지는 순간이 옵니다. 그래서 맨 위 데모는 대기열 Q와 바리스타 B를 따로 만들고 선으로 이었습니다. 선을 잇는 방법도 튜플로 적습니다.

N = ⟨X, Y, D, {Md}, EIC, EOC, IC, Select⟩

D는 부품 이름들이고 Md는 각 부품의 모델입니다. 선은 세 종류입니다. EIC(외부 입력 결합)는 결합 모델의 입력 포트에서 부품의 입력 포트로, EOC(외부 출력 결합)는 부품의 출력 포트에서 결합 모델의 출력 포트로, IC(내부 결합)는 한 부품의 출력 포트에서 다른 부품의 입력 포트로 갑니다. Select는 같은 시각에 차례가 겹친 부품 중 누구를 먼저 실행할지 정하는 규칙입니다.

선을 누르면 그 선이 어느 튜플의 어떤 원소인지 여기에 나옵니다.

결합에 대해 닫혀 있다. '카운터 안 숨기기'를 눌러 보세요. 카페 입장에서 카운터는 in 하나, out 하나짜리 상자일 뿐입니다. 어떤 결합 모델이든 그와 똑같이 동작하는 원자 모델이 존재한다는 것이 증명되어 있습니다(closure under coupling). 그래서 카운터를 '바리스타 두 명짜리 카운터'로 갈아 끼워도 카페 쪽 선은 하나도 바뀌지 않고, 카운터를 품은 카페를 다시 더 큰 상가 모델의 부품으로 쓸 수도 있습니다.

선에 관한 규칙도 두 가지 기억해 둡시다. 출력 포트 하나에서 선이 여러 개 나갈 수 있습니다. G의 손님은 카운터와 T에 동시에 가고, B의 음료는 Q의 ready 포트와 카운터의 출력으로 동시에 갑니다. 반면 부품의 출력이 자기 자신의 입력으로 곧바로 돌아오는 선은 허용하지 않습니다.

G, Q·B, T 구성은 DEVS 교과서에 늘 나오는 GPT 예제(생성기 Generator, 처리기 Processor, 트랜스듀서 Transducer)를 카페로 옮긴 것입니다. 트랜스듀서는 시스템에 손대지 않고 재기만 하는 관측용 부품입니다. T는 자기 시계를 상태로 들고 다니며 손님마다 들어온 시각과 나간 시각을 비교합니다. 부품은 전역 시계를 볼 수 없기 때문입니다.

4추상 시뮬레이터: 시계는 누가 쥐는가

모델은 함수 묶음일 뿐 스스로 돌지 않습니다. DEVS는 모델 구조를 그대로 본뜬 시뮬레이터 나무를 만듭니다. 원자 모델마다 시뮬레이터가, 결합 모델마다 코디네이터가 붙고, 꼭대기에 루트 코디네이터가 하나 있습니다. 각 노드는 두 시각을 기억합니다. tL은 마지막으로 전이한 시각, tN은 다음에 전이할 예정 시각입니다.

노드끼리는 다섯 가지 메시지만 주고받습니다.

메시지방향뜻
(i, t)아래로초기화하고 다음 시각을 알려 달라.
(*, t)아래로시각 t가 됐다. 지금 차례인 부품은 출력하고 내부 전이하라.
(x, t)아래로입력 x가 시각 t에 도착했다. 외부 전이하라.
(y, t)위로내가 시각 t에 y를 출력했다.
(done, tN)위로처리를 마쳤고, 내 다음 예정 시각은 tN이다.

코디네이터의 tN은 자식들 tN의 최솟값입니다. 2편의 미래 사건 목록이 나무 모양으로 흩어져 있는 셈입니다. 루트는 맨 위 tN이 언제인지 보고 (*, tN)을 내려보내는 일만 되풀이합니다. 아래 실험은 손님이 1분부터 3분마다 오고, 제조는 정확히 4분 걸리며, T가 8분에 관측을 끝내는 짧은 시나리오입니다.

i 초기화* 내부 전이 지시x 입력y 출력done 완료 보고
    메시지는 나무의 위아래로만 움직입니다. G의 손님이 T에 갈 때도 G → 카페 (y), 카페 → T (x)처럼 공통 부모를 거칩니다. 부품은 누가 자기 출력을 받는지 모르고, 그것을 아는 것은 결합 정보를 가진 코디네이터뿐입니다. 이것이 부품을 갈아 끼울 수 있는 이유입니다.

    1분에는 루트 사이클이 두 번 돕니다. 첫 사이클에서 G가 손님 1을 내보내고, 그 손님을 받은 Q가 ta = 0 상태가 되어 두 번째 사이클에서 바리스타에게 넘깁니다. 시계는 그대로인데 사건이 두 번 일어난 것입니다. 5분과 9분에도 같은 일이 벌어집니다. 로그에서 사이클마다 맨 앞의 루트 → 카페 (*) 메시지를 세어 보세요.

    5같은 시각에 두 사건이 겹치면

    정수 분 단위로 일정을 잡은 모델에서는 사건이 정확히 같은 시각에 겹치는 일이 흔합니다. 일부러 겹치게 만들어 봅시다. 손님은 2분부터 정확히 4분마다 오고, 제조도 정확히 4분이 걸리며, 줄 설 자리 K는 0입니다. 그러면 바리스타가 음료를 내놓는 바로 그 순간에 다음 손님이 도착합니다.

    고전 DEVS에서 G와 B가 같은 시각에 차례가 되면 코디네이터는 Select 순서대로 한 명씩 실행합니다. G가 먼저라면 Q는 바리스타가 아직 바쁘다고 알고 있는 상태에서 손님을 받습니다.

    4.0분
    0자리

    파란 점은 도착, 갈색 막대는 제조, 회색 막대는 기다린 시간, 빨간 ✕는 자리가 없어 돌아간 손님입니다.

    6분에 일어난 일

      병렬 DEVS(Chow와 Zeigler, 1994)는 두 가지를 바꿉니다. 같은 시각에 차례가 된 부품은 모두 한꺼번에 출력하고, 한 부품에 같은 순간 도착한 입력은 꾸러미(bag) 하나로 묶어 한 번에 전달합니다. 그리고 내부 전이와 외부 입력이 한 부품에서 겹칠 때를 위해 합류 전이 δcon을 따로 둡니다. Select는 필요 없어집니다.

      M = ⟨Xb, Yb, S, δext, δint, δcon, λ, ta⟩,   δcon : S × Xb → S

      Select가 사라진 대신 결정은 Q의 δext 안으로 들어갔습니다. "꾸러미 안에서 ready를 먼저 보고 in을 본다"는 규칙이 모델 명세에 한 줄로 남습니다. '병렬: in 먼저 처리'를 누르면 고전 DEVS에서 G를 먼저 실행했을 때와 같은 결과가 나옵니다. 병렬 DEVS가 정답을 알려 주는 것이 아니라, 그 결정을 누가 내리는지를 모델러 눈에 보이는 곳으로 옮겨 놓은 것입니다.

      제조 시간을 3.9분이나 4.1분으로 바꿔 보세요. 겹침이 사라지면 네 방식이 모두 같은 결과를 냅니다. 3.9분이면 아무도 돌아가지 않고, 4.1분이면 Select와 상관없이 두 명 중 한 명이 돌아갑니다. 정확히 4.0분일 때만 결과가 실행 순서에 달려 있습니다. 동시 사건 문제는 입력 데이터를 분 단위로 반올림했을 때 특히 자주 숨어 들어옵니다.

      6가장 큰 차이: 사건이 아니라 부품이 주인공

      지금까지 본 것을 한 문장으로 줄이면 이렇습니다. 다른 방식에서는 사건이나 프로세스가 모델의 단위이고, DEVS에서는 포트를 가진 부품이 모델의 단위입니다. 사건은 부품 안에서 일어나는 상태 전이일 뿐이고, 부품 밖으로 나가는 것은 출력 메시지뿐입니다.

      답하는 질문의 층위가 다르다

      사건 스케줄링(2편), 활동 스캐닝, 프로세스 상호작용(SimPy)을 흔히 시뮬레이션의 세계관(world view)이라고 부릅니다. 셋 모두 "시뮬레이션 프로그램을 어떻게 짤 것인가"에 대한 답입니다. DEVS는 그보다 한 층 위에서 "모델이란 수학적으로 무엇인가"에 답합니다. 모델은 입력 궤적을 받아 출력 궤적을 내놓는 시스템이고, 그 안쪽을 일곱 개짜리 튜플로 적습니다.

      그래서 DEVS 시뮬레이터의 내부를 사건 스케줄링으로 짜는 것도 얼마든지 가능합니다. 4절의 코디네이터들이 들고 있는 tN 값을 한 줄로 모으면 2편의 사건 목록이 됩니다. 전자회로에 빗대면, 회로도는 부품과 핀과 배선만 적고 전류를 어떤 수치 방법으로 계산할지는 회로 시뮬레이터가 정합니다. 사건 스케줄링은 계산 방법 쪽에 가깝고, DEVS는 회로도 쪽에 가깝습니다. 프로그래밍에 빗대면, 전역 변수를 여러 함수가 함께 고치는 프로그램과 캡슐화된 객체들이 메시지를 주고받는 프로그램의 차이와 닮았습니다. DEVS는 여기에 시간을 정확히 다루는 규칙을 더한 것입니다.

      미래를 정할 수 있는 건 자기 자신뿐

      이 차이에서 가장 실질적인 결과가 나옵니다. 사건 스케줄링에서는 어느 루틴이든 사건 목록에 아무 사건이나 넣고 뺄 수 있습니다. 손님 도착 루틴이 "3분 뒤 바리스타 휴식 시작"을 예약해도 막을 방법이 없습니다. DEVS에서 부품이 정할 수 있는 미래는 자기 ta 하나뿐입니다. 남에게 무슨 일이 언제 일어나게 하려면 지금 메시지를 보내야 하고, 그 일이 언제 일어날지는 받는 쪽이 자기 δext 안에서 정합니다.

      그래서 DEVS에는 '예약 취소'라는 연산이 없습니다. 이미 정해 둔 일정이 바깥 사건 때문에 바뀌면, 그 부품이 δext에서 σ를 새로 계산하면 끝입니다. 사건 스케줄링이라면 예약해 둔 사건을 찾아 지우고 다시 넣어야 하고, SimPy라면 기다리던 프로세스를 interrupt()로 깨운 뒤 남은 시간을 직접 계산해야 합니다. 다음 절의 신호등이 바로 이 경우입니다.

      언제 쓰고, 언제 과한가

      DEVS가 제값을 하는 곳은 부품이 많고, 여러 사람이 부품을 나눠 만들고, 같은 부품을 여러 시나리오에서 다시 써야 하는 큰 모델입니다. 제조 라인, 교통, 통신망, 그리고 국방 M&S가 대표적입니다. 국내에서도 국방과학연구소의 통합 교전 시뮬레이션 환경 AddSIM에 맞춰 무기체계 모델을 DEVS 형식론으로 설계하거나, DEVS를 분산 시뮬레이션 표준인 HLA와 엮어 교전급 시뮬레이션을 구성한 연구들이 있습니다.

      class SignalController(Atomic):
    NEXT = {"car": "yellow", "yellow": "walk", "walk": "car"}
    def __init__(self, g_min=20, g_max=60):
        super().__init__("C")
        self.g_min, self.g_max = g_min, g_max

        self.phase, self.sigma, self.g, self.req = "car", g_max, 0.0, False
    def ta(self):     return self.sigma
    def output(self): return ("signal", self.NEXT[self.phase])
    def delta_int(self):
        self.phase = self.NEXT[self.phase]
        self.sigma, self.g, self.req = self.dur[self.phase], 0.0, False
    def delta_ext(self, e, port, value):
        self.sigma -= e                                  # 기본: 하던 일 계속
        if self.phase == "car":
            self.g += e                                  # 이번 녹색에서 지난 시간

                self.sigma = max(0.0, self.g_min - self.g)   # 자기 σ만 다시 정한다

    def delta_int(self):          pass          # 내부 전이
    def delta_ext(self, e, port, value): pass   # 외부 전이 (e = 경과 시간)

class Generator(Atomic):          # G: 손님을 내보낸다
    def __init__(self, mean_gap, rng):
        super().__init__("G")
        self.mean_gap, self.rng = mean_gap, rng
        self.sigma, self.n = rng.expovariate(1 / mean_gap), 0
    def ta(self):        return self.sigma
    def output(self):    return ("out", self.n + 1)
    def delta_int(self):
        self.n += 1
        self.sigma = self.rng.expovariate(1 / self.mean_gap)
    def delta_ext(self, e, port, value):
        self.sigma = INF if port == "stop" else self.sigma - e

class Queue(Atomic):              # Q: 줄 세우고, 바리스타가 비면 즉시(ta=0) 넘긴다
    def __init__(self):
        super().__init__("Q")
        self.q, self.busy, self.sigma = [], False, INF
    def ta(self):        return self.sigma
    def output(self):    return ("out", self.q[0])
    def delta_int(self):
        self.q.pop(0)
        self.busy, self.sigma = True, INF
    def delta_ext(self, e, port, value):
        if port == "in":    self.q.append(value)
        if port == "ready": self.busy = False
        self.sigma = 0 if (not self.busy and self.q) else INF

class Barista(Atomic):            # B: 한 명씩 만든다
    def __init__(self, mean_svc, rng):
        super().__init__("B")
        self.mean_svc, self.rng = mean_svc, rng
        self.job, self.sigma = None, INF
    def ta(self):        return self.sigma
    def output(self):    return ("out", self.job)
    def delta_int(self): self.job, self.sigma = None, INF
    def delta_ext(self, e, port, value):
        self.job, self.sigma = value, self.rng.expovariate(1 / self.mean_svc)

class Transducer(Atomic):         # T: 자기 시계를 들고 다니며 체류시간을 잰다
    def __init__(self, obs_time):
        super().__init__("T")
        self.sigma, self.clock = obs_time, 0.0
        self.arrived, self.waits = {}, []
    def ta(self):        return self.sigma
    def output(self):    return ("out", "stop")
    def delta_int(self): self.clock, self.sigma = self.clock + self.sigma, INF
    def delta_ext(self, e, port, value):
        self.clock += e
        if self.sigma < INF: self.sigma -= e
        if port == "arrived": self.arrived[value] = self.clock
        if port == "solved":  self.waits.append(self.clock - self.arrived.pop(value))

class Coordinator:
    """결합 모델 한 층을 돌리는 코디네이터. tN의 최솟값이 곧 '다음 사건'."""
    def __init__(self, models, couplings, select):
        self.m = {m.name: m for m in models}
        self.ic, self.select = couplings, select
        self.tL = {n: 0.0 for n in self.m}
        self.tN = {n: m.ta() for n, m in self.m.items()}
    def step(self):
        t = min(self.tN.values())
        if t == INF:
            return False
        d = next(n for n in self.select if self.tN[n] == t)   # Select: 동시면 우선순위
        y = self.m[d].output()                                # λ는 δint 바로 앞에서
        self.m[d].delta_int()
        self.tL[d], self.tN[d] = t, t + self.m[d].ta()
        if y is not None:
            port, value = y
            for src, sp, dst, dp in self.ic:                  # 결합을 따라 배달
                if (src, sp) == (d, port):
                    self.m[dst].delta_ext(t - self.tL[dst], dp, value)
                    self.tL[dst], self.tN[dst] = t, t + self.m[dst].ta()
        return True

rng = random.Random(7)
