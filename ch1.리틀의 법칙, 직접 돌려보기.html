1. 상자 하나를 그린다

어떤 시스템이든 주위에 경계를 하나 긋는다. 편의점이라면 줄 끝부터 계산대까지, 웹 서버라면 요청이 들어와서 응답이 나갈 때까지다. 위 시뮬레이션의 점선 상자가 그 경계다. 경계를 정하면 세 가지를 잴 수 있다.

L
상자 안에 있는 인원의 시간 평균. 매 순간의 인원 N(t)를 관측 시간 동안 평균한 값이다.
λ
상자에 들어오는 비율 (단위 시간당 인원). 자리가 없어 돌아간 사람은 상자에 들어오지 않았으므로 세지 않는다.
W
한 사람이 상자 안에 머무는 시간의 평균.

John D. C. Little은 1961년에, 장기 평균이 존재하기만 하면 이 셋 사이에 다음 관계가 늘 성립함을 증명했다.

L = λW

도착 간격과 서비스 시간이 어떤 분포를 따르든, 창구가 몇 개든, 선착순이든 아니든 상관없다. 필요한 조건은 시스템이 안정적이라는 것, 곧 사람이 상자 안에 끝없이 쌓이지 않는다는 것뿐이다. 위에서 분포를 ‘일정’으로 바꾸거나 창구를 늘려 보면 두 값이 여전히 만나는 것을 볼 수 있다. 반대로 λ를 cμ보다 크게 하고 대기 공간을 무제한으로 두면 줄이 계속 길어져 평균 자체가 수렴하지 않는다.

2. 왜 성립할까: 같은 넓이를 두 번 센다

관측 시간 T 동안 n명이 상자를 거쳐 갔다고 하자. 아래 위쪽 그림은 고객 한 명을 가로 막대 하나로 그린 것이다. 막대의 길이가 그 사람의 체류 시간 Wi이고, 주황 부분은 기다린 시간, 초록 부분은 서비스받은 시간이다. 아래쪽 그림은 매 순간 상자 안의 인원 N(t)이다.

어느 순간 τ에 세로선을 그으면, 그 선을 지나는 막대의 개수가 바로 N(τ)다. 그러니 막대 길이를 모두 더한 값과 N(t) 아래 넓이는 같은 양을 다른 방향으로 센 것이다. 이 넓이를 A라 하면

L = A/T,  W = A/n,  λ = n/T
⇒ L = (n/T)(A/n) = λW

그래프 위에 마우스를 올리거나 터치해서 세로선을 움직여 보자. 일시정지하면 천천히 볼 수 있다.

3. 경계는 어디에 그어도 된다

상자를 대기열만 감싸게 그리면 Lq = λWq이고, 창구만 감싸게 그리면 ‘평균적으로 바쁜 창구 수 = λ × 평균 서비스 시간’이 된다. 마지막 식이 곧 이용률의 정의다. 창구가 c개이고 손님을 거절하지 않으면 cρ = λ/μ가 된다.

4. M/M/1: 이용률이 1에 가까워지면

리틀의 법칙은 세 양 사이의 관계일 뿐, 셋 중 어느 하나를 혼자 알려 주지는 않는다. 하나를 구하려면 모형이 필요하다. 가장 간단한 M/M/1 (지수분포 도착, 지수분포 서비스, 창구 1개)에서는 이용률 ρ = λ/μ < 1일 때 다음이 성립한다.

L = ρ/(1 − ρ),  Lq = ρ2/(1 − ρ)
W = L/λ = 1/(μ − λ),  Wq = W − 1/μ

W를 구할 때 리틀의 법칙을 쓴 것에 주목하자. 그리고 곡선의 모양을 보자. ρ가 0.8이면 L = 4, 0.9면 9, 0.95면 19다. 창구가 80% 바쁠 때와 95% 바쁠 때 줄 길이는 다섯 배 가까이 차이 난다.

연습 문제

학생식당

점심시간 학생식당 안에는 평균 60명이 있고, 1분에 4명씩 들어온다. 한 사람은 평균 몇 분 머무를까?

W = L/λ = 60/4 = 15분. 대기열 모형도, 배식 시간 분포도 몰라도 된다.
웹 서버의 동시 요청 수

어떤 API 서버에 초당 200개의 요청이 들어오고 평균 응답 시간은 50ms다. 서버 안에서 동시에 처리 중인 요청은 평균 몇 개일까? 워커 스레드가 8개라면?

단위를 맞추면 W = 0.05초. L = 200 × 0.05 = 10개. 평균만으로도 워커 8개를 넘으므로 요청이 쌓이기 시작하고, 그러면 W가 더 늘어난다. 처리량 계획에서 리틀의 법칙이 가장 자주 쓰이는 방식이다.
생산 라인의 리드타임

한 생산 라인에 재공품(WIP)이 평균 120개 있고 시간당 40개가 완성된다. 리드타임은? 처리량은 그대로 두고 리드타임을 2시간으로 줄이려면 재공품을 몇 개로 줄여야 할까?

W = 120/40 = 3시간. 2시간으로 줄이려면 L = 40 × 2 = 80개. 린 생산에서 ‘재공품을 줄이면 리드타임이 준다’는 말의 근거가 이 식이다.
공용 프린터 (M/M/1)

연구실 프린터에 인쇄 작업이 시간당 10건 들어오고(포아송 도착), 프린터는 시간당 12건을 처리한다(지수분포 서비스). ρ, L, W는? 도착이 시간당 11건으로 10% 늘면?

ρ = 10/12 ≈ 0.833, L = 0.833/0.167 = 5건, W = 1/(12 − 10) = 0.5시간 = 30분.
도착이 11건이면 ρ ≈ 0.917, L = 11건, W = 1시간. 도착이 10% 늘었을 뿐인데 체류 시간은 두 배가 된다. 4절 곡선의 가파른 구간이다.
자리가 없으면 돌아가는 미용실

대기 의자가 3개뿐인 미용실에 손님이 시간당 6명 오지만, 그중 3분의 1은 자리가 없어 그냥 돌아간다. 가게 안에는 평균 2명이 있다. 들어온 손님은 평균 얼마나 머무를까?

상자에 실제로 들어온 비율은 λeff = 6 × 2/3 = 4명/시간. W = 2/4 = 0.5시간. λ = 6을 그대로 쓰면 20분이라는 틀린 답이 나온다. 위 시뮬레이션에서 대기 공간을 줄여 보면 표의 ‘실효 도착률’이 이 값에 해당한다.

6. 다음 단계: DES와 ABM

맨 위 시뮬레이터는 이산사건 시뮬레이션(DES)이다. 시계가 일정한 간격으로 흐르지 않는다. 미래 사건 목록(FEL)에서 가장 이른 사건, 곧 ‘다음 도착’이나 ‘어느 창구의 서비스 종료’를 꺼내 시계를 그 시각으로 옮기고, 상태를 바꾸고, 그 결과로 생기는 새 사건을 목록에 넣는다. 두 사건 사이에는 아무 일도 일어나지 않으므로 그 구간의 N(t)는 상수이고, 넓이 A는 사건마다 ‘현재 인원 × 경과 시간’을 더해 정확히 계산된다.

같은 구조를 파이썬으로 (M/M/1)

import heapq, random

def simulate_mm1(lam, mu, t_end=10_000, seed=0):
    rng = random.Random(seed)
    fel = [(rng.expovariate(lam), "arr")]  # 미래 사건 목록
    queue = []         # 기다리는 사람의 도착 시각
    in_service = None  # 서비스 중인 사람의 도착 시각
    last = area = sum_w = 0.0
    n_in = n_out = 0

    while fel:
        t, kind = heapq.heappop(fel)
        if t > t_end:
            break
        n = len(queue) + (in_service is not None)
        area += n * (t - last)       # ∫N(t)dt 누적
        last = t
        if kind == "arr":
            n_in += 1
            heapq.heappush(fel, (t + rng.expovariate(lam), "arr"))
            if in_service is None:
                in_service = t
                heapq.heappush(fel, (t + rng.expovariate(mu), "dep"))
            else:
                queue.append(t)
        else:                        # 서비스 종료
            n_out += 1
            sum_w += t - in_service
            if queue:
                in_service = queue.pop(0)
                heapq.heappush(fel, (t + rng.expovariate(mu), "dep"))
            else:
                in_service = None

    L, lam_hat, W = area / last, n_in / last, sum_w / n_out
    print(f"L = {L:.3f},  λ·W = {lam_hat * W:.3f}")

simulate_mm1(0.8, 1.0)   # 이론값 L = 4

지금 돌고 있는 시뮬레이터의 사건 기록

    ABM으로 넘어가면 고객 하나하나가 자기 규칙을 가진 에이전트가 된다. 줄이 길면 처음부터 포기하고(balking), 기다리다 지치면 떠나고(reneging), 옆 줄이 짧으면 옮긴다(jockeying). 위의 ‘대기 공간’ 제한은 가장 단순한 포기 규칙이다. 규칙이 이렇게 복잡해지면 4절 같은 닫힌 식은 더 이상 쓸 수 없지만, 리틀의 법칙은 여전히 성립한다.

    그래서 DES든 ABM이든 모델을 만들면 L, λ, W를 서로 독립적으로 측정해 L ≈ λW인지부터 확인하는 것이 좋은 첫 번째 검증이 된다. 어긋난다면 통계 수집 코드에 버그가 있거나, 초기 과도 구간(warm-up)을 버리지 않았거나, 실행 시간이 너무 짧은 경우가 대부분이다. 맨 위 그래프에서 처음 몇십 분 동안 두 선이 벌어져 있는 것이 바로 과도 구간과 경계 효과다.
