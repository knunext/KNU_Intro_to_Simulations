1왜 출력 분석인가

확률적 시뮬레이션의 출력은 그 자체가 확률변수입니다. 한 번의 실행은 주사위를 한 번 던진 것과 같습니다.

1.1하루를 돌리면 한 숫자

점심 피크의 커피점을 모델링했다고 합시다. 손님은 분당 평균 0.6명, 바리스타 두 명, 한 잔에 평균 3분입니다. 08시부터 18시까지 600분을 한 번 시뮬레이션하면 “오늘의 평균 대기시간”이 하나 나옵니다. 버튼을 여러 번 눌러 보세요. 모델도 모수도 그대로인데 숫자는 매번 다릅니다.

같은 모델, 다른 하루

점 하나가 하루치 시뮬레이션의 평균 대기시간입니다. 가로 띠는 지금까지 모은 날들로 만든 95% 신뢰구간입니다.

하루만 보고 “평균 대기는 4.2분”이라고 보고했다면, 다른 날 돌렸으면 2분이나 8분이 나왔을 수도 있다는 사실을 숨긴 셈입니다. 출력 분석의 목표는 두 가지입니다. 하나는 관심 있는 값(여기서는 평균 대기)을 추정하는 것, 다른 하나는 그 추정이 얼마나 정확한지 함께 말하는 것입니다.

1.2종료형과 비종료형

종료형 시뮬레이션

시작과 끝이 자연스럽게 정해집니다. 커피점은 08시에 빈 매장으로 열고 18시에 닫습니다. 시작 상태(빈 매장)도 현실 그대로입니다. 관심 있는 값은 “하루 동안의 평균 대기” 같은 것이고, 하루를 여러 번 반복해서 분석합니다(2.1~2.2절).

비종료형(정상 상태) 시뮬레이션

자연스러운 끝이 없습니다. 24시간 도는 웹 서버, 쉬지 않는 공장 라인이 그렇습니다. 관심 있는 값은 “오래 돌렸을 때의 평균”이고, 시작 상태(빈 시스템)는 현실이 아니라 편의상 정한 것입니다. 그래서 초반 데이터를 버리거나(2.4절) 한 번의 긴 실행을 잘라 쓰는(2.5절) 기법이 필요합니다.

앞에서1편의 리틀의 법칙과 M/M/1 공식은 모두 정상 상태 값입니다. 1편 시뮬레이터에서 측정값이 공식값에 다가가는 데 시간이 걸렸던 이유가 2.3~2.4절의 주제입니다.

2이론

핵심은 하나입니다. 신뢰구간 공식은 서로 독립인 값들을 가정한다는 것. 이 편의 기법 대부분은 독립인 값을 만들어 내는 방법입니다.

2.1반복 실행과 t 신뢰구간

시드를 바꿔 n번 실행하면 각 실행의 결과 X1, …, Xn은 서로 독립이고 같은 분포를 따릅니다. 이것이 반복 실행(replication)입니다. 이제 0편 2.6절의 신뢰구간을 쓸 수 있는데, 시뮬레이션은 한 번 돌리는 데 시간이 걸려 n이 작은 경우가 많으므로 1.96 대신 t 분포의 값을 씁니다.

보고할 때는 점추정값만이 아니라 “평균 대기 4.3분 (95% 신뢰구간 3.6~5.0분, 반복 20회)”처럼 구간과 반복 횟수를 함께 씁니다. 모든 반복에 쓴 시드 목록을 남겨 두면 다른 사람이 결과를 그대로 재현할 수 있습니다.

2.2몇 번 돌려야 하나

원하는 정밀도 ε(예: ±0.5분)가 정해져 있다면 필요한 반복 횟수를 미리 계산할 수 있습니다. 먼저 10번 정도 시험 삼아 돌려(파일럿 실행) 표준편차 S0를 얻고, 반폭 공식을 n에 대해 거꾸로 풉니다.

2.3자기상관: 손님 한 명 한 명은 독립이 아니다

“하루를 20번 돌리기 귀찮으니, 아주 긴 하루를 한 번 돌리고 손님 1만 명의 대기시간으로 신뢰구간을 만들면 되지 않을까?” 많이 하는 실수입니다. 앞 손님이 오래 기다렸다면 줄이 길다는 뜻이고, 바로 뒤 손님도 오래 기다릴 가능성이 큽니다. 연속된 값들이 서로 닮는 이 성질을 자기상관(autocorrelation)이라고 합니다.

손님별 대기시간은 서로 닮았다

위: M/M/1 대기열에서 연속된 손님 500명의 대기시간(평균 처리 시간 1분). 아래: 시차 k만큼 떨어진 두 손님의 상관계수.

해결책은 독립인 값을 만드는 것입니다. 종료형이면 반복 실행이 답입니다. 실행끼리는 다른 시드로 돌리므로 독립입니다. 비종료형이면 반복 실행과 워밍업 제거(2.4절)를 함께 쓰거나, 긴 실행 하나를 큰 묶음으로 나누는 배치 평균(2.5절)을 씁니다.

2.4워밍업: 처음 데이터를 버려야 하는 이유

비종료형 시스템을 텅 빈 상태에서 시작하면, 처음 손님들은 줄이 거의 없어서 대기가 짧습니다. 이 초반 데이터를 섞으면 정상 상태의 평균을 과소평가합니다. 이를 초기화 편향이라고 합니다. 초반 d명을 버리면 되는데, d를 어떻게 정할까요? 가장 널리 쓰는 것은 웰치의 방법입니다.

  1. 여러 번 반복 실행한다R번(예: 20번) 돌려서 i번째 손님의 대기시간을 R개씩 얻습니다.
  2. 같은 순번끼리 평균 낸다i번째 손님의 대기시간을 R번 실행에 걸쳐 평균하면 “i번째 손님의 기대 대기시간”의 추정값이 됩니다.
  3. 이동 평균으로 매끄럽게 하고 평평해지는 곳을 찾는다곡선이 더 이상 올라가지 않고 평평해지는 지점 이후를 사용합니다. 넉넉하게 잡는 편이 안전합니다.

웰치의 방법으로 워밍업 길이 정하기

M/M/1, 이용률 0.9, 평균 처리 시간 1분. 정상 상태의 평균 대기는 공식으로 9분입니다(점선). 흐린 선은 실행 하나, 진한 선은 20번 실행의 이동 평균입니다.

2.5배치 평균: 긴 실행 하나를 잘라 쓰기

워밍업이 길면 반복 실행마다 그만큼을 버려야 해서 낭비입니다. 대안은 워밍업 후 아주 긴 실행 한 번을 b개의 큰 묶음(배치)으로 나누고, 배치마다 평균을 내는 것입니다. 배치가 충분히 크면 이웃 배치의 평균끼리는 거의 독립이 되므로, b개의 배치 평균을 반복 실행 결과처럼 써서 t 구간을 만듭니다. 배치 수를 바꿔 보며 배치 평균들 사이의 상관(시차 1)을 확인하세요.

배치 평균

M/M/1, 이용률 0.9. 워밍업 1,000명 뒤 손님 4만 명을 b개 배치로 나눴습니다. 점선은 공식값 9분.

배치가 너무 많으면(배치가 작으면) 이웃 배치끼리 상관이 생겨 구간이 지나치게 좁아지고, 너무 적으면 t 값이 커져 구간이 넓어집니다. 실무에서는 배치 수를 10~30개 정도로 두고, 배치 평균들의 시차 1 상관이 0에 가까운지 확인합니다.

2.6두 대안 비교와 공통 난수

시뮬레이션의 진짜 목적은 대개 비교입니다. “새 에스프레소 머신을 들이면(평균 3분 → 2.8분) 대기가 줄어드는가?” 두 대안을 각각 n번 돌려 차이 Dj = Xj − Yj를 만들고, 차이들로 t 구간을 만듭니다. 구간이 0을 포함하지 않으면 차이가 있다고 결론 내립니다.

여기서 강력한 요령이 있습니다. 두 대안을 같은 손님 흐름으로 돌리는 것입니다. j번째 실행에서 A와 B가 똑같은 도착 시각, 똑같은 메뉴 주문을 겪게 하면, 운 좋은 날과 운 나쁜 날의 효과가 양쪽에서 상쇄되어 순수한 정책 차이만 남습니다. 이를 공통 난수(common random numbers, CRN)라고 합니다. 0편 2.1절의 시드가 여기서 빛을 발합니다.

독립 난수와 공통 난수 비교

대안 A: 바리스타 2명, 평균 3분. 대안 B: 같은 인원, 새 머신으로 평균 2.8분. 손님은 분당 0.6명, 하루 600분. 각 방식으로 10쌍을 돌린 차이(A − B)의 95% 구간입니다.

공통 난수를 제대로 쓰려면 난수의 쓰임새를 맞춰야 합니다. 도착 간격, 메뉴 선택, 제조 시간에 각각 별도의 난수 흐름(스트림)을 주세요. 하나의 생성기를 같이 쓰면, B에서 직원이 한 명 더 있어 사건 순서가 바뀌는 순간 같은 난수가 다른 손님에게 쓰이면서 동기화가 깨집니다. 손님이 도착할 때 그 손님의 메뉴와 제조 시간을 미리 뽑아 두는 것도 좋은 방법입니다.

대안이 셋 이상이면 쌍마다 비교하게 되는데, 95% 구간을 m개 만들면 그중 하나라도 틀릴 확률이 5%보다 커집니다. 간단한 해결책은 각 구간을 1 − 0.05/m 수준으로 만드는 본페로니 보정입니다. 대안이 아주 많으면 8편의 최적화 기법으로 넘어갑니다.

2.7요인 설계: 여러 가지를 한꺼번에 바꿀 때

직원 수, 머신, 손님 수처럼 결과에 영향을 줄 만한 것을 요인(factor), 각 요인이 갖는 값을 수준(level)이라고 합니다. 한 번에 하나씩만 바꾸는 실험은 요인끼리의 상호작용을 놓칩니다. 예를 들어 직원을 늘리는 효과는 손님이 많은 날에 훨씬 클 수 있습니다. 요인 k개에 각각 낮음(−)과 높음(+) 두 수준을 두고 모든 조합 2k개를 돌리는 것이 2k 요인 설계입니다.

23 요인 실험: 점심 피크의 커피점

A 직원 수(2명 / 3명), B 머신(평균 3.0분 / 2.6분), C 손님(분당 0.55명 / 0.65명). 각 조합을 공통 난수로 10번씩 돌린 평균 대기시간입니다.

3.2점심 피크 대책중간

사장님의 질문: “점심에 아르바이트를 한 명 더 쓸까, 새 머신을 살까?” 2.7절 실험 결과를 다시 보며 답해 봅시다.

  1. 주효과를 비교한다직원 추가(A)와 머신 교체(B) 중 대기를 더 크게 줄이는 쪽은? 효과 막대의 길이로 비교합니다.
  2. 상호작용을 확인한다AC 상호작용이 크다면 “직원을 늘리는 효과는 손님이 많은 날 더 크다”는 뜻입니다. 시험 기간처럼 손님이 많을 때만 직원을 늘리는 정책을 생각할 수 있습니다.
  3. 비용과 함께 판단한다시뮬레이션은 대기시간을 알려 줄 뿐, 결정은 비용(시급, 머신 가격)과 함께 합니다. 이 계산을 체계화하는 것이 8편의 시뮬레이션 최적화입니다.

주의: 이 결론은 모델 안에서만 참입니다. 실제 매장에서 바리스타 셋이 좁은 공간에서 서로 방해한다면 3명의 효과가 모델보다 작을 것입니다. 모델이 현실을 충분히 닮았는지 확인하는 일은 8편의 주제입니다.

3.3내 시뮬레이션에 적용하기실전

2편의 SimPy 모델이든 직접 만든 모델이든, 아래 틀에 넣으면 이 편의 분석을 그대로 할 수 있습니다. 핵심은 실행 함수가 seed를 받아 결과 하나를 돌려주게 만드는 것입니다. 대안 비교에서는 같은 시드를 양쪽에 넣어 공통 난수를 씁니다.

import numpy as np
from scipy import stats

def run(seed, baristas=2, mean_service=3.0):
    """시뮬레이션 한 번(하루)을 돌려 평균 대기시간을 돌려준다.
    도착과 제조 시간에 별도의 난수 스트림을 써서 공통 난수가 동기화되게 한다."""
    ss = np.random.SeedSequence(seed)
    arr_rng, svc_rng = [np.random.default_rng(s) for s in ss.spawn(2)]
    t, free, waits = 0.0, [0.0] * baristas, []
    while True:
        t += arr_rng.exponential(1 / 0.6)             # 도착 간격 (분)
        if t > 600:
            return np.mean(waits)
        s = mean_service * svc_rng.gamma(4, 1 / 4)   # 평균 1, C = 0.5인 감마에 평균을 곱함
        i = int(np.argmin(free))                     # 가장 먼저 비는 바리스타
        start = max(t, free[i])
        waits.append(start - t)
        free[i] = start + s

def ci(x, conf=0.95):
    x = np.asarray(x)
    h = stats.t.ppf((1 + conf) / 2, len(x) - 1) * x.std(ddof=1) / np.sqrt(len(x))
    return x.mean(), h

seeds = range(1000, 1020)                            # 시드 목록을 기록해 두면 재현 가능
a = [run(s, mean_service=3.0) for s in seeds]
b = [run(s, mean_service=2.8) for s in seeds]        # 같은 시드 = 공통 난수
m, h = ci(np.array(a) - np.array(b))
print(f"A - B = {m:.2f} ± {h:.2f}분")

1~3편에서1편 시뮬레이터가 공식값에 천천히 다가간 이유(자기상관, 초기화 편향), 2편의 반복 실행 도구, 3편 생태계의 몬테카를로 일괄 실행이 모두 이 편의 기법입니다. ABM에서 “공존 확률”처럼 비율을 추정할 때도 반복 실행으로 구간을 만듭니다.

8편으로대안이 수십, 수백 개면 하나하나 비교할 수 없으므로 탐색 알고리즘이 필요합니다. 그때도 공통 난수와 반복 실행이 탐색의 정확도를 좌우합니다.

4.2요약

종료형
자연스러운 시작과 끝. 반복 실행 → 결과마다 독립 → t 구간.
비종료형
정상 상태 값이 목표. 워밍업 제거(웰치) + 반복 실행, 또는 배치 평균.
자기상관
한 실행 안의 값들은 독립이 아니다. 개별 값으로 만든 구간은 너무 좁다.
정밀도
반폭 ∝ 1/√n. 필요한 n ≈ (1.96 S₀/ε)².
비교
쌍별 차이로 구간. 공통 난수로 Cov를 키워 차이의 분산을 줄인다.
요인 설계
2k 조합으로 주효과와 상호작용을 한 번에. 하나씩 바꾸면 상호작용을 놓친다.

4.3연습 문제

1. 파일럿 10회의 표준편차가 3분입니다. 반폭 ±0.3분을 원하면 대략 몇 번 돌려야 할까요?

n ≈ (1.96 × 3 / 0.3)² = 19.6² ≈ 385회입니다. n이 충분히 커서 t값과 1.96의 차이는 무시해도 됩니다. 실행이 오래 걸린다면 목표 정밀도를 다시 생각하거나, 공통 난수 같은 분산 감소 기법을 씁니다.

2. 웹 서버 시뮬레이션을 한 번 길게 돌려 요청 100만 건의 응답 시간으로 신뢰구간을 만들었더니 ±0.001초가 나왔습니다. 무엇이 문제일까요?

요청별 응답 시간은 강한 자기상관이 있으므로 독립 가정의 구간은 지나치게 좁습니다. 또 빈 서버에서 시작했다면 초기화 편향도 있습니다. 워밍업을 정한 뒤 배치 평균(배치 20개 정도)이나 여러 번의 반복 실행으로 구간을 다시 만들어야 합니다.

3. 공통 난수를 썼는데도 차이의 구간이 독립 난수와 비슷하게 넓습니다. 무엇을 의심해야 할까요?

난수 동기화가 깨졌을 가능성이 큽니다. 하나의 생성기를 모든 용도에 같이 쓰면, 두 대안에서 사건 순서가 달라지는 순간 같은 난수가 다른 용도에 쓰입니다. 도착, 메뉴, 제조 시간에 별도 스트림을 주거나 손님 생성 시점에 필요한 값을 미리 뽑아 두세요.

4. 23 실험에서 직원 효과가 손님 수준 C에 따라 −6분(C−)과 −14분(C+)이었습니다. AC 상호작용은?

eAC = (−14 − (−6))/2 = −4분입니다. 직원 추가는 손님이 많을 때 4분 × 2만큼 더 효과적입니다. A의 주효과는 두 값의 평균인 −10분이지만, 상호작용이 크므로 “직원을 늘리면 10분 준다”고만 보고하면 오해를 부릅니다.
