1시뮬레이션이란

현실을 단순화한 모델을 만들고, 그 모델을 컴퓨터에서 실행해 보며 질문에 답하는 방법입니다.

1.1모델: 질문에 필요한 것만 남기기

지하철 노선도는 실제 거리와 방향을 거의 무시합니다. 그런데도 어디서 갈아탈지 정하는 데는 실제 지도보다 더 쓸모가 있습니다. 이처럼 모델은 현실의 한 부분을 목적에 맞게 단순화한 것입니다. 좋은 모델인지는 현실과 얼마나 똑같은지가 아니라, 질문에 답하는 데 필요한 것만 남겼는지로 판단합니다.

시뮬레이션은 모델을 시간에 따라 실행해 보는 것입니다. 모델이 규칙을 모아 놓은 것이라면, 시뮬레이션은 그 규칙을 실제로 따라가며 무슨 일이 일어나는지 관찰하는 실험입니다.

2편에서 다룰 교내 프롬프트 커피점으로 예를 들어 보겠습니다. 질문이 “점심시간에 직원을 한 명 더 쓰면 손님이 덜 기다릴까?”라면 모델에 남길 것과 버릴 것은 대략 다음과 같습니다.

남긴 것

  • 손님이 오는 간격
  • 손님이 고르는 메뉴
  • 메뉴마다 만드는 데 걸리는 시간
  • 직원 수와 커피 머신 수

버린 것

  • 손님의 옷차림과 대화 내용
  • 매장 음악과 인테리어
  • 커피 맛
  • 직원의 이름

질문이 바뀌면 남길 것도 바뀝니다. 질문이 “비 오는 날 매출은 얼마나 줄까?”라면 날씨를 모델에 넣어야 합니다. 그래서 모델링은 항상 질문을 정하는 데서 시작합니다.

1.2언제 시뮬레이션을 쓰나

직접 해 보기 어려울 때

새 공항 터미널의 동선을 시험하려고 터미널을 두 번 지을 수는 없습니다. 비용이 크거나, 위험하거나, 시간이 너무 오래 걸리는 실험은 컴퓨터 안에서 먼저 해 봅니다.

공식으로 풀기 어려울 때

1편의 큐잉 공식은 단순한 가정 위에서만 성립합니다. 줄이 길면 그냥 가 버리는 손님, 시간대마다 달라지는 손님 수가 들어가면 공식이 없거나 매우 복잡해집니다.

여러 대안을 비교할 때

“직원을 한 명 늘릴까, 키오스크를 놓을까?”처럼 같은 상황에서 정책만 바꿔 결과를 나란히 비교할 수 있습니다.

시뮬레이션이 맞지 않는 경우도 있습니다. 공식으로 바로 풀리는 문제라면 공식이 더 빠르고 정확합니다. 또 입력 데이터가 전혀 없다면 시뮬레이션이 내놓는 숫자도 믿기 어렵습니다. 쓰레기를 넣으면 쓰레기가 나온다(garbage in, garbage out)는 말이 시뮬레이션에도 그대로 적용됩니다.

1.3첫 실험: 생일 문제

한 반에 몇 명이 모이면, 생일이 같은 두 사람이 있을 확률이 50%를 넘을까요? 1년이 365일이니 183명쯤은 있어야 할 것 같지만, 실제로는 훨씬 적습니다. 공식을 몰라도 컴퓨터로 직접 확인할 수 있습니다. 무작위로 생일을 정한 가상의 반을 1,000개 만들고, 그중 생일이 겹치는 반이 몇 개인지 세면 됩니다.

가상의 반 만들기

위쪽 띠는 1월 1일부터 12월 31일까지이고, 점 하나가 학생 한 명입니다. 생일이 겹친 날은 빨간색으로 표시됩니다.

23명이면 이미 50%를 넘습니다. 아래쪽 곡선은 공식으로 구한 정확한 값이고, 점은 시뮬레이션으로 얻은 값입니다. 시뮬레이션은 공식을 모르고도 그 곡선에 가까이 갑니다. 이렇게 무작위 실험을 많이 반복해서 나온 비율로 확률을 추정하는 방법을 몬테카를로 방법이라고 부릅니다. 모나코의 카지노 도시 이름에서 따왔고, 이 시리즈의 모든 편에서 쓰는 기본 도구입니다.

Python으로는 열 줄도 걸리지 않습니다.

import random

def same_birthday(n):
    days = [random.randint(1, 365) for _ in range(n)]
    return len(set(days)) < n      # 겹치는 날이 있으면 집합 크기가 n보다 작다

trials = 10000
hits = sum(same_birthday(23) for _ in range(trials))
print(hits / trials)                # 약 0.507

1.4시뮬레이션의 종류

시뮬레이션은 세 가지 물음으로 분류할 수 있습니다.

정적 / 동적
시간의 흐름이 모델에 들어가는가? 생일 문제는 시간이 필요 없으니 정적이고, 줄이 길어졌다 짧아지는 커피점은 동적입니다.
결정적 / 확률적
무작위 요소가 있는가? 같은 입력이면 늘 같은 결과가 나오면 결정적, 돌릴 때마다 결과가 다르면 확률적입니다.
이산 / 연속
상태가 띄엄띄엄 바뀌는가, 매끄럽게 바뀌는가? 줄 선 사람 수는 3명에서 4명으로 뛰고, 물탱크의 물 높이는 조금씩 계속 바뀝니다.

아래 예시를 먼저 스스로 분류해 본 뒤 답을 확인해 보세요.

예시시간무작위상태 변화이 시리즈에서
생일 문제정적확률적이산0편 (몬테카를로)
커피점의 손님 줄동적확률적이산1, 2편 (DES)
여우와 토끼가 사는 숲동적확률적이산 (틱 단위)3편 (ABM)
공을 던졌을 때의 궤적동적결정적연속7편 (연속 시스템)
비와 방류에 따른 댐 수위동적결정적 또는 확률적연속6편 (시스템 다이내믹스)
점을 던져 원주율 추정정적확률적이산0편 (몬테카를로)

경계가 애매한 경우도 있습니다. 공 궤적을 컴퓨터로 계산할 때는 아주 작은 시간 간격으로 쪼개서 계산하므로, 엄밀히 말하면 연속 시스템을 이산적으로 근사하는 셈입니다. 분류는 모델을 고를 때 쓰는 생각의 도구이지, 정답을 외우는 대상이 아닙니다.

1.5시뮬레이션 연구의 과정

코드를 짜는 일은 전체 과정의 일부일 뿐입니다. 실제 시뮬레이션 연구는 대략 다음 순서로 진행됩니다.

  1. 질문 정하기무엇을 알고 싶은가, 무엇을 결정해야 하는가
  2. 개념 모델무엇을 남기고 버릴지 종이에 그려 보기
  3. 데이터 모으기도착 간격, 처리 시간 같은 입력 측정
  4. 프로그램 짜기모델을 코드로 옮기기
  5. 검증과 타당성 확인코드가 모델대로 도는가, 모델이 현실과 맞는가
  6. 실험하기시나리오를 바꿔 가며 여러 번 돌리기
  7. 분석과 결정결과를 해석하고 결론 내기

5단계에서 문제가 발견되면 2단계나 4단계로 되돌아갑니다. 실제로는 이 되돌아가기를 여러 번 반복합니다.

검증(verification)과 타당성 확인(validation)은 다릅니다. 검증은 “설계도대로 지었는가?”를 묻습니다. 예를 들어 손님이 서비스를 받기 전에 떠나는 버그는 없는지 확인합니다. 타당성 확인은 “설계도 자체가 맞는가?”를 묻습니다. 시뮬레이션 속 평균 대기시간이 실제 커피점에서 잰 값과 비슷한지 비교하는 식입니다. 1편에서 시뮬레이션 결과를 공식과 비교한 것은 검증의 한 방법이었습니다.

2필요한 확률과 통계

목표는 수학 시험이 아니라, 시뮬레이션 코드를 읽고 결과를 해석할 수 있을 만큼 아는 것입니다. 고등학교 확률과 통계를 잊었어도 괜찮습니다.

2.1컴퓨터가 만드는 난수

컴퓨터는 정해진 계산만 하는 기계라서 진짜 무작위 수를 만들지 못합니다. 대신 무작위처럼 보이는 수열을 계산으로 만들어 내는데, 이를 의사난수(pseudo-random number)라고 합니다. 가장 오래된 방법인 선형 합동 생성기는 이전 수에 곱하고 더한 뒤 나머지를 취합니다.

x다음 = (a · x + c) mod m,    U = x / m mod는 나눈 나머지입니다. U는 0 이상 1 미만의 수가 되며, 시뮬레이션의 모든 무작위성은 이 U에서 시작합니다.

처음 넣는 x를 시드(seed)라고 합니다. 시드가 같으면 수열도 똑같이 나옵니다. 불편해 보이지만 시뮬레이션에서는 아주 중요한 성질입니다. 버그를 찾을 때 같은 상황을 다시 만들 수 있고, 두 정책을 똑같은 손님 흐름으로 비교할 수도 있기 때문입니다.

생성기의 품질도 중요합니다. 아래에서 연속된 두 수 (U1, U2), (U2, U3)…를 점으로 찍어 보면, 좋은 생성기는 사각형을 고르게 채우지만 나쁜 생성기는 몇 개의 줄 위에만 점이 놓입니다.

난수 생성기 들여다보기

왼쪽은 연속된 두 수의 쌍 1,000개, 오른쪽은 1,000개 수를 열 칸으로 나눈 히스토그램입니다.

import random

random.seed(42)
print([round(random.random(), 3) for _ in range(3)])   # [0.639, 0.025, 0.275]

random.seed(42)                     # 같은 시드로 다시 시작하면
print([round(random.random(), 3) for _ in range(3)])   # 똑같은 수열이 나온다

Python의 random 모듈은 메르센 트위스터라는 검증된 생성기를 씁니다. 실제 작업에서는 생성기를 직접 만들지 말고 라이브러리를 쓰세요.

2.2확률은 오래 했을 때의 비율

주사위에서 1이 나올 확률이 1/6이라는 말은 무슨 뜻일까요? 여섯 번 던지면 꼭 한 번 나온다는 뜻은 아닙니다. 아주 많이 던졌을 때, 1이 나온 비율이 1/6에 가까워진다는 뜻입니다. 이를 큰 수의 법칙이라고 하며, 시뮬레이션을 오래 또는 여러 번 돌리는 근거가 됩니다.

직접 던져 보세요. 처음 몇 번은 평균이 크게 흔들리다가, 던진 횟수가 늘수록 3.5 근처로 모입니다.

주사위 던지기

왼쪽은 눈마다 나온 비율(점선이 1/6), 오른쪽은 던질 때마다 갱신한 평균(점선이 3.5)입니다.

독립이라는 말도 기억해 두세요. 앞의 결과가 다음 결과에 영향을 주지 않는다는 뜻입니다. 주사위가 다섯 번 연속 1이 나왔다고 해서 다음에 1이 덜 나오지는 않습니다. “이제 나올 때가 됐다”는 생각을 도박사의 오류라고 부릅니다. 대부분의 시뮬레이션 모델은 손님들이 서로 독립적으로 도착한다고 가정합니다.

2.3확률변수와 분포

확률변수는 무작위 실험의 결과로 나오는 수입니다. 주사위 눈, 다음 손님이 오기까지 걸리는 시간, 1시간 동안 오는 손님 수가 모두 확률변수입니다. 값이 1, 2, 3처럼 띄엄띄엄하면 이산, 2.37분처럼 어떤 값이든 될 수 있으면 연속 확률변수입니다.

분포는 어떤 값이 얼마나 자주 나오는지를 나타냅니다. 이산이면 막대 높이가 곧 확률입니다. 연속이면 정확히 2.370000…분이 나올 확률은 0이라서, 대신 구간의 넓이로 생각합니다. 표본을 많이 뽑아 히스토그램 칸을 좁히면 막대 윗부분이 매끄러운 곡선에 다가가는데, 이 곡선을 확률밀도라고 합니다. 곡선 아래 넓이가 그 구간에 들어갈 확률입니다.

시뮬레이션에서 자주 쓰는 분포 다섯 가지를 직접 뽑아 보세요. 표본 수를 늘리면 히스토그램(막대)이 이론 곡선(선)에 가까워집니다.

분포 탐색기

막대는 뽑은 표본의 히스토그램, 선은 이론적인 분포입니다.

표본 수

지수분포와 포아송분포는 한 쌍입니다. 손님 사이의 간격이 평균 3분인 지수분포를 따르면, 1시간 동안 오는 손님 수는 평균 20명인 포아송분포를 따릅니다. 같은 현상을 “간격”으로 보느냐 “개수”로 보느냐의 차이입니다. 1편과 2편의 손님 도착이 바로 이 모델입니다.

2.4평균과 퍼짐

분포를 숫자 하나로 요약하면 평균입니다. 하지만 평균만으로는 부족합니다. 바리스타 두 명이 음료 다섯 잔을 만든 시간을 재었다고 해 봅시다.

걸린 시간(분)평균분산표준편차
바리스타 A2, 3, 3, 4, 33(1+0+0+1+0) / 5 = 0.4약 0.63분
바리스타 B1, 5, 3, 1, 53(4+4+0+4+4) / 5 = 3.2약 1.79분

평균은 둘 다 3분이지만 B는 들쭉날쭉합니다. 이 차이를 숫자로 나타낸 것이 분산과 표준편차입니다. 분산은 각 값이 평균에서 떨어진 거리를 제곱해서 평균 낸 것이고, 표준편차는 분산의 제곱근입니다. 제곱근을 취하면 단위가 다시 “분”이 되므로 보통 표준편차로 이야기합니다.

분산 = (각 값 − 평균)2의 평균,    표준편차 = √분산 표본으로 계산할 때는 개수 n 대신 n − 1로 나누는 경우가 많습니다. 표본이 크면 차이는 거의 없습니다.

퍼짐이 왜 중요한지 시뮬레이션으로 확인해 보겠습니다. 손님은 평균 3.3분마다 오고, 바리스타는 평균 3분에 한 잔을 만듭니다. 평균만 보면 세 경우가 똑같습니다.

평균은 같아도 기다림은 다르다

왼쪽 점들은 음료를 만든 시간 40건, 오른쪽 막대는 손님 4만 명을 시뮬레이션한 평균 대기시간입니다. 세로 선은 공식으로 계산한 값입니다.

처리 시간이 들쭉날쭉하면 평균이 같아도 손님은 거의 두 배를 기다립니다. 오래 걸린 한 잔 때문에 뒤에 선 사람 모두가 밀리기 때문입니다. 그래서 1편의 대기시간 공식에는 처리 시간의 평균뿐 아니라 분산도 들어갑니다. 시뮬레이션의 입력을 정할 때 평균만 맞추면 안 되는 이유이기도 합니다.

2.5원하는 분포의 난수 만들기

컴퓨터가 주는 것은 0과 1 사이의 고른 수 U뿐입니다. 이것으로 어떻게 “아메리카노를 고를 확률 40%”나 “평균 3분인 지수분포”를 만들까요? 열쇠는 누적분포입니다. 누적분포 F(x)는 “x 이하의 값이 나올 확률”로, 왼쪽에서 오른쪽으로 가며 0에서 1까지 올라가는 계단이나 곡선입니다.

방법은 간단합니다. U를 뽑아 세로축에 놓고, 가로로 그어 누적분포와 만나는 곳에서 아래로 내립니다. 그 x가 우리가 원하는 분포를 따르는 난수입니다. 이를 역변환법이라고 합니다. 누적분포가 가파른 곳일수록 많은 U가 모이니, 그 근처 값이 자주 나옵니다.

역변환법

위는 누적분포, 아래는 뽑은 결과입니다. 위쪽 그래프를 누르면 그 높이를 U로 써서 하나를 뽑습니다.

메뉴처럼 이산적인 경우에는 누적확률 구간을 차례로 비교하면 됩니다. 지수분포는 누적분포가 F(x) = 1 − e−x/3이고, 이를 거꾸로 풀면 아래 식이 됩니다. ln은 자연로그로 계산기의 ln 버튼과 같습니다. 식의 유도는 몰라도 괜찮고, 그림의 원리만 이해하면 충분합니다.

x = − 평균 × ln(1 − U)
import math
import random

MENU = [("아메리카노", 0.40), ("라떼", 0.25), ("아이스티", 0.15),
        ("밀크셰이크", 0.10), ("핫도그", 0.10)]

def pick_menu():
    u = random.random()
    acc = 0.0
    for name, p in MENU:
        acc += p                    # 누적 확률: 0.40, 0.65, 0.80, 0.90, 1.00
        if u < acc:
            return name
    return MENU[-1][0]

def next_arrival_gap(mean=3.0):
    u = random.random()
    return -mean * math.log(1 - u)  # 지수분포의 역변환

메뉴 확률은 설명을 위한 예시입니다. 실제 값은 커피점에서 주문을 세어 정해야 하는데, 이것이 4편 입력 모델링의 주제입니다.

2.6몇 번 돌려야 믿을 수 있나

확률적 시뮬레이션은 돌릴 때마다 결과가 다릅니다. 평균 대기시간이 한 번은 4.1분, 다음에는 2.6분이 나올 수 있습니다. 그러니 한 번 돌린 결과로 결론을 내면 안 됩니다. 여러 번 돌려 평균을 내고, 그 평균이 얼마나 믿을 만한지 범위로 함께 말해야 합니다.

여기서 두 가지 사실이 쓰입니다. 첫째, 값 n개의 평균은 참값 주위에 흩어지는데, 그 흩어짐(표준오차)은 σ / √n입니다. 표본을 4배로 늘려야 흩어짐이 절반으로 줄어듭니다. 둘째, 중심극한정리에 따르면 원래 분포가 한쪽으로 치우쳐 있어도 평균들의 분포는 n이 커질수록 종 모양(정규분포)에 가까워집니다.

이 둘을 합치면 95% 신뢰구간을 만들 수 있습니다.

평균 ± 1.96 × 표준편차 / √n 1.96은 정규분포에서 가운데 95%를 덮는 폭입니다. n이 작으면 1.96 대신 t분포의 조금 더 큰 값을 씁니다.

“95% 신뢰구간”은 “참값이 이 구간에 있을 확률이 95%”라는 뜻으로 오해하기 쉽습니다. 정확한 뜻은 “이 방법으로 구간을 100번 만들면 약 95번은 참값을 포함한다”입니다. 아래에서 참값이 3분인 지수분포로 실험을 반복해 확인해 보세요.

신뢰구간 100번 만들기

왼쪽 가로 막대 하나가 실험 한 번의 95% 신뢰구간입니다. 참값(세로 점선)을 놓친 구간은 빨간색입니다. 오른쪽은 지금까지 얻은 표본 평균들의 히스토그램입니다.

n을 늘리면 구간이 좁아지고, 표본 평균의 히스토그램도 더 좁고 대칭인 종 모양이 됩니다. 눈여겨볼 점이 하나 더 있습니다. 지수분포처럼 치우친 분포에서 n이 작으면, 포함 비율이 95%에 못 미칩니다. 미리 2만 번씩 돌려 확인해 보니 n = 5일 때 약 81%, n = 10일 때 약 87%, n = 30일 때 약 92%, n = 100일 때 약 94%였습니다. 공식에는 “n이 충분히 크면”이라는 전제가 숨어 있다는 뜻입니다.

2편에서는 이 방법으로 커피점 시뮬레이션을 여러 번 돌려 평균 대기시간의 신뢰구간을 구합니다. 이때 x 하나하나는 손님 한 명이 아니라 시뮬레이션 한 번(하루 영업)의 결과입니다.

import math
import random
import statistics

def one_experiment(n):
    xs = [random.expovariate(1 / 3) for _ in range(n)]   # 참 평균이 3분인 지수분포
    mean = statistics.mean(xs)
    half = 1.96 * statistics.stdev(xs) / math.sqrt(n)   # stdev는 n - 1로 나눈다
    return mean - half, mean + half

lo, hi = one_experiment(30)
print(f"95% 신뢰구간: {lo:.2f} ~ {hi:.2f}분, 참값 3분 포함: {lo <= 3 <= hi}")

3.2두 가지 시간 진행 방식

동적 시뮬레이션은 시간을 앞으로 보내는 방식에 따라 크게 둘로 나뉩니다. 이 구분을 기억해 두면 각 편이 어디에 속하는지 금방 보입니다.

일정한 간격으로 (고정 시간 간격)

시계를 0.1초나 1틱씩 똑같이 보내고, 매번 모든 것을 갱신합니다. 상태가 계속 변하거나 모든 개체가 매 순간 무언가를 하는 시스템에 맞습니다. 3편 ABM, 6편 시스템 다이내믹스, 7편 연속 시스템이 이 방식입니다.

다음 사건으로 건너뛰며 (사건 기반)

아무 일도 없는 시간은 건너뛰고, 손님 도착이나 음료 완성처럼 상태가 바뀌는 순간으로 바로 넘어갑니다. 대부분의 시간 동안 아무 일도 없는 시스템에서 훨씬 빠릅니다. 1편과 2편, 그리고 같은 일을 부품 단위로 적는 2-2편 DEVS가 이 방식입니다.
