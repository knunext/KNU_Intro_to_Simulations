A1엘리베이터: 수업 시작 10분 전

8층짜리 강의동에 엘리베이터가 두 대 있습니다. 평소에는 충분한데, 9시 수업 직전에는 1층 로비에 줄이 길게 늘어서고 지각하는 학생이 생깁니다. 엘리베이터를 늘리지 않고 운행 규칙만 바꿔서 줄일 수 있을까요? 세 가지 배차 규칙을 같은 학생들로 비교하고, 부하에 따라 가장 좋은 규칙이 바뀌는 것을 확인합니다.

이 사례에서 해 볼 것

  • 엘리베이터의 상태와 규칙을 시뮬레이션 모델로 적고, 손계산한 수송 능력으로 타당성을 확인합니다.
  • 집합 제어, 구역 나누기, 목적층 예약을 공통 난수로 비교해 차이를 신뢰구간으로 말합니다.
  • 부하가 커질 때 가장 좋은 규칙이 바뀌는 지점을 찾습니다.
  • 시간에 따라 변하는 도착(수업 전 몰림)에서 지각하는 학생 수로 규칙을 평가하고, 시간대별로 규칙을 바꾸는 방안을 시험합니다.

1질문과 개념 모델

엘리베이터 한 대는 정원이 있는 서버이고, 승강장의 줄은 큐입니다. 다른 점은 서버가 움직인다는 것입니다.

1.1질문 정하기단계 1

질문은 "어떤 배차 규칙이 수업 직전의 대기와 지각을 가장 줄이는가"입니다. 무엇을 줄일지도 정해야 합니다. 평균 대기만 보면 오래 기다리는 몇 사람의 불만이 가려지므로 95번째 백분위 대기를 함께 보고, 수업 직전에는 9시 전에 1층에 도착했는데 9시가 넘어서야 강의실 층에 닿은 학생 수, 곧 지각을 봅니다.

1.2개념 모델단계 2

건물
1층부터 8층까지. 아침에는 학생이 모두 1층에서 타서 2~8층 중 한 곳으로 갑니다(상향 피크). 수업이 끝나면 반대로 각 층에서 1층으로 갑니다(하향 피크).
엘리베이터
정원 12명. 한 층 오르내리는 데 2초, 서면 문을 열고 닫는 데 4초에 한 사람이 타고 내릴 때마다 1초가 더 듭니다. 상향 피크에는 할 일이 없으면 1층으로 돌아가 기다립니다.
집합 제어
가장 흔한 방식입니다. 가는 방향의 호출을 지나가며 모두 받고, 그 방향에 더 할 일이 없으면 방향을 바꿉니다(2편의 LOOK 스케줄링과 같은 생각). 어느 차든 먼저 온 차가 태웁니다.
구역 나누기
위층을 엘리베이터 수만큼 나눠, 차마다 자기 구역의 층만 다닙니다. 두 대라면 한 대는 2~5층, 한 대는 6~8층입니다.
목적층 예약
1층 키패드에서 갈 층을 먼저 누르면, 그 층에 이미 서기로 한 차, 곧 올 차, 덜 붐비는 차를 따져 차를 정해 줍니다. 손님은 배정된 차만 탑니다. 여기서는 그때그때 가장 나은 차를 고르는 단순한 규칙으로 구현했습니다.
계단
선택 사항입니다. 켜면 학생마다 참을성(평균 60초)이 있어서, 그 시간을 넘게 기다렸고 가려는 층이 두 층 이내면 계단으로 갑니다. 3편의 에이전트 판단이 들어가는 자리입니다.

가속과 감속, 문이 다시 열리는 일, 짐을 든 학생은 버렸습니다. 시간은 1초씩 나아가며 매초 차마다 "문을 열고 닫는 중인가, 이 층에 설 것인가, 어느 쪽으로 갈 것인가"를 정합니다. 사건 기반으로 짤 수도 있지만, 규칙이 "매 순간 차가 무엇을 할까"로 적혀 있어 시간 단계 방식이 더 읽기 쉽습니다.

2데이터와 구현

도착은 시간에 따라 변하고, 규칙은 부하에 따라 다르게 작동합니다. 둘 다 재야 합니다.

2.1데이터 모으기단계 3

8시 30분부터 9시 5분까지 1층 로비에서 5분마다 엘리베이터를 기다리기 시작한 사람 수를 셉니다. 몇 사람에게는 몇 층으로 가는지 묻습니다. 이렇게 하면 4편 2.7절의 시간에 따라 변하는 도착률과 목적층 분포가 나옵니다. 엘리베이터 쪽은 스톱워치로 한 층 이동 시간, 문이 열리고 닫히는 시간, 한 사람이 타는 시간을 몇 번 재면 됩니다. 이 사례에서는 도착률이 8시 30분 분당 3명에서 8시 52분쯤 분당 20명까지 오르고, 9시 직후 분당 2명으로 떨어진다고 가정했습니다.

2.3검증과 타당성단계 5

검증. 손님이 한 명뿐인 경우를 손으로 따라가 봅니다. 1층에서 5층까지 가는 손님은 타는 데 문 4초와 1초, 네 층 8초가 걸리고 5층에서 문이 열리면 내리므로, 혼자 탔다면 도착부터 14초 안팎이어야 합니다. 시뮬레이터에 손님 한 명만 넣으면 실제로 14초가 나옵니다. 그다음 정원 12명을 넘게 태우는 차가 없는지, 상향 피크에서 모든 손님이 1층에서 탔는지를 확인합니다.

타당성. 엘리베이터 공학에는 상향 피크의 수송 능력을 손으로 어림하는 방법이 있습니다. 정원 12명이 다 찬 차가 7개 층 중 평균 몇 층에 서는지(약 5.9층), 꼭대기까지 오르내리는 데 몇 초 걸리는지를 더해 한 바퀴 시간을 구하면 약 80초이고, 차 한 대가 분당 9명, 두 대가 분당 18명쯤을 나를 수 있습니다. 3.1절에서 집합 제어가 분당 16~18명 근처에서 무너지기 시작하는 것과 맞습니다. 같은 계산을 구역 나누기에 하면 차마다 서는 층과 꼭대기 층이 줄어 분당 21명쯤까지 버팁니다. 실제 건물이라면 측정한 대기와 줄 길이를 모델과 비교해야 하고, 이 계산은 그 전에 모델이 터무니없지 않은지 보는 첫 확인입니다.

3실험과 결정

같은 학생들을 세 규칙에 똑같이 보내고, 부하와 시간대를 바꿔 가며 비교합니다.

3.1부하와 규칙단계 6

도착률에 따른 평균 대기 (엘리베이터 두 대, 상향 피크)

도착률마다 시드 5개로 30분씩 돌렸고, 세 규칙에 같은 시드를 썼습니다(5편의 공통 난수). 150초 위는 잘라서 그렸습니다.

한산할 때(분당 6명)는 집합 제어가 가장 좋습니다. 평균 대기가 집합 제어 5초, 구역 나누기 10초, 목적층 예약 9초입니다. 호출이 오면 가장 가까운 차가 바로 오기 때문입니다. 그런데 분당 14명을 넘으면 순서가 뒤집혀, 분당 18명에서는 집합 제어 94초, 목적층 예약 51초, 구역 나누기 34초입니다. 붐빌 때는 한 번에 서는 층이 적은 쪽이 한 바퀴를 빨리 돌아 더 많이 나릅니다. 정답이 부하에 따라 다릅니다.

3.3분석과 결정단계 7

이 모델로는 평소에는 집합 제어, 수업 직전 15분만 구역 나누기가 가장 낫습니다. 지각이 31명에서 10명으로 줄고, 한산한 시간의 장점도 잃지 않습니다. 엘리베이터를 한 대 더 놓는 공사 없이 제어기 설정만 바꾸면 됩니다.

목적층 예약이 기대보다 못한 것은 이 사례의 배정 규칙이 단순하기 때문입니다. 실제 시스템은 같은 층으로 가는 사람을 더 적극적으로 묶고 몇 초 뒤의 도착까지 내다보고 배정합니다. 결론은 "목적층 예약이 나쁘다"가 아니라 "우리가 짠 목적층 예약은 구역 나누기만큼 묶지 못한다"입니다. 결정 전에 비교할 대안을 공정하게 구현했는지 따지는 것도 모델링의 일입니다.

지각 31명과 10명의 차이는 시드 10개로 본 것입니다. 이 차이를 보고하려면 같은 시드끼리 짝지은 차이의 신뢰구간을 붙입니다(4.3절의 파이썬 코드가 그렇게 합니다).

4연결과 정리

4.1모델의 한계

층 사이 이동
아침에는 모두 1층에서 탄다고 했지만, 실제로는 수업 사이에 층과 층을 오가는 사람도 섞입니다.
무리 지어 오는 학생
버스가 도착하면 수십 명이 한꺼번에 들어옵니다. 포아송 도착보다 몰림이 심하면 줄은 더 길어집니다(1편 2.6절의 Ca²).
사람의 행동
꽉 찬 차를 보내고 다음 차를 기다리는 사람, 버튼을 두 번 누르는 사람, 문을 잡는 사람은 없습니다.
단순한 목적층 예약
3.3절에서 말했듯 실제 시스템보다 배정이 단순합니다.

4.2쓰인 편들

1편과 2편엘리베이터는 움직이는 서버이고, 손계산한 수송 능력은 가동률이 1이 되는 지점을 찾는 계산입니다.

4편수업 전 몰림은 시간에 따라 변하는 포아송 도착이고, 솎아내기로 만들었습니다.

5편과 8편규칙 비교는 공통 난수로, 최종 선택은 여러 대안 중 가장 나은 것을 고르는 문제입니다. 시간대별 전환 시각(8시 45분)도 최적화할 대상입니다.

3편기다리다 계단으로 가는 학생은 각자 참을성을 가진 에이전트입니다.

4.3파이썬으로 확인하기

상향 피크만 남긴 짧은 모델로 집합 제어와 구역 나누기를 비교합니다. 같은 시드를 두 규칙에 주고, 짝지은 차이에 t 신뢰구간을 붙입니다.

# elevator.py : 아침 상향 피크. 집합 제어(LOOK)와 구역 나누기를 같은 손님들로 비교한다
import random, statistics as st

F, CAP, T_FLOOR, T_DOOR, T_PER = 8, 12, 2, 4, 1      # 1층(0)~8층(7), 한 층 2초, 문 4초 + 한 사람 1초

def arrivals(lam, T, seed):                            # 1층에서 2~8층으로 가는 손님 (포아송 도착)
    rng, t, out = random.Random(seed), 0.0, []
    while True:
        t += rng.expovariate(lam / 60)
        if t > T: return out
        out.append({"t": t, "d": rng.randint(1, F - 1)})

def run(alg, lam, cars=2, T=1800, seed=1):
    people = arrivals(lam, T, seed)                    # 같은 시드면 두 규칙에 같은 손님 (공통 난수)
    zone = lambda p: min(cars - 1, (p["d"] - 1) * cars // (F - 1))
    car = [{"pos": 0, "dir": 0, "door": 0, "load": []} for _ in range(cars)]
    lobby, waits, i, tick = [], [], 0, 0
    while i < len(people) or lobby or any(c["load"] for c in car):
        while i < len(people) and people[i]["t"] <= tick:
            lobby.append(people[i]); i += 1
        for k, c in enumerate(car):
            if c["door"] > 0:
                c["door"] -= 1; continue
            mine = [p for p in lobby if alg == "look" or zone(p) == k]
            if c["pos"] % T_FLOOR == 0:                # 층에 서 있다 (pos는 초 단위 위치, 한 층 = 2)
                fl = c["pos"] // T_FLOOR
                out = [p for p in c["load"] if p["d"] == fl]
                board = mine[:CAP - len(c["load"]) + len(out)] if fl == 0 else []
                if out or board:
                    c["load"] = [p for p in c["load"] if p["d"] != fl] + board
                    for p in board: waits.append(tick - p["t"]); lobby.remove(p)
                    c["door"] = T_DOOR + T_PER * (len(out) + len(board)); continue
                if c["load"] and max(p["d"] for p in c["load"]) > fl: c["dir"] = 1     # 손님 내릴 층이 위에 있다
                elif fl > 0: c["dir"] = -1                                            # 1층으로 돌아간다
                else: c["dir"] = 0                                                    # 1층에서 기다린다
            c["pos"] += c["dir"]
        tick += 1
    return st.mean(waits)

for lam in (8, 18):
    look = [run("look", lam, seed=s) for s in range(10)]
    zone = [run("zone", lam, seed=s) for s in range(10)]
    diff = [a - b for a, b in zip(look, zone)]          # 같은 손님끼리 짝지은 차이
    hw = 2.262 * st.stdev(diff) / len(diff) ** 0.5      # t(0.975, 9) = 2.262
    print(f"분당 {lam}명: 집합 제어 {st.mean(look):.1f}초, 구역 나누기 {st.mean(zone):.1f}초, "
          f"차이 {st.mean(diff):+.1f} ± {hw:.1f}초")
분당 8명: 집합 제어 6.8초, 구역 나누기 12.5초, 차이 -5.7 ± 0.7초
분당 18명: 집합 제어 84.7초, 구역 나누기 30.0초, 차이 +54.7 ± 20.8초

한산할 때는 집합 제어가, 붐빌 때는 구역 나누기가 낫다는 결론이 두 구간 모두에서 0을 포함하지 않는 차이로 확인됩니다. 붐빌 때의 구간이 넓은 것은 줄이 길어질수록 실행마다의 흔들림이 커지기 때문입니다(5편).

4.4연습과 확장

1. 구역 나누기로 바꾸는 시각을 8시 40분, 8시 45분, 8시 50분으로 바꿔 보면 지각은 어떻게 달라질까요?

너무 늦게 바꾸면 이미 쌓인 줄을 다 빼지 못하고, 너무 일찍 바꾸면 한산한 시간에 손해를 봅니다. 도착률이 수송 능력을 넘기 시작하는 시각 조금 전이 좋은 후보입니다. 여러 시각을 같은 시드로 비교하는 것은 8편의 최적화 문제입니다.

2. 구역을 2~5층과 6~8층이 아니라 2~4층과 5~8층으로 나누면 어떨까요?

위 구역은 이동 거리가 길어 한 바퀴가 오래 걸리므로, 위 구역에 층을 많이 주면 그쪽이 먼저 막힙니다. 수송 능력을 구역별로 손계산해 두 차의 부하가 비슷해지도록 나누는 것이 출발점이고, 그다음 시뮬레이션으로 확인합니다. 층마다 수강생 수가 다르면 도착 비율도 함께 고려합니다.

3. 계단을 켜면 평균 대기는 줄어드는데, 그것이 좋은 일일까요?

오래 기다린 사람이 줄에서 빠지므로 남은 사람의 대기는 짧아지지만, 계단으로 간 사람은 그만큼 불편을 겪었습니다. 평가 지표에 "계단으로 간 사람 수"를 넣지 않으면 규칙을 잘못 고를 수 있습니다. 1편 미용실 문제의 λeff처럼, 누가 상자 밖으로 빠졌는지를 함께 봐야 합니다.

4. 목적층 예약을 더 잘 만들려면 무엇을 바꿔야 할까요?

같은 층으로 가는 사람을 같은 차에 묶는 보상을 키우고, 차가 1층에서 출발하기 전 몇 초 동안 배정을 바꿀 수 있게 하고, 앞으로 몇 초 안에 올 사람을 예측해 미리 자리를 남겨 두는 방법이 있습니다. 바꿀 때마다 같은 시드로 이전 버전과 비교해 정말 나아졌는지 확인합니다.
