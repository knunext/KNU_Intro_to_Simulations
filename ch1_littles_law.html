1왜 큐잉인가

줄은 평균적으로 바빠서가 아니라, 가끔 몰리고 가끔 늘어져서 생깁니다. 이 한 문장이 이 편 전체의 요약입니다.

1.1줄은 왜 생기나

아래 시뮬레이터에서 손님은 왼쪽에서 들어와 줄을 서고, 오른쪽 창구에서 서비스를 받고 떠납니다. 도착률 λ(1분에 오는 손님 수)와 창구 하나의 서비스율 μ(1분에 처리하는 손님 수)를 바꿔 보세요. λ가 μ보다 작아도 줄은 생깁니다. 도착 간격과 서비스 시간을 모두 "일정"으로 바꾸면 줄이 사라지는 것도 확인해 보세요.

1.2큐잉 이론이 답하는 질문

얼마나 기다리나

평균 줄 대기 Wq와 체류시간 W. 손님 입장에서 가장 먼저 묻는 숫자입니다.

몇 대가 필요한가

목표 대기를 지키는 데 필요한 서버 수 c. 콜센터 상담원, 계산대, 클라우드 인스턴스 수를 정할 때 씁니다.

몇 명이 돌아가나

자리가 차서 들어오지 못하는 비율. 주차장, 병상, 접속 제한이 있는 서버에서 중요합니다.

어디가 병목인가

여러 단계를 거치는 시스템에서 가장 먼저 막히는 곳. 주문, 제조, 픽업으로 이어진 커피점이 그렇습니다.

이 질문들에 공식으로 답하는 것이 큐잉 이론입니다. 공식은 계산이 빠르고 원인을 보여 주지만, 가정이 맞을 때만 정확합니다. 가정이 어긋나는 곳을 아는 것이 공식을 아는 것만큼 중요합니다.

2이론

어디에나 성립하는 법칙 하나와, 가정을 하나씩 바꿔 가는 모델 다섯 개를 봅니다.

2.1리틀의 법칙

시스템 둘레에 상자를 하나 그립시다. 상자 안의 평균 인원을 L, 상자에 들어오는 비율을 λ, 한 사람이 상자 안에 머무는 평균 시간을 W라고 하면, 오래 관측했을 때 언제나 다음이 성립합니다.

L = λ W

도착이 얼마나 불규칙한지, 창구가 몇 개인지, 누가 먼저 서비스를 받는지와 상관이 없습니다. 조건은 두 가지뿐입니다. 관측을 충분히 오래 하고, 그동안 상자 안 인원이 끝없이 늘어나지 않으면 됩니다. 왜 그런지는 그림으로 보면 바로 보입니다. 손님마다 머문 시간을 막대로 그리면, 막대 넓이의 합은 "시각마다 상자 안에 몇 명이 있었나"를 시간에 대해 더한 넓이와 같습니다. 같은 넓이를 두 방향에서 센 것입니다.

같은 넓이를 두 번 세기

위는 손님별로 머문 시간(회색은 줄에서, 색칠한 부분은 서비스), 아래는 시각마다 상자 안의 인원 N(t)입니다. 두 그림의 칠한 넓이는 같습니다.

관측 구간을 T, 그동안 들어온 사람을 n명, 칠한 넓이를 A라고 하면 L = A/T, λ = n/T, W = A/n입니다. 곱하면 λW = A/T = L. 위 예처럼 처음과 끝에 상자가 비어 있으면 정확히 같고, 그렇지 않아도 관측이 길어지면 가장자리에 걸친 몇 사람의 영향은 사라집니다.

2.2경계는 어디에 그어도 된다

상자는 마음대로 그릴 수 있습니다. 다만 세 양을 같은 상자에 대해 재야 합니다.

상자안의 평균 인원들어오는 비율머무는 시간
시스템 전체LλW
줄만LqλWq
창구만바쁜 창구 수의 평균λ서비스 시간 1/μ

세 번째 줄에서 바로 가동률이 나옵니다. 바쁜 창구 수의 평균은 λ/μ이고, 창구가 c개면 한 창구가 바쁜 비율은 ρ = λ/cμ입니다. ρ가 1 이상이면 창구가 처리할 수 있는 것보다 많이 들어오므로 줄이 끝없이 길어집니다. 또 W = Wq + 1/μ이므로 넷 중 하나만 알면 나머지가 모두 나옵니다.

주의자리가 없어 돌아간 손님은 상자에 들어오지 않았습니다. 이때는 λ 대신 실제로 들어온 비율 λeff를 씁니다. 2.7절과 3.2절의 미용실 문제가 이 경우입니다.

2.3켄달 표기: 큐의 이름 읽기

M/G/1, M/M/c/K 같은 이름은 켄달(Kendall) 표기법입니다. 빗금으로 나눈 칸마다 큐의 성질을 하나씩 적습니다. 첫 칸은 도착 과정, 둘째 칸은 서비스 시간 분포, 셋째 칸은 서버 수, 넷째 칸은 시스템 정원입니다. 정원이 무제한이고 선착순이면 넷째 칸부터는 생략합니다. 칸을 골라 보면 그 큐에 정확한 공식이 있는지, 근사만 있는지, 시뮬레이션이 필요한지가 나옵니다.

큐 이름 조합해 보기

M
마르코프(Markov), 즉 기억이 없는 지수분포. 도착 칸에서는 포아송 도착입니다. 변동계수 제곱 C² = 1.
D
결정적(Deterministic). 간격이나 시간이 늘 같습니다. C² = 0.
Ek
얼랑(Erlang) 분포. 지수 단계 k개를 이은 것으로 M과 D 사이입니다. C² = 1/k.
G
일반(General) 분포. 평균과 분산만 알면 되는 공식이 많습니다. 도착 칸에서는 GI라고도 씁니다.
Mt
도착률이 시간에 따라 바뀌는 포아송 도착. 점심 피크가 있는 카페가 그렇습니다.

2.4M/M/1: 이용률이 1에 가까워지면

포아송 도착, 지수분포 서비스, 서버 한 대. 가장 단순한 이 큐에서 시스템 안 인원이 n명일 확률은 P(n) = (1 − ρ)ρn이고, 평균은 다음과 같습니다.

L = ρ / (1 − ρ),   W = 1 / (μ − λ),   Wq = ρ / (μ − λ)

이용률과 체류시간

세로축은 체류시간을 서비스 시간 한 번의 몇 배인지로 나타낸 값 W/E[S] = 1/(1 − ρ)입니다.

곡선은 ρ = 0.8 근처부터 가팔라집니다. 밀린 손님은 창구가 한가한 짧은 틈, 시간의 1 − ρ만큼에만 빠지기 때문입니다. 그 틈이 반으로 줄면 대기는 두 배보다 더 늘어납니다. 서버를 90%까지 쓰는 것이 "효율적"으로 보여도 손님 입장에서는 서비스 시간의 열 배를 머무는 시스템이라는 뜻입니다.

2.5M/M/c와 풀링

서버가 c대이고 줄은 하나라면, 도착한 손님은 모든 서버가 바쁠 때만 기다립니다. 그 확률 P대기를 구하는 식이 얼랑 C 공식이고, 평균 줄 대기는 Wq = P대기 / (cμ − λ)입니다. 이 공식으로 질문 하나에 답해 봅시다. 같은 서버 c대를 둘 때, 줄을 하나로 세우는 것과 서버마다 따로 세우는 것은 얼마나 다를까요? 아예 c배 빠른 서버 한 대로 바꾸면 어떨까요?

줄 하나, 줄 여럿, 빠른 서버 하나

세 설계 모두 처리 능력의 합은 같습니다. 시간 단위는 느린 서버 한 대의 평균 서비스 시간입니다.

줄을 하나로 묶는 효과를 풀링(pooling)이라 합니다. 따로 선 줄에서는 옆 창구가 놀고 있어도 내 줄은 줄지 않지만, 줄이 하나면 놀고 있는 서버가 생기지 않습니다. 은행과 공항 체크인이 줄을 하나로 세우는 이유입니다. 빠른 서버 한 대는 줄 대기는 풀링보다 길지만 서비스 자체가 빨라 체류시간은 가장 짧습니다. 어느 쪽이 나은지는 손님이 무엇을 싫어하는지, 즉 줄에 서 있는 시간인지 전체 시간인지에 달렸습니다.

2.6M/G/1과 세 손잡이

서비스 시간이 지수분포가 아니면 어떨까요? 도착이 포아송이고 서버가 한 대라면 폴라체크-힌친(P-K) 공식 Wq = λE[S²] / 2(1 − ρ)이 정확한 답을 줍니다. 정리하면 아래 꼴이 되는데, 도착 쪽 변동까지 넣은 이 모양이 킹맨(Kingman)의 G/G/1 근사이기도 합니다. M/M/1, M/D/1, M/G/1, G/G/1이 모두 이 식 하나로 읽힙니다.

P-K 공식에 왜 제곱 E[S²]이 들어갈까요? 버스가 평균 10분 간격으로 오는데 간격이 들쭉날쭉하면, 아무 때나 정류장에 간 사람은 짧은 간격보다 긴 간격에 걸릴 가능성이 큽니다. 긴 간격이 시간을 더 많이 차지하니까요. 카페에서도 서비스가 오래 걸리는 손님은 그 자체로 오래 걸리고, 다음 손님이 그 손님의 서비스 도중에 도착할 가능성도 그만큼 큽니다. 길이가 두 번 곱해져 제곱이 됩니다. 평균이 같아도 가끔 아주 오래 걸리는 주문이 섞이면 대기가 크게 느는 이유입니다.

서버가 여러 대면 정확한 식이 없고, M/M/c의 값에 변동 항을 곱하는 근사 Wq(M/G/c) ≈ (Ca² + Cs²)/2 × Wq(M/M/c)를 흔히 씁니다.

2.7자리가 모자랄 때: M/M/1/K

시스템 안에 최대 K명까지만 있을 수 있다면, K명이 찬 순간에 온 손님은 돌아갑니다. 이 큐는 상태가 0부터 K까지뿐이라 ρ가 1보다 커도 안정합니다. 대신 돌아가는 손님이 늘어납니다. 상태 확률은 P(n) = (1 − ρ)ρn / (1 − ρK+1)이고, 돌아갈 확률은 P(K)입니다.

정원이 있는 큐의 상태 분포

막대는 시스템 안 인원이 n명일 확률입니다. 빨간 막대가 꽉 찬 상태, 즉 도착한 손님이 돌아가는 확률입니다.

정원이 작으면 대기는 짧아지지만 그만큼 손님을 잃습니다. 리틀의 법칙을 쓸 때는 실제로 들어온 비율 λeff = λ(1 − P(K))로 나눠야 합니다. 서버가 여러 대인 M/M/c/K도 같은 방식(출생-사망 과정)으로 풀리며, 1.1절 시뮬레이터의 이론값이 이 계산입니다.

2.8큐의 네트워크: 잭슨 네트워크

현실의 시스템은 큐 여러 개가 이어져 있습니다. 커피점이라면 키오스크 주문, 바리스타 제조, 픽업대로 이어지고, 디저트만 산 손님은 제조를 건너뛰며, 잘못 만든 음료는 다시 만듭니다. 외부 도착이 포아송이고, 각 노드가 지수분포 서비스의 M/M/c이고, 다음 노드를 확률로 고른다면 이것을 잭슨(Jackson) 네트워크라고 합니다.

먼저 노드마다 들어오는 총 흐름을 구합니다. 노드 j의 도착률은 바깥에서 오는 양과 다른 노드에서 넘어오는 양의 합입니다(트래픽 방정식). 잭슨의 정리에 따르면 그다음에는 각 노드를 그 도착률을 가진 독립된 M/M/c처럼 계산해도 됩니다. 되먹임 때문에 노드로 들어오는 흐름이 실제로는 포아송이 아닌데도 결과는 정확합니다. 아래에서 시뮬레이션으로 확인해 보세요.

커피점 세 단계의 병목 찾기

상자 안 숫자는 그 노드의 이용률입니다. 1에 가까울수록 진하게, 1을 넘으면 빨갛게 표시합니다.

바리스타 수

트래픽 방정식은 이 예에서 손으로도 풉니다. 주문 노드에는 λ, 픽업 노드에도 결국 모두가 오므로 λ가 들어옵니다. 제조 노드에는 건너뛰지 않은 λ(1 − q)가 들어오는데, 그중 r만큼은 다시 돌아오므로 λ2 = λ(1 − q) + rλ2, 즉 λ2 = λ(1 − q)/(1 − r)입니다. 다시 만드는 비율이 조금만 늘어도 제조 노드의 이용률이 먼저 1에 다가가는 것을 볼 수 있습니다. 네트워크 전체의 평균 체류시간은 노드별 평균 인원을 더한 뒤 리틀의 법칙으로 W = ΣLj / λ입니다.

공식이 멈추는 곳서비스가 지수분포가 아니거나, 여러 품목을 동시에 만들거나, 손님이 줄을 보고 포기하면 잭슨의 정리는 더 이상 정확하지 않습니다. 2편의 커피점이 바로 그런 네트워크이고, 그래서 시뮬레이션으로 풉니다.

3예제와 사례 연구

공식을 나란히 놓고, 손으로 풀고, 실제 결정에 써 봅니다.

3.1여섯 모델 한눈에

2.6절의 세 손잡이로 보면 여섯 모델은 같은 식의 변주입니다. 아래 그래프는 같은 서비스 시간에서 이용률에 따른 평균 줄 대기를 서비스 시간 단위로 그린 것입니다. 변동 손잡이와 서버 수를 바꿔 보세요.

같은 조건, 여섯 가지 가정

서버가 여럿인 모델의 이용률은 서버 한 대 기준입니다. 점선은 지금 고른 ρ입니다.

3.2손으로 풀어 보기

리틀의 법칙은 세 칸 중 두 칸을 알면 나머지를 줍니다. λ와 W의 시간 단위를 같게 맞추는 것만 잊지 마세요.

리틀의 법칙 계산기

두 칸을 채우면 나머지 한 칸이 계산됩니다. 시간 단위는 마음대로 고르되 λ와 W를 같은 단위로 넣으세요.

예: L = 60, λ = 4를 넣으면 W = 15가 나옵니다.

1. 학생식당 안에 평균 60명이 있고 1분에 4명씩 들어옵니다. 한 사람은 평균 몇 분 머무를까요?

W = L/λ = 60/4 = 15분입니다. 배식 시간 분포도, 줄 구조도 몰라도 됩니다.

2. API 서버에 초당 200개의 요청이 들어오고 평균 응답 시간은 50ms입니다. 동시에 처리 중인 요청은 평균 몇 개일까요? 워커가 8개라면?

단위를 맞추면 W = 0.05초, L = 200 × 0.05 = 10개입니다. 평균만으로도 워커 8개를 넘으므로 요청이 쌓이기 시작하고, 그러면 W가 더 늘어납니다. 처리량 계획에서 리틀의 법칙이 가장 자주 쓰이는 방식입니다.

3. 생산 라인에 재공품이 평균 120개 있고 시간당 40개가 완성됩니다. 리드타임은? 처리량은 그대로 두고 리드타임을 2시간으로 줄이려면?

W = 120/40 = 3시간입니다. 2시간으로 줄이려면 L = 40 × 2 = 80개로 줄여야 합니다. 린 생산에서 "재공품을 줄이면 리드타임이 준다"는 말의 근거가 이 식입니다.

4. 연구실 프린터에 인쇄 작업이 시간당 10건 들어오고(포아송), 프린터는 시간당 12건을 처리합니다(지수분포). ρ, L, W는? 작업이 시간당 11건으로 10% 늘면?

ρ = 10/12 ≈ 0.83, L = 0.83/0.17 = 5건, W = 1/(12 − 10) = 0.5시간입니다. 11건이면 ρ ≈ 0.92, L = 11건, W = 1시간. 도착이 10% 늘었을 뿐인데 체류시간은 두 배가 됩니다. 2.4절 곡선의 가파른 구간입니다.

5. 대기 의자가 3개뿐인 미용실에 손님이 시간당 6명 오지만 그중 3분의 1은 자리가 없어 돌아갑니다. 가게 안에는 평균 2명이 있습니다. 들어온 손님은 평균 얼마나 머무를까요?

실제로 들어온 비율은 λeff = 6 × 2/3 = 4명/시간이므로 W = 2/4 = 0.5시간입니다. λ = 6을 그대로 쓰면 20분이라는 틀린 답이 나옵니다. 1.1절 시뮬레이터에서 대기 공간을 줄여 보면 표의 λeff가 이 값에 해당합니다.

3.3사례: 학생식당 배식구를 하나 더 열까

점심 피크에 학생이 1분에 3명씩 오고, 배식은 한 명당 평균 0.6분이 걸립니다. 지금은 배식구 두 곳에 줄을 따로 세우는데 줄이 길다는 불만이 많습니다. 배식구를 하나 더 열려면 사람이 한 명 더 필요합니다. 그 전에 할 수 있는 것은 없을까요? 배식 시간이 지수분포에 가깝다고 보고(Cs² = 1) 공식으로 비교해 봅시다.

안모델평균 줄 대기필요한 것
지금: 두 곳, 줄 따로M/M/1 두 개, 각 λ = 1.55.4분없음
두 곳, 줄 하나로M/M/22.6분줄 안내선
줄 하나 + 배식 편차 줄이기M/G/2, Cs² = 0.25약 1.6분메뉴 미리 담기
세 곳, 줄 따로M/M/1 세 개, 각 λ = 10.9분배식 인력 1명

이용률이 0.9로 같은데도 줄을 하나로 합치기만 해도 대기가 절반 아래로 줍니다. 배식 시간의 편차를 줄이면(Cs² = 1 → 0.25) 변동 손잡이가 1에서 0.625로 내려가 다시 40% 가까이 줍니다. 인력을 늘리는 안이 가장 효과가 크지만, 앞의 두 안은 거의 돈이 들지 않습니다. 단, 이 숫자는 점심 피크가 일정하게 이어진다는 가정에서 나온 것입니다. 피크가 20분만 이어진다면 줄은 정상 상태에 이르지 못하므로, 실제 결정 전에는 2편처럼 시간대별 도착을 넣은 시뮬레이션으로 확인합니다.

4연결과 정리

4.1앞뒤 편과의 연결

2편으로도착률이 시간대마다 바뀌고, 한 손님이 여러 품목을 주문하고, 줄을 보고 포기하는 커피점에는 닫힌 공식이 없습니다. 2편은 그 커피점을 사건 단위로 시뮬레이션하고, 단순한 단계에서는 이 편의 P-K 공식으로 시뮬레이터를 검증합니다.

3편으로큐잉 이론의 손님은 모두 같은 규칙을 따릅니다. 손님마다 참을성이 다르고 서로 영향을 주고받는다면 에이전트 기반 모델이 필요합니다.

4편과 5편으로공식에 넣을 Cs²는 데이터에서 추정해야 하고(4편), 시뮬레이션 결과는 반복과 신뢰구간으로 말해야 합니다(5편).

8편으로리틀의 법칙은 분포와 상관없이 성립하므로, 공식이 없는 모델에서도 시뮬레이터가 맞게 도는지 점검하는 도구가 됩니다. 측정한 L과 λW가 다르면 코드에 버그가 있습니다.

4.2요약

리틀의 법칙
L = λW. 분포, 서버 수, 순서 규칙과 상관없이, 같은 경계에 대해 잰 세 양 사이에 성립한다. 돌아간 손님이 있으면 λeff.
가동률
ρ = λ/cμ < 1이어야 줄이 끝없이 늘지 않는다. 1에 가까울수록 대기는 1/(1 − ρ)로 폭증한다.
세 손잡이
평균 줄 대기 ≈ 혼잡도 × 변동 × 서비스 시간. M/G/1에서는 등호(P-K), G/G/1에서는 근사(킹맨).
풀링
같은 서버라면 줄은 하나가 낫다. 빠른 서버 하나는 체류시간이 가장 짧다.
정원
M/M/1/K는 ρ > 1이어도 안정하지만 손님을 잃는다.
네트워크
트래픽 방정식으로 노드별 도착률을 구하고, 잭슨 네트워크라면 노드마다 M/M/c로 계산한다. 이용률이 가장 높은 노드가 병목이다.

4.3연습 문제

1. M/M/1에서 이용률을 0.8에서 0.9로 올리면 평균 체류시간은 몇 배가 될까요? 0.9에서 0.95로 올리면?

W ∝ 1/(1 − ρ)이므로 0.8 → 0.9는 5 → 10으로 두 배, 0.9 → 0.95는 10 → 20으로 다시 두 배입니다. 이용률은 각각 12.5%, 5.6%만 올랐습니다.

2. 서비스 시간이 평균 2분, 표준편차 2분인 M/G/1과 표준편차 1분인 M/G/1이 있습니다. 이용률이 같다면 줄 대기는 몇 배 차이일까요?

Cs²는 각각 1과 0.25입니다. 변동 손잡이는 (1 + 1)/2 = 1과 (1 + 0.25)/2 = 0.625이므로 줄 대기는 1.6배 차이입니다. 평균은 같습니다.

3. 콜센터에 전화가 분당 4통 오고 통화는 평균 2분(지수분포)입니다. 상담원이 몇 명 이상이어야 안정할까요? 9명과 10명 중 어느 쪽이 "도착한 전화의 80% 이상이 바로 연결"을 만족할까요?

바쁜 상담원 수의 평균이 λ/μ = 8명이므로 9명 이상이어야 합니다. 얼랑 C로 계산하면 9명일 때 기다릴 확률이 약 0.65, 10명일 때 약 0.41입니다. 바로 연결되는 비율은 각각 약 35%와 59%로 둘 다 목표에 못 미치고, 12명(약 86%)은 되어야 합니다. 2.5절 위젯에서 c와 ρ를 맞춰 확인해 보세요.

4. 정원이 5명인 M/M/1/5에서 λ = μ이면 돌아가는 비율은?

ρ = 1이면 모든 상태의 확률이 같아 1/(K + 1) = 1/6 ≈ 17%입니다. 2.7절 위젯에서 ρ = 1, K = 5로 확인할 수 있습니다.

5. 2.8절 네트워크에서 바리스타가 2명일 때, 다시 만드는 비율 r을 얼마까지 견딜 수 있을까요? (λ = 0.8, q = 0.2)

제조 노드가 안정하려면 λ2 = 0.64/(1 − r) < 2 × (1/1.5) = 1.33이어야 하므로 1 − r > 0.48, 즉 r < 0.52입니다. 하지만 r = 0.4만 되어도 이용률이 0.8이라 체류시간이 크게 늘어납니다. 안정과 쾌적은 다른 기준입니다.

4.4파이썬으로 확인하기

사건 목록 하나로 M/M/c/K를 시뮬레이션하고, 측정값을 2.7절의 출생-사망 공식과 비교하는 코드입니다. 표준 라이브러리만 씁니다. 2편에서 같은 구조를 커피점 전체로 키웁니다.

# mmck_sim.py : 사건 리스트로 M/M/c/K를 돌리고 리틀의 법칙과 이론값을 확인한다
import heapq, random

def simulate(lam, mu, c, K, T=200_000, seed=1):
    rng = random.Random(seed)
    fel = [(rng.expovariate(lam), "arr")]       # 미래 사건 목록: (시각, 종류)
    t = area = 0.0                               # area = 사람 수를 시간으로 적분한 값
    n = accepted = blocked = 0
    waits, queue, busy = [], [], 0
    while fel:
        t_next, kind = heapq.heappop(fel)
        if t_next > T:
            break
        area += n * (t_next - t)
        t = t_next
        if kind == "arr":
            heapq.heappush(fel, (t + rng.expovariate(lam), "arr"))
            if n == K:                            # 정원이 차면 돌아간다
                blocked += 1
                continue
            n += 1
            accepted += 1
            if busy < c:
                busy += 1
                heapq.heappush(fel, (t + rng.expovariate(mu), ("dep", t)))
            else:
                queue.append(t)
        else:                                     # 떠남: ("dep", 도착 시각)
            waits.append(t - kind[1])
            n -= 1
            if queue:
                heapq.heappush(fel, (t + rng.expovariate(mu), ("dep", queue.pop(0))))
            else:
                busy -= 1
    L, lam_eff, W = area / t, accepted / t, sum(waits) / len(waits)
    return L, lam_eff, W, blocked / (accepted + blocked)

def theory(lam, mu, c, K):                        # 출생-사망 과정의 정상 분포
    p = [1.0]
    for k in range(1, K + 1):
        p.append(p[-1] * lam / (mu * min(k, c)))
    s = sum(p)
    p = [x / s for x in p]
    L = sum(k * x for k, x in enumerate(p))
    lam_eff = lam * (1 - p[K])
    return L, lam_eff, L / lam_eff, p[K]

lam, mu, c, K = 1.8, 1.0, 2, 6                   # 서버 2대, 정원 6명
sim, th = simulate(lam, mu, c, K), theory(lam, mu, c, K)
for name, s, t in zip(["L", "λ_eff", "W", "돌아간 비율"], sim, th):
    print(f"{name}: 시뮬레이션 {s:.3f}, 이론 {t:.3f}")
print(f"리틀의 법칙 확인: L = {sim[0]:.3f},  λ_eff × W = {sim[1] * sim[2]:.3f}")

실행 결과 (시드 1): L: 시뮬레이션 2.847, 이론 2.856, W: 시뮬레이션 1.783, 이론 1.788, 돌아간 비율: 시뮬레이션 0.112, 이론 0.113, 그리고 L = 2.847, λ_eff × W = 2.847. 마지막 줄의 두 값은 같은 넓이를 두 번 센 것이라 시드와 상관없이 거의 일치합니다.
